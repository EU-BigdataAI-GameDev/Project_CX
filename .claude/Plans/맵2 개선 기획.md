# 맵2 개선 기획 (v1.0, 2026-11-07)

맵2(`Map2_SoulCity2`)에 세 가지를 한다: **① 전용 배경음**, **② 계단 그래픽과 콜라이더 맞추기**, **③ 비밀번호 단말기를 회로 연결 퍼즐로 교체**.
작업은 서브에이전트가 한다. 순서: A(①+②, 에디터 켠 채 레벨 작업) → B(③, C++ + 전체 빌드 + 배치).

> 맵2는 손으로 편집한 레벨이다. 일괄 재생성(`build_map2.py` 재실행) 금지, 고칠 액터만 고친다.

## 1. 배경음 (Map2 BGM)

- 원본: `Sounds/[Project_CX] District 5 - Undercurrent.wav` (약 38MB).
- 임포트: `/Game/Project_CX/Audio/BGM/SW_BGM_Map2` (Map1·타이틀과 같은 방식). 임포트 후 `Sounds/`의 원본 파일 삭제(손으로 넣고 빼는 폴더).
- 연결: `ALocalCoopGameMode` 생성자 `MapMusic.Add(TEXT("Map2_SoulCity2"), Map2Track)`.
- 반복 구간: 곡을 분석해 박자(마디) 단위로 `LoopStart`/`LoopEnd`를 잡는다. 인트로는 처음 한 번만 재생. 크로스페이드는 1마디. 분석 근거는 `Docs/배경음_제작기록.md`에 Map1처럼 기록.
- 확인: 맵2에서 곡이 재생되는지, 반복 이음새가 박자에 맞는지(로그 + 들어 보기 요청).

## 2. 계단 그래픽 ↔ 콜라이더 일치

**문제**: 맵2 계단은 그래픽(`SM_stairs_W1_H3_00` 등을 스케일한 아트)과 걷는 판정(보이지 않는 경사 콜라이더 `ramp()`, `Collision/Stairs` 폴더)이 따로 있다. 세로 1.1배(`scale_map2_vertical.py`), 레인 앞 넓히기(`widen_lane_front.py`), 손 편집을 거치며 둘이 어긋났다.
- 대표 사례: **마지막 단말기(`HackTerminal_M2_Memory`, `CAVE_LIFT_ECHO`, Y≈12505) 주변 계단** — 그래픽은 계단인데 콜라이더는 평평한 바닥.

**방법**
1. 전수 조사: 맵2의 모든 계단 아트 액터(이름·메시에 stairs/Stair 포함, `Art/*/Stairs` 폴더)와 근처 콜라이더(경사·바닥 COL)를 짝지어 비교한다.
   - 비교값: 계단 아트의 시작·끝 Y, 아래·위 Z(바운드), 폭(X) ↔ 콜라이더 경사의 같은 값.
   - 오차 기준: 높이 15cm, 길이 30cm 넘으면 불일치.
   - 결과 표를 `Docs/LevelManifests/map2_stairs_audit.md`로 남긴다(고치기 전 트랜스폼 포함 → 되돌리기 가능).
2. 수정 원칙
   - **그래픽이 기준**(눈에 보이는 대로 걸어야 한다). 콜라이더를 계단 아트에 맞춘다.
   - 평평한 바닥 콜라이더가 계단을 덮고 있으면: 그 바닥 콜라이더를 계단 구간에서 잘라 내고(크기·위치 조정) 계단 경사 콜라이더를 새로 넣는다.
   - 경사 콜라이더는 계단 코(앞 모서리)를 잇는 면에 맞춘다(발이 계단 위로 뜨거나 파묻히지 않게). 오를 수 있는 각도(Walkable Floor Angle)를 넘으면 보고.
   - 고친 액터에는 태그 `GEN_Map2StairFix`를 붙인다.
   - 계단이 아닌 콜라이더·아트는 건드리지 않는다.
3. 검증: 계단마다 위에서 아래로 라인 트레이스를 여러 점 쏴서 콜라이더 높이가 계단 높이와 맞는지 확인하고 표에 기록. 대표 계단 3곳(특히 마지막 단말기 쪽) PIE 스크린샷 → `Docs/Screenshots/Map2Stairs/`.
4. 저장: 맵2만 저장(이번 작업은 실제 레벨 수정이므로 저장한다). 임시 액터는 남기지 않는다.

## 3. 회로 연결 퍼즐 (Circuit Link) — 비밀번호 대체

**대상**: `HackTerminal_M2_Passcode`(`SHUTTER_CTRL-5`, Y≈5920, 게이트 `HackGate_M2_S3Door`). 퍼즐 종류를 `Passcode` → 새 종류 `CircuitLink`로 바꾼다.
- 이 단말기 전용 숫자 단서 4개(`HackClue_M2_S1_Canal`, `_S2_R1`, `_S2_R2`, `_S2_R4`)는 쓸모가 없어지므로 **그 4개만** 삭제.
- `Passcode` 종류 자체는 코드에 남긴다(다른 맵에서 쓸 수 있음).

### 3-1. 규칙 (참고 이미지 기준)

- 격자(기본 6×5) 위에 **시작점(파랑)** 과 **도착점(초록)** 이 짝지어 놓여 있다(3~4쌍).
- 여동생이 시작점에서 상하좌우로 회로를 그려 **짝이 맞는 도착점**까지 잇는다.
- 회로끼리 **교차·겹침 불가**(한 칸은 회로 하나만). 모든 칸을 채울 필요는 없다.
- 모든 쌍이 이어지면 해킹 성공 → 게이트 열림.
- 제한 시간 없음, 실패 없음(언제든 다시 그리기 가능).

### 3-2. 협동 요소 (비밀번호 단서의 역할을 이어받음)

- **여동생 화면**: 시작점은 모두 파랑, 도착점은 모두 초록 → 어떤 시작점이 어떤 도착점과 짝인지 모른다.
- **오빠 화면**: 오빠가 단말기 중계 거리(메모리 패턴처럼 900cm) 안에 있으면, 오빠 칸에 같은 격자가 작게 뜨고 **짝마다 다른 색·번호**가 보인다. 오빠가 말로 알려 준다.
- 틀린 짝에 이으면: 회로가 이어지긴 하지만 빨갛게 깜빡이고 "MISMATCH". 성공으로 치지 않는다.
- 오빠가 멀리 있으면 여동생은 시행착오로도 풀 수 있다(틀린 짝은 바로 표시되니 막히지는 않는다).

### 3-3. 조작 (여동생, 기존 퍼즐과 같은 키)

| 동작 | 키보드(2P) / 패드 |
|---|---|
| 커서 이동 | 방향키·WASD / D-패드·왼쪽 스틱 |
| 회로 그리기 시작·끝 | 시작점·도착점 위에서 F/X(확인) → 이동하면 회로가 따라온다 |
| 되돌리기 | 왔던 칸으로 되돌아가면 회로가 줄어든다 |
| 회로 지우기 | 이미 그린 회로 위에서 확인 → 그 회로 삭제 |
| 나가기 | 기존 퍼즐 취소 키 |

### 3-4. 퍼즐 데이터

- 손으로 만든 레이아웃 3개 이상(풀 수 있는 답이 반드시 있는 것) 중 단말기를 열 때마다 하나를 고른다.
- 레이아웃은 코드 상수 또는 단말기의 `UPROPERTY`(격자 크기, 쌍 목록)로 둔다. 시작할 때 답이 있는지 BFS로 검사하고, 없으면 경고 로그 후 기본 레이아웃 사용.

### 3-5. 구현 (기존 구조 따름)

- `EHackPuzzleType::CircuitLink` 추가, `HackTerminal`에 레이아웃 설정 속성.
- 퍼즐 로직은 `CXHackPuzzles`의 다른 퍼즐과 같은 방식으로 분리(격자 상태·연결 판정 순수 함수 → 테스트하기 쉽게).
- 서버 권위: 여동생 입력은 `SisterHackComponent`의 기존 RPC 경로로 서버에 보내고, 회로 상태를 복제(메모리 패턴의 서버 세션 방식 참고). 오빠 화면 표시도 복제값으로.
- HUD: `CoopHUD`에 C++로 그린다(WBP 없음). 이미지처럼 어두운 격자, 네온 선, 끝점 사각형. 오빠 칸 미니 격자.
- 제미니 연동: `HackTerminal`(단말기 해킹) 대리 해킹이 이 퍼즐에서도 동작해야 한다(`GetJeminiPuzzleState`의 progress = 이어진 쌍 / 전체 쌍).
- 디버그: `CXSolveHack`이 이 퍼즐도 풀어야 한다.

### 3-6. 확인

- 단말기를 열고 → 짝 맞춰 이으면 게이트가 열리는지, 교차가 막히는지, 되돌리기·지우기, 틀린 짝 표시.
- 오빠 중계 표시(거리 안/밖).
- 제미니 단말기 대리 해킹, `CXSolveHack`.
- HUD 스크린샷 → `Docs/Screenshots/CircuitLink/`.

- 끝나면 아래 "구현 결과"와 `Docs/TODO.md`, 필요하면 `Docs/Debug_log.md` 갱신.

### 3. 회로 연결 퍼즐 (2026-11-07)

- 코드(C++만, WBP 없음)
  - 규칙: `Variant_Sister/Hacking/CXCircuitLinkPuzzle.h/.cpp`의 순수 구조체 `FCXCircuitLinkPuzzle`. 서버 단말기가 직접 들고 있어야 해서 `CXHackPuzzles.h`가 아닌 별도 헤더(HackTerminal.h가 포함). 입력 `ECXCircuitOp`(상하좌우·확인) → 판정 `ECXCircuitStep`(Moved / Started / Extended / Backtracked / Blocked / Deleted / Linked / Mismatch / Complete). `Solve`(짝마다 DFS + 남은 짝 BFS 연결 가지치기, 단계 상한 20만), `FindRoute`(BFS), `ApplySolution`.
  - 조작: 그리는 중이 아니면 커서만 이동. 빈 끝점(시작점·도착점 어느 쪽이든) 위 확인 = 그리기 시작 → 이동하면 회로가 따라옴, 바로 앞 칸으로 돌아가면 한 칸 줄어듦. 반대 종류의 빈 끝점에 닿으면 자동으로 끝(짝 맞으면 Linked, 다르면 MISMATCH — 빨갛게 깜빡이며 남고 성공으로 안 침). 다른 회로·자기 회로·같은 종류 끝점 칸은 Blocked. 회로 위 확인 = 그 회로 삭제, 그리는 중 확인 = 그리던 회로 삭제. 가장자리에서 멈춤. 취소 키는 기존 그대로(세션 끝 → 다시 열면 새 레이아웃).
  - 레이아웃: 코드 기본 4종(6x5, 3쌍 2개·4쌍 2개, Python으로 답 확인). 단말기 `CircuitLayouts`(UPROPERTY `FCXCircuitLayout`: Width/Height/Starts/Goals)를 채우면 그것만 후보. 열 때마다 직전과 다른 것을 무작위로 고르고, 구조 검사 + `Solve`에 실패한 레이아웃은 경고 로그 후 제외, 남는 게 없으면 기본 0번.
  - `AHackTerminal`: `EHackPuzzleType::CircuitLink`(값 4, 뒤에 추가 — `Passcode`는 그대로 남김). 서버 API `ServerCircuitBegin/Input/End/Solve`, 복제 `CircuitWidth/Height/Endpoints/Paths(FCXCircuitPathRep)/ActivePath/Cursor/bCircuitRelayActive/CircuitLastEvent/EventTime/LayoutId`. Tick에서 오빠 중계 판정(`CircuitRelayRange` 900cm, 생존, 메모리 패턴과 같은 `FindRelayPawn`). 입력 검증: 세션을 연 여동생, 생존, `InteractRange + CircuitServerRangeSlack(200)`.
  - `USisterHackComponent`: 커서·회로는 서버가 들고 여동생은 방향/확인만 보낸다(권위 측 직접 호출, 원격은 `Server_CircuitSession` / `Server_CircuitInput` → `Client_CircuitResult`). 막힘·이동·되돌리기 소리는 기존 해킹 효과음 피치만 바꿔 재사용. 다른 경로(CXSolveHack·제미니)로 단말기가 열리면 `TickCircuit`이 성공 표시 후 세션을 닫는다. 진행도 = 이어진 짝 / 전체 짝(제미니 `GetJeminiPuzzleState` progress 동일). 테스트용 `DebugCircuitInput(op)`, `DebugCircuitConnect(startPair, goalPair)`, `DebugCircuitSolveByInput()`, `GetCircuitDebugState()`(모두 실제 입력 경로 사용).
  - HUD(`ACoopHUD`): 여동생 칸 `DrawCircuitHackSession` — 어두운 기판 격자 + 교차점 눈금, 시작점 파랑(속 사각)·도착점 초록(속 링), 회로는 글로우 + 굵은 선 + 흰 하이라이트 + 둥근 연결점(그리는 중 분홍, 연결 청록, MISMATCH 빨강 깜빡임), 커서 괄호, 짝 칸·진행 바·중계 상태, 판정 배너 CIRCUIT LINKED / MISMATCH / ACCESS GRANTED, 막힘 시 커서 위 BLOCKED. 오빠 칸 `DrawCircuitRelay` — 메모리 패턴 중계 자리(제미니 패널 아래로 내림), 거리 안이면 짝마다 색(노랑·보라·주황·청록)과 번호, 시작점 채움·도착점 테두리, 여동생 커서·회로도 보임. 거리 밖이면 흐린 격자 + MOVE CLOSER / PAIR MAP OFFLINE + 단말기 월드 마커.
  - 제미니: 모드 A(열린 단말기 대행)는 3초 뒤 서버가 정답 회로를 채우고 해킹 완료(원격 여동생이면 서버 사본이 처리). 모드 B(`FindNextLockedTerminal` + `MarkHacked`)는 퍼즐 종류와 무관해 그대로 동작.
  - `CXSolveHack`: 회로 연결 세션 중이면 `ServerCircuitSolve`(정답 회로 채움 + 해킹 완료), 아니면 기존대로.
- 레벨(`Map2_SoulCity2`, 맵2만 저장): `HackTerminal_M2_Passcode`(`SHUTTER_CTRL-5`) `PuzzleType` → CircuitLink, `CircuitRelayRange` 900. 단서 `HackClue_M2_S1_Canal`, `_S2_R1`, `_S2_R2`, `_S2_R4` 4개만 삭제. 라벨·위치·게이트(UnlockActors 13개, 손으로 넣은 `NEON_..._F0~F2` 포함)는 그대로. 이전 상태 `Docs/LevelManifests/Map2_circuitlink_before.json`. `Tools/LevelBuild/add_map2_hacking.py`: 1번 단말기 `CIRCUIT_LINK`, `CLUES = []`, 검사는 3종(회로/주파수/메모리) + 회로 단말기 오빠 중계 발판 + 단서 0개(스크립트는 이번에 다시 돌리지 않음 — 다시 돌리면 같은 결과).
- 빌드: 헤더 변경 → 에디터 정상 종료 → 전체 빌드 성공(경고 0) → 재실행. HUD 글자 넘침 수정은 Live Coding.
- PIE 검증(맵2 실제 단말기, 디버그 함수 = 실제 입력 경로): 맞는 짝 연결 Linked 1/n, 다른 회로로 들어가기 Blocked(회로 변화 없음), 한 칸 전진 → 되돌아오기 Backtracked(길이 -1), 그리는 중 확인 = 삭제, 회로 위 확인 = 삭제(0/n), 틀린 짝 Mismatch(event Denied, 성공 수 0), 오빠 16.5m = 중계 꺼짐 / 4.9m = 켜짐(짝 색·번호), 입력으로 전부 풀기 → Complete, 게이트 COL 충돌 꺼짐, 세션 자동 종료. 새 PIE에서 `CXSolveHack` → 정답 채움·해킹·게이트 열림. 새 PIE에서 `CXJeminiCmd HackTerminal sister`(세션 중, 1/4 연결 상태 progress 0.25) → 3초 뒤 정답 채움·해킹, 배터리 100→80. 새 PIE에서 세션 없이 같은 명령 → 모드 B `SHUTTER_CTRL-5` 해킹. 스크린샷 `Docs/Screenshots/CircuitLink/01~05`.
