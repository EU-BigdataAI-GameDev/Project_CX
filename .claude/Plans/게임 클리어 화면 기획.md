# 게임 클리어화면 기획 (임시 화면)

- 문서 버전: v1.1 (2026-11-02) — 클리어 조건(두 버튼 문), 세이브 초기화, 마지막 맵 이름 확정
- 원본 요청: `.claude/mds/9. 게임 화면 제작 요청.md` — "게임 클리어화면"
- 공통 규칙: **`설정 메뉴 기획.md` 0장 "공통 UI 규칙"**(전체 화면 단일 메뉴·누구나 조작, 입력 표, 포커스, HUD 톤, 사운드 큐)을 따른다. 이 문서에는 클리어화면 고유 내용만 적는다.
- 범위: 구현 완료(2026-11-02) — 결과와 기획과 다른 점은 **10장 "구현 결과 (as-built)"** 참조. 엔딩 연출이 생기기 전까지 쓰는 **임시(placeholder) 화면**이다.

---

## 1. 목적

- 마지막 맵(보스방)의 출구 문을 연 것으로 게임 클리어를 알리고, 플레이를 깔끔하게 끝내 시작화면으로 돌려보낸다.
- 현재 MVP 진행 구조: **방 1 → 방 2 → 세이브 복도 → 마지막 방(보스맵, `Map3_Final`) → 출구 문 → 클리어**.
- 엔딩 연출이 아직 없으므로 화면 중앙 `COMING SOON` 텍스트와 버튼 하나(`타이틀로`)만 둔다.

## 2. 진입 / 종료

| 구분 | 조건 |
|---|---|
| 진입 | **클리어 판정** — 마지막 맵 출구 문 앞에서 **오빠와 여동생이 각자 자기 버튼을 눌러 문이 열림**(2.1) |
| 종료 | `타이틀로` 선택 — 이것 하나뿐 |

### 2.1 클리어 조건 — 두 버튼 문

- 출구 문 양옆에 버튼 2개: **왼쪽 오빠 버튼(청록) / 오른쪽 여동생 버튼(마젠타)**. 각 버튼은 **자기 캐릭터만** 누를 수 있다(상대 버튼 앞에서는 상호작용 안내가 뜨지 않음).
- 상호작용 키: 키보드 `F` / 게임패드 `X`(여동생 해킹 시작과 같은 키 — 두 캐릭터 공용 "상호작용").
- 눌린 버튼은 **켜진 상태로 유지**(동시에 누를 필요 없음). 버튼 등이 회색 → 자기 색으로 바뀌고, 문 위 표시등 2칸 중 한 칸이 켜진다.
- **두 버튼이 모두 켜지면** 문이 열린다(약 1.5초 열림 연출) → 연출이 끝나면 클리어화면 진입.
- 두 사람 모두 살아서 문 앞에 와야 하므로, 한 명이 부활 대기 중이면 부활할 때까지 문은 열리지 않는다.

### 2.2 진입 연출

- 진입 연출: 판정 순간 게임플레이 입력 차단 → 0.5초 동안 게임 화면 위로 딤이 깔림 → **월드 일시정지** → 패널 페이드인(0.15초 + 세로 0.96→1.0, 0장 규칙).
- 표시 중에는 월드가 정지되고 두 폰 모두 입력을 받지 않는다(부활 카운트다운·해킹 타이머도 정지).
- 표시 중(진입 연출 포함) **ESC/Start는 일시정지 메뉴를 열지 않는다**(`UCXMenuSubsystem::SetMenuBlocked(true)`).
- 연출 중(약 0.65초)에는 메뉴 입력 무시.

## 4. 메뉴 항목

| KR | EN | 동작 | 조건 |
|---|---|---|---|
| 곧 공개 (제목) | COMING SOON | — | — |
| 타이틀로 | QUIT TO TITLE | **확인창 없이** 0.4초 검정 페이드 → 시작화면 이동 | 항상 |

- EN 라벨은 ESC 메뉴·게임 오버화면과 같은 `QUIT TO TITLE`로 통일한다.
- 두 플레이어 **누구나** 선택 가능. 포커스 색 = 마지막 입력 플레이어 색(0.3).
- **확인창 없음**: 원본 요청 공통 규칙의 명시적 예외 — 클리어 시점에는 잃을 진행이 없다.
- **기본 포커스**: 유일한 버튼 `타이틀로`. 위/아래 입력은 무시(순환할 대상이 없음).
- **최상위 `ESC`/`B`/`Start`: 아무 동작 없음(입력은 소비).** 이유: 게임 오버화면과 같은 규칙으로 통일하고, 마지막 전투 직후 버튼 연타로 화면이 읽히기도 전에 넘어가는 것을 막는다. 진행은 반드시 `A`/`Enter`/클릭으로.

## 5. 비주얼 / 사운드

- 0장 톤 그대로. 제목 `COMING SOON`은 흰색 90% + 테두리/브래킷은 청록·마젠타 반반(두 사람의 클리어). 경고 주황은 쓰지 않는다.
- 제목 네온 점등(0.4초, 짧은 깜박임 2회) 후 고정 — 시작화면 게임명 점등과 같은 문법.
- 사운드: 진입 시 인게임 BGM을 0.5초에 걸쳐 낮춰 정지(클리어 전용 짧은 징글 슬롯만 두고, 에셋이 없으면 무음). `타이틀로` 선택 시 화면 페이드와 같은 시간으로 남은 음악 페이드아웃. 메뉴 큐는 0.6 그대로.

## 6. 예외 상황

| 상황 | 처리 |
|---|---|
| 두 사람이 동시에 `타이틀로` 선택 | 먼저 들어온 입력만 처리, 이후 페이드로 들어가 나머지는 무시 |
| 한 명이 사망·부활 대기 중 | 그 사람 버튼은 누를 수 없으므로 **문이 열리지 않는다.** 이미 켜 둔 버튼은 유지되고, 부활 후 남은 버튼을 누르면 열린다 |
| 한 명만 버튼을 누름 | 버튼은 켜진 채로 대기(시간 제한 없음). 문 위 표시등으로 남은 쪽이 보인다 |
| 버튼을 누른 뒤 사망 | 버튼은 꺼지지 않는다(다시 누를 필요 없음) |
| 같은 프레임에 게임 오버 조건과 클리어 판정 | 판정은 서버(호스트) 한 곳에서 순서대로 — 먼저 처리된 쪽만 열리고 다른 쪽은 차단(이미 메뉴 차단 상태) |
| 문이 열리는 중 / 열린 뒤 버튼 재입력 | 무시(클리어는 1회만 발동) |
| 클리어 시 ESC 메뉴가 열려 있음 | 월드 정지 중이라 트리거가 발동하지 않음 — 해당 없음 |
| 진입 연출 / 타이틀로 페이드 중 입력 | 무시 |
| 표시 중 게임패드 끊김 | 화면 그대로(키보드/다른 패드로 선택 가능). 일시정지 메뉴 자동 열기는 차단 상태라 일어나지 않음 |

## 8. 한글 폰트 / 영문 전환

**언리얼에서 한글이 깨져 보이면 메뉴명을 모두 영어로 바꿔도 된다.** 한글을 쓰려면 한글 폰트 에셋(예: Noto Sans KR)을 프로젝트에 추가해야 한다. 영문 라벨: `COMING SOON`, `QUIT TO TITLE`, 힌트 `[A / ENTER] SELECT`. 기존 메뉴 구현과 같이 처음부터 영문으로 구현해도 된다.

## 9. 구현 메모 (C++ 우선)

- 위젯은 다른 메뉴와 같이 **전부 C++(WBP 없음)** — `WidgetTree->ConstructWidget`으로 트리 생성.
- `UCXGameClearWidget : UCXMenuWidgetBase`(`UI/Menu/`). 항목 1개(`UCXMenuItemWidget`), 패널 `UCXNeonPanelWidget`, 색은 `CXMenuStyle` 토큰, 딤은 `UCXPauseDimWidget` 재사용(70%). `ConsumesTopLevelBack()`을 `true`로 두고 `OnBack()`은 아무것도 하지 않음, Start도 소비.
- 출구 문: `ACXCoopExitDoor`(문 메시 + 버튼 컴포넌트 2개, 각 버튼에 담당 캐릭터 클래스/역할 지정). 버튼 상태 `bBrotherPressed` / `bSisterPressed`는 복제 변수(서버에서만 변경). 둘 다 켜지면 문 열림 연출 후 `NotifyGameCleared` 호출.
- 판정 주체: `ALocalCoopGameMode::NotifyGameCleared()`(서버 권위 — listen server 전제와 같은 구조). 1회 플래그 → **세이브 삭제**(`UGameplayStatics::DeleteGameInSlot("CX_Slot0", 0)`) → `UCXMenuSubsystem::SetMenuBlocked(true)` → 0.5초 후 `UGameplayStatics::SetGamePaused(true)` + `PushMenu(UCXGameClearWidget, 1P 컨트롤러, ZOrder 200)`.
- `타이틀로`: `UCXPauseMenuWidget::BeginQuitToTitle`과 같은 흐름 — `UCXMenuSubsystem::NotifyLeavingMap()` → `UCXGameInstance::bTitleIntroPlayed = true`(시작화면 0.3초 축약 페이드) → `UCXAudioSubsystem::StopMusic(0.4f)`와 0.4초 검정 페이드 동시 진행 → `UGameplayStatics::OpenLevel("/Game/Project_CX/Maps/Map_Title")`. 세이브는 클리어 판정 때 이미 삭제했으므로 시작화면에는 `이어하기`가 없다. 메뉴 스택은 맵 이동 시 서브시스템이 정리하지만 **`bMenuBlocked`는 현재 맵 이동 시 자동으로 풀리지 않으므로** `OpenLevel` 직전에 `SetMenuBlocked(false)`를 호출한다(또는 서브시스템의 `ResetPauseState`에서 같이 초기화).
- 향후 확장(지금은 만들지 않음): 엔딩 연출, 크레딧, 플레이 통계, 클리어 기록 저장.

## 10. 구현 결과 (as-built, 2026-11-02)

전부 C++(WBP·에셋 수정 없음). 공통 메뉴 기반(`UI/Menu/` — `UCXMenuSubsystem`, `UCXMenuWidgetBase`, `UCXMenuItemWidget`, `UCXPauseDimWidget`, `CXMenuStyle`)을 재사용했다. 라벨은 8장 규칙대로 영문.

### 구현한 것

| 항목 | 내용 |
|---|---|
| 공용 상호작용 `UCoopInteractComponent` | 두 캐릭터 공용 F(키보드) / X(`Gamepad_FaceButton_Left`). 런타임 IA/IMC(`IA_Coop_Interact`/`IMC_CoopInteract`, 우선순위 10)를 **이 폰을 조작하는 로컬 플레이어**에 추가 → 조작 장치 설정(키보드가 여동생인 스왑 조합 포함)을 기존 입력 경로 그대로 따른다. 0.2초마다 범위 안 `ICoopInteractable` 중 `CanInteract`가 참인 가장 가까운 대상을 포커스(후보 목록은 1초마다 갱신 — 런타임 스폰 대상도 잡힘). 실행은 서버 권위(클라이언트면 `Server_Interact` RPC, 서버가 `CanInteract` 재검증). 여동생은 `ASisterCharacter` 생성자에서, 오빠(BP_Brother, 부모 Character)는 `ALocalCoopGameMode::SetPlayerDefaults`가 런타임에 붙인다. |
| F/X 우선순위 | 한 번 누르면 한 동작: **① 해킹 중이면 해킹 입력(비밀번호 제출) ② 범위 안에 해킹 가능한 단말기가 있으면 해킹 시작 ③ 그 외 포커스 대상(문 버튼)**. F/X는 `UCoopInteractComponent` 하나만 바인딩하고 `USisterHackComponent::WantsInteract()`가 참이면 `Interact()`로 넘긴다 — `IMC_Hack`에서 F/X 매핑을 뺐다(같은 키 이중 바인딩 방지). 방향키/D-pad·Backspace/B 해킹 입력은 그대로. |

### 기획과 다른 점

- **진입 연출 순서**: 9장 메모는 "0.5초 후 `SetGamePaused` + `PushMenu`"지만, 2.2의 "0.5초 딤 → 정지 → 패널"을 보이게 하려고 **위젯을 판정 즉시 올리고**(딤이 0.5초에 걸쳐 깔림) 0.5초 뒤 월드를 정지한다. 그 0.5초 동안 게임플레이 입력은 폰 `DisableInput`으로 막는다.
- **`OpenLevel` 직전 `SetMenuBlocked(false)`** 대신 서브시스템 `ResetPauseState`(PreLoadMap)에서 해제(9장에 적힌 대안). 어떤 경로로 맵을 떠나도 풀린다.
- **문 열림 연출**: 셔터가 위로 말려 올라가는 세로 스케일(위쪽 피벗). 문 뒤는 검정 판(통로처럼 보이게). 충돌은 다 열린 순간 끈다.
- **상호작용 키 바인딩 위치**: 해킹의 F/X도 공용 상호작용 컴포넌트가 받아 넘긴다(위 우선순위). 해킹 HUD 문구(`[X] HACK`/`[X] SUBMIT`)는 그대로.
- **위젯 소유**: 화면 전체 하나 — `LocalPlayer 0` 컨트롤러 소유(장치 스왑이면 여동생 컨트롤러). 누구나 조작.

### 보류 / 미검증

- **`Map3_Final` 미배치**: 맵이 아직 없고 기존 `Map3`/`Map3_work`는 다른 팀원 작업이라 손대지 않았다. 맵이 생기면 보스방 출구에 `ACXCoopExitDoor`를 놓기만 하면 된다(-X가 카메라 쪽, 원점 = 문 아래 가운데 바닥).
- **원격 클라이언트(listen server)**: 버튼 상태/열림은 복제되지만, 클리어화면·세이브 삭제·월드 정지는 **호스트(로컬 협동) 기준**이다. 원격 클라이언트에 클리어화면을 띄우는 Client RPC는 없다. 네트워크 PIE로 검증하지 않았다.
- **사망/부활 연동**: 시스템이 없어 `IsPawnAbleToInteract`(유효·조작 중·숨김 아님)만 — 사망·부활 대기 판정은 그 시스템이 생기면 여기에 추가.
- **실제 게임패드 X**: 패드가 없어 미검증(키보드 F만 실제 입력으로 확인, 여동생 쪽은 `Interact()` 직접 호출).
- **진입 연출 타이밍 육안 확인**: 원격 파이썬 호출 간격(약 1초) 때문에 셔터가 올라가는 중간·딤이 깔리는 중간 화면은 캡처하지 못했다(결과 상태만 확인).
- 사운드(버튼/문 열림/클리어 징글)는 슬롯만, 에셋이 없어 무음. 마우스 클릭 선택은 공통 베이스 경로라 별도 확인 안 함.
