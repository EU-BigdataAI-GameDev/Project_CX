## 0. 공통 UI 규칙 (모든 메뉴 화면 공용)

ESC 메뉴 / 시작화면 / 게임 오버화면 / 설정 메뉴는 모두 이 규칙을 따른다. 다른 문서는 이 장을 참조만 한다.

### 0.1 화면 원칙

- 메뉴는 **화면 전체(1920x1080)에 하나만** 띄운다. 분할된 한쪽 칸에 띄우지 않는다.
- 두 플레이어 **누구나** 메뉴를 조작할 수 있다. 조작 권한(소유자) 개념은 없다.
- **동시 입력은 먼저 들어온 입력이 이긴다.** 같은 프레임에 두 입력이 들어오면 P1 입력을 처리하고 나머지는 버린다. 화면 전환(열기/닫기/확인창) 직후 **0.15초 입력 잠금**으로 "한 명은 닫고 한 명은 다시 여는" 중복을 막는다.
- **모든 메뉴는 게임패드만으로 조작 가능**해야 한다(여동생은 기본 게임패드).

### 0.2 입력 표

| 동작 | 키보드/마우스 | 게임패드 |
|---|---|---|
| 메뉴 열기/닫기 | `ESC` | `Start` |
| 이동 | 방향키 / 마우스 | D-pad / 왼쪽 스틱 |
| 선택 | `Enter` / 좌클릭 | `A` (FaceButton_Bottom) |
| 뒤로 | `ESC` | `B` (FaceButton_Right) |
| 값 조절(슬라이더·선택형) | `←` `→` | D-pad 좌우 / 왼쪽 스틱 좌우 |
| 탭 전환(설정 메뉴) | `Q` `E` | `LB` `RB` |

- 마우스: 항목에 **호버하면 포커스가 그 항목으로 이동**한다(키보드/패드 포커스와 하나로 공유). 마우스 커서는 마우스가 움직일 때만 보이고, 키/패드 입력이 오면 숨긴다.
- 스틱 이동은 0.35초 첫 반복, 이후 0.1초 간격 자동 반복. 스틱 데드존 0.5.
- 서브 화면(설정, 확인창)에서 `ESC`/`B`는 **한 단계 뒤로**. 최상위 메뉴에서의 `ESC`/`B` 동작은 화면별 문서에 정의한다.

### 0.3 포커스 규칙

- 화면이 열리면 **기본 포커스 항목**(화면별 문서에 명시)에 포커스가 간다.
- 위/아래 끝에서 **순환(wrap-around)** 한다(설정 메뉴의 항목 리스트 포함).
- 비활성 항목(조건 미충족)은 **목록에서 숨긴다**. 보기만 가능한 항목은 표시하되 포커스는 받고 값 변경은 안 된다(자물쇠 아이콘 + 안내 문구).
- 서브 화면에서 돌아오면 **들어갔던 항목에 포커스를 복원**한다.
- 포커스 하이라이트 색은 **마지막으로 입력한 플레이어 색**(P1 오빠 청록 / P2 여동생 마젠타). 누가 조작 중인지 바로 보인다.

### 0.4 확인창

- 되돌릴 수 없는 동작(타이틀로, 새 게임 덮어쓰기, 게임 종료, 기본값 복원)은 확인창을 띄운다.
- 확인창은 화면 중앙 모달. 버튼 2개 `확인` / `취소`, **기본 포커스는 항상 안전한 쪽 `취소`**.
- 확인창에서 `ESC`/`B` = `취소`.
- 버튼 라벨: `확인` = `CONFIRM`, `취소` = `CANCEL`.

### 0.5 비주얼 톤 (HUD와 통일 — `HUD 기획.md`)

| 토큰 | 값 (`ACoopHUD` 기본값과 동일) | 용도 |
|---|---|---|
| Panel | `(0.01, 0.015, 0.03, 0.62)` 어두운 반투명 | 메뉴 패널, 확인창 |
| Brother | `(0.0, 0.85, 1.0)` 청록 | P1 포커스, 오빠 관련 표기 |
| Sister | `(1.0, 0.22, 0.62)` 마젠타 | P2 포커스, 여동생 관련 표기 |
| Warning | `(1.0, 0.35, 0.08)` 주황 | 확인창 경고 문구, 연결 끊김 |
| Text | 흰색 90% / 비활성 40% | 일반 텍스트 |

- 패널 테두리는 1~2px 얇은 네온 라인, 모서리에 짧은 브래킷(HUD 타겟 브래킷과 같은 문법).
- 배경: 인게임 메뉴는 게임 화면 위에 검정 55% 딤 + 약한 스캔라인. 시작화면은 자체 배경.
- 포커스 항목: 왼쪽 2px 네온 바 + 텍스트 밝기 100% + 옅은 글로우. 포커스 이동 시 바가 0.08초 슬라이드.
- 화면 열기/닫기: 0.15초 페이드 + 패널 세로 스케일 0.96→1.0(CRT 켜짐 느낌). 과한 글리치는 피한다(가독성 우선).

### 0.6 사운드 큐 (모두 `효과음` 버스)

| 큐 | 시점 |
|---|---|
| `UI_Move` | 포커스 이동, 값 조절 1단계 |
| `UI_Confirm` | 선택 |
| `UI_Back` | 뒤로 / 취소 / 메뉴 닫기 |
| `UI_Open` | 메뉴·확인창 열기 |
| `UI_Denied` | 불가 동작(보기 전용 항목 변경 시도, 키보드 중복 지정 시도) |

- 일시정지 중에도 재생되도록 UI 사운드는 일시정지 영향을 받지 않게 재생한다(`bIsUISound`).

### 0.7 한글 폰트 / 영문 전환

- **언리얼에서 한글이 깨져 보이면 메뉴명을 모두 영어로 바꿔도 된다.** 한글을 쓰려면 한글 폰트 에셋(예: **Noto Sans KR**)을 프로젝트에 추가하고 UMG 폰트로 지정해야 한다. 엔진 기본 Roboto에는 한글 글리프가 없다(HUD도 같은 이유로 영문 표기).
- 모든 문구는 KR/EN 쌍으로 정의하고, 문서마다 영문 라벨을 함께 적어 둔다. 구현 시 `FText` 문자열 테이블(String Table) 하나에 두 언어 키를 두면 전환이 한 줄로 끝난다.

## 1. 설정 메뉴 목적

사운드, 화면 분할, 조작 장치, 조작법을 한곳에서 다룬다. ESC 메뉴와 시작화면이 같은 화면을 연다. 차이는 하나뿐이다.

| 진입 경로 | `조작 장치` |
|---|---|
| 시작화면 → 설정 | **변경 가능** |
| ESC 메뉴 → 설정 | **보기만 가능**(플레이 중 장치가 바뀌면 혼란) |

## 2. 진입 / 종료

- 진입: 시작화면 또는 ESC 메뉴에서 `설정` 선택.
- 종료: 최상위(탭 화면)에서 `ESC`/`B` → 호출한 메뉴로 복귀(포커스는 `설정` 항목에 복원).
- 값은 **바꾸는 즉시 적용**(미리듣기/미리보기)하고, 설정 메뉴를 **닫을 때 저장**한다. 별도의 "적용" 버튼은 두지 않는다.

- 중앙 1200x720 패널, 상단 탭 4개, 하단에 포커스 항목 설명줄 + 입력 힌트(마지막 입력 장치에 맞는 아이콘: 키보드면 `[Enter] [ESC] [←→]`).
- 탭 포커스: 탭 줄과 항목 리스트는 위/아래로 오간다(리스트 맨 위에서 위 → 탭 줄). `LB`/`RB`·`Q`/`E`는 어디서나 탭 전환.
- 기본 포커스: 첫 진입 시 `사운드` 탭의 `전체`. 같은 세션에서 다시 열면 마지막 탭 유지.

### 4.2 사운드

| KR | EN | 동작 | 기본값 |
|---|---|---|---|
| 전체 | MASTER | 0~100, 10단위, 좌우로 조절 | 80 |

- 조절할 때마다 해당 버스로 짧은 미리듣기 큐 재생(`효과음`은 `UI_Move`, `배경음`은 현재 BGM이 즉시 반영).
- 마우스: 바 클릭/드래그로 값 설정(10단위 스냅).

### 4.3 화면 분할

| KR | EN | 동작 | 기본값 |
|---|---|---|---|
| 분할 방식 | LAYOUT | `상하` (TOP / BOTTOM) ↔ `좌우` (LEFT / RIGHT) | **상하** |

- 만일에 대비한 옵션. 옆에 작은 미리보기 아이콘(위 청록/아래 마젠타, 또는 좌 청록/우 마젠타).
- 인게임에서 바꾸면 즉시 반영. 단, 현재 HUD는 **각 칸 1920x540(상하) 기준**이라 좌우(960x1080)에서는 HUD 배치 재조정이 필요하다(아래 구현 메모).

### 4.4 조작 장치

| KR | EN | 동작 | 기본값 |
|---|---|---|---|
| 오빠 (P1) | BROTHER (P1) | `키보드/마우스` ↔ `게임패드` | 키보드/마우스 |
| 여동생 (P2) | SISTER (P2) | `키보드/마우스` ↔ `게임패드` | 게임패드 |

값 라벨: `키보드/마우스` = `KEYBOARD & MOUSE`, `게임패드` = `GAMEPAD`.

규칙:

| 조합 | 허용 |
|---|---|
| 오빠 키보드 / 여동생 게임패드 (기본) | O |
| 오빠 게임패드 / 여동생 키보드 | O |
| 둘 다 게임패드 | O (게임패드 2개 필요) |
| 둘 다 키보드 | **X** — 키보드는 하나뿐 |

- **UI에서 둘 다 키보드가 되는 조작 자체를 막는다**: 한쪽이 이미 키보드면, 다른 쪽을 키보드로 바꾸려 할 때 값이 바뀌지 않고 `UI_Denied` + 안내 문구 "키보드는 한 명만 쓸 수 있습니다" / `ONLY ONE PLAYER CAN USE THE KEYBOARD`. (자동 스왑은 하지 않는다 — 의도치 않게 상대 장치가 바뀌는 혼란 방지.)
- 각 행 오른쪽에 연결 상태 표시: `연결됨` / `CONNECTED`, `연결 안 됨` / `NOT CONNECTED`(주황). 게임패드가 부족하면 메뉴를 닫을 때 경고만 띄우고 시작화면의 `P2 PRESS START` 확인 단계에서 걸러진다(`게임 시작화면 기획.md`).
- **ESC 메뉴에서 열면 보기 전용**: 두 행에 자물쇠 아이콘, 좌우 입력 시 `UI_Denied` + "조작 장치는 시작화면에서만 바꿀 수 있습니다" / `INPUT DEVICES CAN ONLY BE CHANGED FROM THE TITLE SCREEN`.

#### 키 충돌 — 확정/적용 (2026-11-01)

- (변경 전) 해킹 취소 입력은 `SisterHackComponent`가 런타임 매핑으로 **게임패드 `B`(FaceButton_Right) + 키보드 `Escape`** 에 걸어 두었다. → 현재 **게임패드 `B` + 키보드 `Backspace`**.
- 여동생이 키보드를 쓰면 해킹 중 `Escape`가 **해킹 취소와 ESC 메뉴 열기 둘 다**에 걸린다.
- **확정/적용: 키보드 해킹 취소를 `Backspace`로 변경**(게임패드 `B`는 유지). `Escape`는 메뉴 전용. `SisterHackComponent` 런타임 매핑에 반영됨(ESC 메뉴 구현과 함께, `ESC 메뉴 기획.md` 10장).
- 게임패드 쪽 정리: 해킹 중에는 메뉴가 닫혀 있으므로 `B`는 **해킹 취소**로만 동작하고 메뉴 `뒤로`와 겹치지 않는다. 해킹 중에도 `Start`는 메뉴를 연다(이때 해킹은 일시정지와 함께 멈추고, 메뉴를 닫으면 그대로 이어진다).

### 4.5 조작법

- 하위 탭 2개: `오빠` / `BROTHER`, `여동생` / `SISTER`. 각 캐릭터 페이지에 장치 토글 `키보드/마우스` ↔ `게임패드`.
- **현재 조작 장치 설정에 맞는 장치 화면을 먼저 보여준다**(기본: 오빠 → 키보드, 여동생 → 게임패드). 토글로 다른 장치 화면도 볼 수 있다.
- 키보드 화면은 키 아이콘 목록, 게임패드 화면은 패드 실루엣 + 지시선. 보기 전용(키 리바인딩은 범위 밖).

오빠 (현재 코드/기획 기준):

| 동작 KR / EN | 키보드/마우스 | 게임패드 | 상태 |
|---|---|---|---|
| 이동 / MOVE | `A` `D` | 왼쪽 스틱 | 구현(`IA_Move`, 템플릿 IMC) |
| 점프 / JUMP | `Space` | `A` | 구현(`IA_Jump`) |
| 사격 / FIRE | 좌클릭 | `RT` | 구현(`IA_Fire`) — 패드 매핑은 제안 |
| 조준(누르고 있기) / AIM (HOLD) | 우클릭 | `LT` | 구현(`IA_Aim`) — 패드 매핑은 제안 |
| 회피 / DODGE | 왼쪽 `Shift` | `RB` | 기획만(`오빠 캐릭터 기획.md` 3장) — 패드 매핑은 제안 |
| 장전 / RELOAD | 자동(탄약 0) | 자동 | 구현 — 수동 장전 키 없음, 안내 문구로만 표기 |
| 메뉴 / MENU | `ESC` | `Start` | 이 문서 (ESC 메뉴 구현됨) |

- 근접 5m 안 적 자동 조준(`AUTO`)도 한 줄 팁으로 표기: "가까운 적은 자동으로 조준됩니다" / `NEARBY ENEMIES ARE AUTO-TARGETED`.

여동생:

## 5. 저장 / 유지

- 설정값(음량 3개, 분할 방식, 조작 장치 2개)은 **게임을 껐다 켜도 유지**한다.
- 저장 시점: 설정 메뉴를 닫을 때 1회. 비정상 종료 대비로 조작 장치 변경은 즉시 저장.
- 세이브 데이터(진행도)와 **분리**한다 — `새 게임`으로 세이브를 덮어써도 설정은 그대로.
- 저장 파일이 없거나 손상되면 기본값으로 시작.

## 8. 구현 메모 (C++ 우선)

- **위젯**: `UCXMenuWidgetBase : UUserWidget`(포커스/순환/입력 잠금/사운드 큐 공통) → `UCXSettingsWidget`. 레이아웃만 WBP에서 `BindWidget`으로 잡고 로직은 C++.
- **메뉴 관리자**: `UCXMenuSubsystem : UGameInstanceSubsystem` — 메뉴 스택(Push/Pop), 전체 화면 위젯은 `AddToViewport`(분할 칸 무관 전체 덮기), 양쪽 플레이어 입력 라우팅. 두 로컬 플레이어 모두 메뉴를 조작하도록 각 Slate 사용자에게 포커스를 준다(`FSlateApplication::SetUserFocus`를 로컬 플레이어마다), 또는 메뉴 입력을 C++(`NativeOnKeyDown`)에서 직접 받아 내비게이션을 처리한다.
- **설정 저장**: `UCXGameUserSettings : UGameUserSettings` (`DefaultEngine.ini`의 `GameUserSettingsClassName` 지정) — `MasterVolume`/`MusicVolume`/`SfxVolume`(int 0~100), `SplitLayout`, `BrotherDevice`/`SisterDevice`를 `UPROPERTY(Config)`로. `GameUserSettings.ini`에 저장되어 세이브(`USaveGame`)와 자연히 분리된다.
- **음량**: Sound Class `SC_Master` ← `SC_Music`, `SC_SFX`(자식). Sound Mix `SM_UserVolume`에 세 클래스 어저스터. 적용은 `UGameplayStatics::SetSoundMixClassOverride` + `PushSoundMixModifier`(게임 시작 시 1회 Push).
- **화면 분할**: 엔진 설정은 `UGameMapsSettings::TwoPlayerSplitscreenLayout`(현재 `Horizontal` = 상하). 런타임 전환은 `UGameViewportClient` 서브클래스에서 `UpdateActiveSplitscreenType()`를 오버라이드해 `UCXGameUserSettings::SplitLayout`을 읽게 한다. `ACoopHUD`는 칸 크기(`Canvas->ClipX/ClipY`) 기준 배치로 바꿔 좌우에도 대응.
- **조작 장치**: 현재 `bOffsetPlayerGamepadIds=True`(1번 게임패드 → P2). 조합별 처리:
  - 기본(오빠 키보드/여동생 패드): 현행 그대로.
  - 둘 다 패드: 오프셋 해제와 동등하게 패드0 → P1, 패드1 → P2(`IPlatformInputDeviceMapper`로 장치-사용자 매핑).
  - 오빠 패드/여동생 키보드: 키보드는 항상 LocalPlayer 0으로 들어오므로 **LocalPlayer 0에 여동생 폰을 배정**(`ALocalCoopGameMode::GetDefaultPawnClassForController` 분기에 설정값 반영). 분할 칸 순서가 바뀌는 것은 허용하거나, 칸 순서를 고정하려면 ViewportClient에서 칸 배치를 스왑.
- **키 충돌**: `USisterHackComponent`의 `MapKey(CancelAction, EKeys::Escape)` → `EKeys::BackSpace`(확정 시 반영).
- **메뉴 입력이 일시정지 중에도 동작**: 메뉴 토글 `IA_Menu`(ESC/Start)는 `bTriggerWhenPaused = true`, 플레이어 컨트롤러 `bShouldPerformFullTickWhenPaused`.

- **SFX 미리듣기**: `UI_Move` 슬롯/`SfxPreviewSound` 슬롯만 — 효과음 에셋이 없어 현재 무음(배경음은 재생 중인 시작화면 BGM에 즉시 반영).
- **탭 순환**: 리스트 맨 아래에서 아래도 탭 줄로 간다(탭 줄을 순환 고리에 포함).
- **패드 실루엣 + 지시선**: 생략, 텍스트 조작표만.
- **여동생 CONTROLS 팁**: 기획에 없던 한 줄 추가(해킹 단말기 범위 표시 — CoopHUD 동작 기준).
- **둘 다 게임패드**: 키보드도 여전히 LocalPlayer 0(오빠)을 움직인다(막지 않음).
- **게임패드 수 판정**: `IsGamepadAttached` + 장치 매퍼의 연결 장치 수(키보드 제외). 인게임 둘 다 패드 Remap이 만드는 가상 장치 ID도 "연결"로 잡힐 수 있어, 인게임 행 상태는 배정 패드 상태 → 연결 끊김 플래그 → 연결 수 순서로 판단한다.

### 보류 / 미검증

- **실제 게임패드 없이 검증**: 패드 연결 상태 표시, 둘 다 패드 / 오빠 패드 조합의 실제 버튼 입력 경로, 시작화면 PRESS START 후 둘 다 패드로 시작(패드가 없으면 시작화면이 배정을 지워 시작 불가 — 기존 동작), RT/LT 사격·조준, 두 번째 패드의 플랫폼 사용자 매핑(시뮬레이션에서 ControllerId 1 + 기본 조합은 매핑된 사용자가 없어 -1)은 **미검증**. 라우팅 판단 자체는 `DebugResolveGamepadPlayer`로만 확인.
- **마우스**: 호버 포커스(항목·탭), 탭 클릭, 바 클릭/드래그는 구현했지만 자동화로 마우스 이벤트를 넣지 못해 미검증.
- **실제 청취**: 믹스 적용은 사운드 클래스 실효 음량(`ListSoundClassVolumes`)으로만 확인, 귀로는 미확인.
- 좌우 분할 HUD는 축소만(재배치 없음), 패키징 빌드 미확인.
