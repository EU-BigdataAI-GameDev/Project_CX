## 0. 요청 요구사항 (원문 정리)

1. 해킹 단말기 근처에서 **화살표를 순서대로 누르는 퍼즐**을 맵1에 추가한다.
2. 해킹 중임을 잘 보여주는 **해킹 UI**를 추가한다.
3. 해킹은 **여동생만** 가능하다. 오빠가 단말기에 가까이 가도 해킹 UI가 뜨지 않고, 해킹 UI는 **여동생 화면에만** 나타난다.
4. 화살표 퍼즐 외에 **다른 퍼즐 아이디어 3개**를 기획한다.
5. **비밀번호 기믹**: 오빠가 맵을 돌아다니며 벽에 적힌 숫자를 불러주면, 여동생이 단말기에 4자리 비밀번호를 입력한다.

## 1. 기존 화살표 퍼즐(develop) 분석과 재구현 이유

`Content/stage2_KJM/BP_HackZone` + `WBP_HackMinigame` (맵2 해킹 방어전, 팀원 구현):

| 항목 | 기존 구현 | 문제 |
|---|---|---|
| 시작 | 박스 오버랩 시 위젯 생성 | 캐릭터 구분 없음 → 오빠도 발동 |
| 화면 | `AddToViewport` | 분할 화면 **양쪽 전체**를 덮음 |
| 입력 | 키보드 방향키(InputKeyEvent) | 키보드는 1P(오빠) 장치 → 게임패드 쓰는 여동생이 조작 불가 |
| 규칙 | 라운드별 길이(`RowLengths`), 최대 7칸, `CheckArrow`로 순서 판정, 해킹 중 몬스터 주기 스폰 | 규칙 자체는 좋음 → 그대로 계승 |

→ 규칙은 계승하고, **여동생 전용 / 여동생 화면 전용 / 게임패드 입력**으로 C++에서 다시 구현한다. 기존 BP는 맵2용으로 그대로 둔다.

## 2. 구조

```
AHackTerminal (월드 단말기)            USisterHackComponent (여동생에게만 붙음)
 ├ 퍼즐 종류: ArrowSequence/Passcode     ├ 0.2초마다 가장 가까운 단말기 탐지(사거리 300cm)
 ├ 라운드 길이 / 비밀번호(랜덤 생성 가능)  ├ 입력: 런타임 생성 매핑(D-pad·X·B, 키보드 대응)
 ├ 상태: Locked → InProgress → Hacked    ├ 세션: 시작/입력 판정/실패 리셋/성공/취소
 ├ 상태등(빨강→초록), UnlockActors 해제   └ 해킹 중 이동·점프 잠금
 └ OnHacked 델리게이트
                    ACoopHUD (플레이어별 분할 화면) — 여동생 칸에서만 해킹 패널/세션 UI를 그린다
AHackCodeClue (벽 숫자) — 오빠 폰을 Owner로 잡고 OnlyOwnerSee → 오빠 화면에만 보임
```

- **여동생 전용**: 해킹 컴포넌트는 `ASisterCharacter`에만 있다. 오빠에게는 탐지/입력/UI가 아예 없다.
- **여동생 화면 전용**: HUD는 PlayerController마다 하나씩 생기고 자기 분할 칸에만 그린다. 해킹 UI는 소유 폰이 여동생일 때만 그린다.
- **서버 권위(listen server 전제)**: 판정/상태 변경은 단말기의 권위 측에서 처리하고 `State`는 복제한다(현재는 로컬 2인이라 같은 머신).

## 3. 퍼즐 A — 화살표 시퀀스 (구현)

| 항목 | 값 |
|---|---|
| 시작 | 단말기 300cm 이내에서 **X**(게임패드 왼쪽 버튼) / 키보드 F |
| 입력 | **D-pad 상하좌우** (키보드 방향키 대응) |
| 라운드 | 기본 `{4, 5, 6}` 칸(단말기별 설정, 최대 7칸 — 기존 BP와 동일) |
| 실패 | 틀리면 **해당 라운드 처음부터**(같은 배열 유지 → 외워서 재도전 가능), 0.6초 `ACCESS DENIED` |
| 성공 | 마지막 라운드 완료 → `ACCESS GRANTED`, 단말기 Hacked, 연결된 장애물 해제 |
| 취소 | **B** / Esc — 진행 초기화, 단말기 Locked 복귀 |
| 소프트락 | 없음(무제한 재시도, 취소 가능) — 레벨 기획 3.5 원칙 |

## 4. 퍼즐 B — 4자리 비밀번호 (구현, 협동 기믹)

- 단말기는 게임 시작 시 비밀번호 4자리를 **랜덤 생성**한다(매 플레이 다름 → 공략 암기 방지).
- 맵 곳곳 벽에 `#1 : 7` 형태의 숫자 단서 4개(`AHackCodeClue`). **오빠 화면에만 보인다**(OnlyOwnerSee).
  → 오빠가 돌아다니며 읽어주고(음성/채팅), 여동생이 입력하는 진짜 협동 구조.
- 입력: **D-pad ▲▼ 숫자 변경, ◀▶ 자리 이동, X 제출, B 취소**.
- 틀리면 `ACCESS DENIED`, 입력값은 유지(한 자리만 고치면 되도록).

## 5. 해킹 UI (여동생 화면)

- 평상시: 좌하단 HACK LINK 패널(`SCANNING` / `SIGNAL DETECTED` / `TERMINAL ONLINE [X] BREACH`) + 단말기 위 마름모 마커 — HUD 기획 참고.
- 해킹 중: 화면 중앙 하단 오버레이 패널
  - 헤더 `BREACHING // TERMINAL_01`, 깜빡이는 커서, 우측 `ROUND 2/3`
  - 화살표 퍼즐: 칸마다 화살표 아이콘 — 완료(채움), 현재(펄스 테두리), 대기(흐림)
  - 비밀번호: 큰 숫자 4칸, 현재 칸 위아래 ▲▼ 표시
  - 하단 진행 바 + 조작 안내, 글리치 스캔 라인(해킹 중 느낌)
  - 실패: 붉은 테두리 + `ACCESS DENIED` / 성공: 초록 `ACCESS GRANTED`
- 단말기 상태등: Locked 빨강 → InProgress 노랑 깜빡임 → Hacked 초록.

## 7. 추가 퍼즐 아이디어 3종 (기획만)

### 7.1 주파수 동조 (Signal Tuning)
- 화면에 목표 파형(사인파)과 현재 파형이 겹쳐 보인다. **왼쪽 스틱 = 주파수, 오른쪽 스틱 = 진폭**을 돌려 두 파형을 일치시키고 1초 유지하면 성공.
- 단말기 근처 감시 드론이 접근할수록 노이즈가 섞여 파형이 흔들린다 → **오빠가 드론을 쏴서 떨어뜨리면 노이즈가 사라지는** 협동 구조.
- 장점: D-pad 위주인 화살표 퍼즐과 달리 아날로그 스틱 감각을 쓴다.

### 7.2 방화벽 미로 (Packet Run)
- 격자 미로에서 데이터 패킷을 D-pad로 한 칸씩 이동해 코어까지 보낸다. 미로에는 **순찰하는 보안 노드**가 있어 닿으면 시작점으로.
- 맵 쪽 스위치(오빠가 사격으로 작동)가 미로의 **방화벽 문 일부를 열고 닫는다** → 오빠가 타이밍 맞춰 쏴서 길을 열어 준다.
- 장점: 실시간 위험 요소 + 오빠의 사격과 직접 연결.

### 7.3 메모리 패턴 (Ghost Echo)
- 3x3 노드가 순서대로 깜빡인 뒤 사라지고, 같은 순서로 노드를 선택해야 한다(라운드마다 1개씩 증가, 사이먼 게임식).
- 패턴은 **오빠 화면에만 재생**된다 → 오빠가 보고 불러주고 여동생이 입력(비밀번호 기믹의 실시간 버전).
- 장점: 비밀번호 기믹의 "정보 비대칭 협동"을 짧은 루프로 반복할 수 있다. 보스 직전 맵에서 난이도 정점 퍼즐로 쓰기 좋다.

### 10.1 흐름

```
여동생이 거미로봇 300cm 안 + F/X  (해킹 가능: 살아 있음, 그로기 아님, 여동생 적 해킹 쿨타임 아님)
  → 주파수 동조 퍼즐(여동생 칸 중앙 하단, 최대 4초, 여동생 제자리 고정 — 거미는 계속 공격)
  → 성공: 서버가 재검증 → 거미 Stunned 3초(이동·공격 정지, 총알 피해는 그대로) → 3초 뒤 재부팅 → Chase
  → 실패(시간 초과 / 대상 사망): 그로기 없음
  → 취소(B / Backspace): 그로기 없음
  세션 종료(성공·실패·취소) 후 3초 동안 적 해킹 불가(단말기 해킹은 쿨타임 없음 — 기존 그대로)
```

### 10.2 퍼즐 C — 주파수 동조 (Frequency Lock, 적 해킹 전용)

7.1의 "주파수 동조" 아이디어를 **전투 중에 쓸 수 있는 반사 퍼즐**로 줄였다(아날로그 스틱 2개 → 버튼 1개, 1초 유지 → 순간 판정).

| 항목 | 값 | 비고 |
|---|---|---|
| 화면 | 가로 막대(노이즈 섞인 파형) 위를 흰 커서가 **좌우 왕복**, 막대 안에 마젠타 목표 구간 `LOCK` | 단말기 패널과 같은 크기·스타일(검은 반투명 + 네온 테두리 + 글리치 띠). 단, 위치는 여동생 칸 **위쪽 가운데** — 하단이면 캐릭터·거미(칸 아래쪽에 서 있음)를 가린다(PIE에서 확인 후 변경) |
| 입력 | **X / F**(해킹을 시작한 같은 키 = 공용 상호작용 키) — 커서가 구간 안일 때 누르면 고정 | 해킹 세션 중 F/X는 1순위로 해킹 입력(기존 규칙) |
| 목표 | **3연속 고정** | 오른쪽 위 칸 3개 + `FREQ LOCK n/3` |
| 단계별 구간 폭 | 막대의 **24% → 18% → 13%** | `FreqZoneWidths` |
| 단계별 커서 속도 | 초당 막대 **1.5 → 2.0 → 2.6**개(한 번 건너는 시간 0.67 → 0.5 → 0.38초) | `FreqCursorSpeeds` |
| 새 구간 위치 | 랜덤, 단 커서에서 막대의 30% 이상 떨어진 곳 | 연타로 바로 맞히는 것 방지 |
| 빗나감 | **1단계부터 다시**(새 구간) + 0.25초 입력 무시, `DESYNC` + 흔들림 | 즉시 실패보다 재미있고, 벌칙은 "시간 손해"뿐 — 4초 제한이 자연스러운 상한 |
| 제한 시간 | **4.0초**(남은 시간 바, 1초 이하 붉게 깜빡) | 숙련자 약 1.5~2.5초(단계당 대기 평균 반 왕복 + 반응) |
| 결과 표시 | 성공 `ACCESS GRANTED // SYSTEM DOWN`(초록), 실패 `ACCESS DENIED`(빨강) 0.6초 후 패널 닫힘 | 결과가 나는 순간 이동 잠금 해제 |
| 소리(기존 에셋) | 시작 `SW_Hack_Start`, 루프 `SW_Hack_Loop`, 고정 `SW_Hack_Input`(단계마다 피치↑), 빗나감 `SW_Hack_Denied`, 성공 `SW_Hack_Granted`, 실패 `SW_Hack_Denied`(피치 0.8), 취소 `SW_Hack_Cancel` | 여동생 로컬 2D(기존 해킹 UI 규칙) |

### 10.3 그로기(거미로봇 `Stunned`)

| 항목 | 값 / 동작 |
|---|---|
| 지속 | **3.0초** `ASpiderBot::StunDuration`(EditDefaultsOnly) |
| 행동 | 이동·공격 정지(서버 상태 기계의 새 상태 `Stunned`), 재해킹 불가, **총알 피해는 그대로**(오빠가 마무리 — 5발 파괴 리듬 유지). 끝나면 즉시 대상 재평가 → `Chase` |
| 그로기 중 사망 | 연출을 걷고 기존 래그돌 |
| 자세 | 공격 애님 `AS_SpiderBot_Attack`의 내려찍기 끝 프레임(17/24)에서 정지 = **톱 팔이 바닥으로 떨어지고(톱날이 땅에 닿음) 몸통이 앞으로 숙음** + 메시 9cm 주저앉음(캡슐 불변). 집게 팔은 공격 애님이 건드리지 않아 그대로 |
| 경련 | 0.18~0.5초마다 0.08초 톱 팔이 살짝 들렸다 떨어지고(애님 위치 78~90%로 점프 — 복귀 구간) 몸이 2.5cm 떨림 |
| 정전 깜빡임 | 0.04~0.12초마다 모든 슬롯: 원래(55%) / `Mat_Black` 정전(30%) / `Mat_EyeGlow` 과부하(15%). 마지막 0.45초는 `Mat_EyeGlow` 고정 = 재부팅 신호 |
| 전기 불빛 | 몸통 위 포인트 라이트, **청록/자홍**이 번갈아 랜덤 밝기(스켈레탈용 청록 발광 머티리얼이 없어 새 에셋 대신 라이트) |
| 스파크 | SoulCity `P_WeldSparks` 파티클(0.35배) |
| 소리 | 시작 `SW_Gate_Off`(전원 차단, 피치 1.15) + 루프 `SparkLoop01`(톱날 `SparkLoop02`와 구분), 끝 `SW_UI_NeonBuzz`(재부팅) |
| HUD | **두 플레이어 칸 모두** 거미 위에 `SYSTEM DOWN` + 남은 시간 바·초(청록/자홍 글리치). 그로기 중 거미 체력 바(5칸)도 항상 표시. 여동생 칸의 `[X] HACK` 마커는 그로기 중 숨김 |

### 10.4 쿨타임 / HUD 마커

- 적 해킹 쿨타임 **3초, 세션이 끝난 시점부터**(`USisterHackComponent::EnemyHackCooldown`). 여동생 기획서 3장은 "시도 시점부터 3초"였지만 퍼즐 자체가 최대 4초라 의미가 없어 종료 시점으로 바꿨다. 단말기 해킹에는 적용하지 않는다(기존 동작 유지).
- 여동생 칸 거미 마커: 해킹 가능(범위 안 + 쿨타임 아님 + 다른 해킹 중 아님)일 때만 `[X] HACK`. 범위 안인데 쿨타임이면 `RELINK 2.1s`, 범위 밖이면 거리. HACK LINK 패널 윗줄에 `ENEMY RELINK n.ns` + 아랫변 게이지.

### 10.5 설계 결정

| 항목 | 결정 | 이유 |
|---|---|---|
| 해킹 중 이동 | **잠금**(단말기와 같음, 최대 4초) | 위험 부담 = 협동: 여동생이 묶인 동안 오빠가 엄호. 결과가 나면 즉시 풀림 |
| 해킹 중 거미 공격 | **계속**(톱 30 / 1.1초) | 미리 거리를 두고(300cm) 거는 판단이 실력. 맞으면서 걸면 최대 2~3대 |
| F/X 우선순위 | 해킹 세션 > 단말기 > 문 버튼 > **적 해킹**(기존 순서 유지) | 단말기·문은 자리가 고정된 목표라 가로채면 안 됨. 거미는 움직이므로 한 걸음 비켜서면 해킹 가능 |
| 피격 시 해킹 취소 | 안 함 | 사망하면 기존 규칙대로 취소(`UCXPlayerLifeComponent::Kill`) |
| 일시정지 | 퍼즐 진행·제한 시간·쿨타임·그로기 시간이 모두 월드 Tick/월드 시각 기준 → ESC 메뉴 동안 함께 멈춤 |

### 10.6 네트워킹(listen server)

- 퍼즐은 여동생을 조작하는 머신에서 로컬로 진행(입력 반응성). 성공하면 권위 측이면 직접, 원격 클라이언트면 `USisterHackComponent::Server_ApplyEnemyHack`(Reliable)로 서버에 보고 → 서버가 **생존·대상 해킹 가능·거리(해킹 거리 + 300cm 여유)·서버 기준 쿨타임**을 재검증한 뒤 `ICXHackTarget::ApplyHackSuccess` → `ASpiderBot::ApplyHackStun`.
- 거미: `State`(OnRep — 연출) + `StunEndTime`(서버 월드 시각) 복제. HUD 카운트다운은 `GameState::GetServerWorldTimeSeconds` 기준이라 모든 머신이 같은 남은 시간을 그린다.
- 한계(포트폴리오 범위): 서버는 퍼즐 입력 자체를 검증하지 않는다(성공 보고 + 상태 재검증만) — 여동생 기획서 7장의 "최소한 서버가 최종 승인" 원칙까지만.
