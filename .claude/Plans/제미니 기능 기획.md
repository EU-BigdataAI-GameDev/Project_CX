# 제미니 기능 기획 (v1.2, 2026-11-07)

> v1.1: 확인 필요 Q1~Q13 사용자 결정 반영(7절), 추가 기능 제안(10절).
> v1.2: 추가 기능 3종 채택 — 미끼 `Decoy`, 빠른 재부팅 `QuickReboot`, 보호막 `Shield`(2-7~2-9). 길 안내·정찰 스캔은 제외.

플레이어가 채팅(키보드) 또는 음성(패드 Y)으로 부탁하면 제미니가 **대사를 말하면서 실제 게임 효과를 실행**하는 기능 9종.
요청 원문: `.claude/mds/13. 제미니 기능 목록 기획 요청.md`. 현재 시스템(as-built): `.claude/Plans/제미니 AI봇 기획.md`, 서버 명세 `Docs/Jemini/02_요구사항_명세서.md`.

> 이 문서는 기획만 한다. 구현은 별도 지시 후 진행.

## 0. 흐름 요약 (기존 구조 그대로)

```
플레이어 입력 → ACXJeminiDrone::SubmitText/SubmitVoice (서버=리슨 호스트)
  → GatherState()로 게임 상태 수집 → FastAPI /command(/voice)
  → Gemini가 함수 1개 선택(강제 모드 ANY, 인자 dialogue + heard)
  → validator.py가 조건·배터리 검사 → status ok / rejected / chat / fallback
  → UE HandleResponse → (ok) ExecuteCommand → 드론 연출 + 게임 효과, 대사 말풍선
```

바뀌는 것: 함수 3개 → **10개**(기능 9 + Chat), 상태 필드 추가(적·체력·버프), 거절 사유 추가, UE 실행 함수 추가.

| (명령 아님) | `Chat` (기존) | 0 | 잡담·질문·되묻기·불가 요청 거절 | "넌 누구야?", "안녕" | "저는 제미니예요! 탈출을 도울게요." |

공통 규칙
- 함수는 **한 턴에 1개**만 호출(강제 모드 ANY 유지). 대사는 1~2문장, 60자 이내, 해요체.
- 실행 여부·배터리는 **서버 validator가 최종 결정**. LLM 대사는 ok일 때만 쓰고, 거절이면 항상 사유별 기본 대사.
- 게임 권위는 리슨 서버(호스트). 효과는 서버에서 적용 → 복제.
- **배터리는 효과가 실제로 실행됐을 때만 차감**(응답과 실행 사이 대상이 사라지면 차감 없음, 5-4절).
- **드론이 작업 중이면 새 요청 불가**(HUD `JEMINI BUSY`, 5-3절).
- **배터리 20% 이하**: HUD에 `LOW BATTERY` 경고, 제미니 대사에 배터리 부족 언급(5-6절). 일부러 남겨 두는 예약 배터리는 없다.

## 구현 결과 (as-built)

### UE (2026-11-07)

전부 C++(WBP·BP·새 에셋·새 플러그인 없음). 이펙트는 엔진 구체·원통 + 기존 `M_Drone_ThrusterBeam`(가산), 소리는 기존 SFX 재사용.

| 기능 | 실행(클래스·함수) | 차감 시점 |
|---|---|---|
| 재장전 | `FlyToReload` → `FinishReloadFlight` → `UBrotherCombatComponent::RequestJeminiReload` | 장전 시작 |
| 단말기 A | 여동생 퍼즐 `terminal` → `USisterHackComponent::BeginJeminiAssist(3초)`, 드론 `HackAssist`가 단말기 상태 감시 | 3초 대행으로 HACKED(직접 풀거나 취소하면 차감 없음) |
| 단말기 B | `FindNextLockedTerminal`(TerminalName 번호 → 없으면 +Y 순) → `TerminalHack` 비행 → `SetInProgress(true)`+빔 3초 → `MarkHacked` | MarkHacked |
| 적 해킹 | 여동생 화살표 중이면 `BeginJeminiAssist(0.1)`(기존 Resolve 경로, 0.6초 안 그로기 안 되면 드론이 직접 `ApplyHackSuccess`) / 아니면 `QueryEnemies().NearestHackable`에 즉시 `ApplyHackSuccess`. 드론 0.5초 대시 + 0.5초 빔 | 그로기 적용 |

공통
- `HandleResponse`는 배터리를 바꾸지 않고 `PendingBatteryAfter`에 보관 → 효과 지점에서 `ChargePending`. 응답 시점·실행 직전에 대상이 없으면 `FailTargetLost`("앗, 놓쳤어요! 배터리는 아껴 둘게요.", status rejected, 차감 없음).
- 작업 중(`Action != Idle`, 복귀 `Returning` 포함) + 요청 대기 중 → `CanAcceptRequest`/`IsBusy` 거절, HUD `JEMINI BUSY`. 보호막은 비행 중만 BUSY.
- `GatherState(Speaker)`: 명세 v2 필드 전부. 적 수는 `QueryEnemies`(ICXHackTarget, 살아 있는 플레이어 15m) — 실행 대상과 같은 함수.
- 쓰러진 사람도 말하기: `UCXJeminiInputComponent`가 전용 `UEnhancedInputComponent`를 컨트롤러 입력 스택에 올림(사망 중 폰 입력 꺼져도 Enter/Y 동작), 사망 시 녹음 취소·채팅 닫기 제거. 게임 오버·클리어·이동 중만 드론이 거절.
- 응답 `command.target` 파싱(`puzzle_type` 제거), 옛 `HackAssist` 등 모르는 명령은 무시(차감 없음).
- HUD: 드론 상태 문구 9종 + `DECOY ns`/`RETURNING`, 배터리 ≤20 `LOW BATTERY` 깜빡임(두 칸), 대사 `
`마다 다음 말풍선(줄당 3초, 마지막 5초), 오빠 `DMG x2 ns` + 탄 눈금 주황, 체력 바 아래 `SHIELD ns`, 회복 `+N` 1초, 쓰러진 칸 `JEMINI REBOOTING...`, 쓰러진 칸에도 입력 상태 표시.
- ini `[/Script/Project_CX.CXJeminiDrone]`: `AssistTimeTerminal=3`, `EnemySearchRange`, `HealAmount`, `DamageBoostDuration`, `DamageBoostMultiplier`, `DecoyDuration`, `ShieldDuration`, `RebootBeamTime`(`AssistTimeEnemy` 삭제).
- 맵 이동 충전(2026-11-07 사용자 요청): `ALocalCoopGameMode::ExecuteTravel`에서 `UCXGameInstance::JeminiBattery` +30(최대 100). 이어하기·RETRY는 세이브 값 그대로.
- 한도 초과 mock 전환(2026-11-07): 서버는 모든 모델이 429면 `RateLimitError` → 텍스트 요청을 `mock_call`로 처리하고 응답 `mock: true`(`MOCK_ON_RATE_LIMIT`, 기본 켬; 음성은 fallback). UE `FCXJeminiResponse::bMock` → 드론 복제 `bServerMock`(fallback이면 유지) → HUD 배터리 패널 제목 옆 `[MOCK]`.
- 디버그: `CXJeminiCmd <이름> [target]`(LLM 없이 실행), `CXJeminiSister <문장>`, `CXJeminiSelfTest [1]`(9종 순서 실행 + 로그).
