### 5-2. 적 대상 선택

- 후보: 월드의 `ICXHackTarget` 구현 액터(현재 `ASpiderBot`). 플레이어(`CombatCharacter`)·더미·상자 같은 `ICombatDamageable`만 구현한 액터는 제외.
- 살아 있음 = `ASpiderBot::IsDead() == false`(일반화: `UCXHealthComponent::IsActorDead`). 해킹 가능 = `IsHackTargetAvailable()`.
- 범위: **살아 있는 플레이어 중 누군가로부터 15m(`EnemySearchRange` 1500cm = 거미 `DetectRadius`) 이내**.
- 우선순위: 살아 있는 플레이어와의 거리(두 사람 중 더 가까운 쪽 기준)가 가장 짧은 적 = 가장 위협적인 적.
- 같은 함수로 상태 수집(`enemy_*_count`)과 실행 대상 결정을 하므로 서버와 UE 판단이 일치한다.

### 5-3. 드론 행동 요약

| 기능 | 드론 | 효과 시점 | 다른 요청 |
|---|---|---|---|
| 재장전 | 오빠에게 비행(≤2초) | 도착 시 장전 2초 | 차단 |
| 단말기 해킹 | A: 여동생 곁 / B: 단말기로 비행 | 3초 후 | 차단 |
| 적 해킹 | 대상으로 대시 + 빔 | 응답 즉시 | 연출 1초 차단 |
| 적 공격 | 적 머리 위로 비행 → 펄스 → 처치 확인 → 플레이어에게 복귀 | 도착 시 | 복귀까지 차단 |
| 공격력 강화 | 오빠에게 비행(≤1초) | 도착 시 30초 시작/연장 | 차단 |
| 체력 회복 | 두 사람 중간 | 응답 즉시 | 연출 1초 차단 |
| 미끼 | 플레이어 반대쪽 공중으로 비행 → 점멸 5초 → 복귀 | 도착 시 5초 | 5초 + 복귀까지 차단 |
| 빠른 재부팅 | 파트너 곁으로 비행 → 빔 1초 | 연출 끝에 부활 | 차단 |
| 보호막 | 대상에게 비행(≤1초) | 도착 시 5초 | 비행 중만 차단 |

**작업 중 요청 불가**: `CanAcceptRequest()`는 요청 대기 중이거나 `Action != Idle`이면 거절(지금은 `FlyToReload`만). 입력하면 HUD `JEMINI BUSY`(기존 표시 재사용), 대사·서버 요청 없음.

### 5-4. 응답과 실행 사이 상태 변화

서버 응답까지 약 1초 사이에 적이 죽거나 퍼즐이 풀릴 수 있다. **배터리는 효과가 실제로 실행된 순간에만 차감**한다.
- `HandleResponse`는 `SetBattery`를 바로 하지 않고 `PendingBatteryAfter`에 보관 → 효과가 실행되는 지점(재장전 시작, 3초 해킹 완료, 그로기 적용, 펄스 명중, 강화 시작, 회복 적용)에서 반영.
- 실행 직전 조건을 다시 보고 대상이 없으면(적 사망, 단말기가 이미 열림, 오빠 사망 등) 차감 없이 클라이언트 대사("앗, 놓쳤어요!", reason `TARGET_LOST`)로 바꾸고 복귀.

### 5-6. 배터리 부족 알림 (20% 이하)

- HUD: 배터리 게이지 경고색(기존) + 게이지 아래 `LOW BATTERY` 깜빡임 문구, 두 칸 모두.
- 대사: 서버 시스템 지시문으로 LLM이 배터리 부족을 덧붙이게 하고, **보험으로** 서버가 `battery_after <= 20`인데 대사에 "배터리/전력"이 없으면 짧은 꼬리말("전력이 얼마 안 남았어요.")을 붙인다(60자 넘으면 꼬리말만 다음 말풍선으로).
- 표정: 기존대로 20% 이하면 기본 표정이 슬픔.
- 예약 배터리 없음: 배터리가 남아 있으면 어떤 기능이든 쓸 수 있다(재장전용으로 남겨 두지 않음).

### 5-5. 네트워킹

- 모든 효과는 서버(호스트) 권위: `ApplyHackSuccess`, `ApplyDamage`, `Heal`, `ApplyDamageBoost`는 서버에서만.
- 복제: 드론 `Action`·대사·배터리(기존), 오빠 `DamageBoostEndTime`, 체력 `CurrentHealth`(기존), 거미 상태(기존).
- 원격 여동생의 퍼즐 세션은 그 머신에서 진행 → 기존 `Client_BeginJeminiAssist` 경로 재사용.
- 피해 배율은 `Server_Fire` → `SpawnBullet`(서버)에서만 적용하므로 클라이언트 위조 여지 없음.
