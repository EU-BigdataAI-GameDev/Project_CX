# 공격 시스템 — 자동 조준 사격 기획 (레일건 발사 로직 구체화)

- 문서 버전: v1.0 (2026-09-14)
- 대상: 오빠 캐릭터 담당 개발자
- 목적: `.claude/Plans/오빠 캐릭터 기획.md`(이하 "오빠 기획서") 2장에서 개념만 잡아둔 레일건 발사 로직을, **우클릭 자동 조준 + 좌클릭 발사 + 총알(투사체) 스폰**이라는 구체적인 요구사항에 맞춰 갱신하는 후속 설계 문서다.
- 선행 문서: 오빠 기획서(이하 인용 시 "오빠 기획서 N장"). 본 문서는 오빠 기획서 2장의 일부 설계 결정을 **명시적으로 대체(override)**한다 — 대체 근거는 0장 참고. 오빠 기획서의 3장(회피), 5장(폴더 구조), 나머지 조항은 그대로 유효하다.

---

## 0. 오빠 기획서와의 정합성 검토 (충돌 및 변경 사항)

새 요구사항을 오빠 기획서와 대조한 결과, 아래 4가지 지점에서 기존 설계와 충돌하거나 갱신이 필요하다. 하나씩 짚고 넘어간다.

### 0.1 우클릭 입력 충돌 (해결됨)

오빠 기획서 3.1은 원래 **우클릭을 회피(Dodge) 키로도 배정**했었다(좌쉬프트와 함께 동일한 `IA_Dodge`에 매핑). 이번 요구사항은 "우클릭으로 가장 가까운 적 자동 조준"을 요구하므로 우클릭 하나를 두 기능(회피/조준)에 동시에 쓸 수 없었다.

**해결 완료**: 오빠 기획서를 v1.1로 갱신해 **회피 키를 좌쉬프트 단독**으로 축소했다. 우클릭은 이제 조준 전용이다.

### 0.2 발사 판정 방식 변경: 히트스캔 → 실제 투사체

오빠 기획서 2.3은 "레이저 컨셉과의 정합, 네트워킹 단순성" 등을 근거로 **히트스캔(라인 트레이스)**을 채택했었다. 그러나 이번 요구사항은 "오빠 캐릭터 앞에서 총알이 나가도록"을 명시했고, 우클릭 자동 조준과 결합하면 **눈에 보이는 총알이 조준 방향으로 날아가는 그림**이 자연스럽다. 따라서 본 문서에서는 **실제 투사체 액터(총알)** 방식으로 대체한다.

- 트레이드오프: 오빠 기획서 2.3의 4번 근거(네트워킹 단순성 — 히트스캔은 트레이스 결과만 복제하면 되지만 투사체는 스폰/이동을 복제해야 함)가 그대로 비용으로 남는다. 다만 UE의 `UProjectileMovementComponent` + `Replicated` 액터 스폰은 표준 패턴이라 포트폴리오 스코프에서 감당 가능한 수준으로 판단한다(8장 참고).

### 0.3 발사 동기화 방식 변경: AnimNotify 제거

오빠 기획서 2.3 말미는 "발사 프레임에서 `UAnimNotify_FireRailgun`이 발사를 트리거"하는 방식을 제안했었다. 그런데 **현재 발사 모션 자체가 없다**(요구사항 명시). 따라서 본 문서에서는 AnimNotify 동기화를 걷어내고, **입력 이벤트(좌클릭 Started)에서 즉시 발사 함수를 호출**하는 방식으로 대체한다. 추후 발사 모션이 추가되면 그때 AnimNotify 방식으로 전환하는 것을 권장(8.1 참고).

### 0.4 데미지 수치 변경: 1.0 → 5.0

오빠 기획서 2.3은 "`MeleeDamage = 1.0f`(MaxHP 5.0 기준)와 동일 스케일 유지"를 기본값으로 제안했었다. 이번 요구사항은 **총알 1발 데미지 5**를 명시적으로 지정했으므로 이를 그대로 채택한다. 다만 이 값은 오빠 기획서 2.3의 스케일 가정(적 HP가 대략 한 자릿수라는 전제)과 어긋날 수 있으므로, **적 HP 밸런스는 별도로 재검토가 필요**하다(오빠 기획서 9.1 체크리스트와 연동, 본 문서 10장에도 재기재).

## 1. 개요

좌클릭(발사)과 우클릭(조준)을 결합한 **자동 조준 사격**을 구현한다. 마우스로 직접 에이밍하지 않고, "가장 가까운 적"을 자동으로 찾아 그 방향으로 총알을 날리는 방식이다 — 사이드뷰 스크롤러라는 카메라 특성상(레벨 기획서 3.3) 정밀 마우스 에이밍보다 자동 조준이 조작감/장르 궁합 양쪽에서 더 적합하다.

| 입력 | 동작 |
|---|---|
| 우클릭 (Hold) | 가장 가까운 적을 자동 조준 (캐릭터가 타겟 방향으로 회전) |
| 좌클릭 (Started) | 발사. 조준 중이 아니어도 그 순간 가장 가까운 적을 즉시 찾아 그 방향으로 발사 |

---

## 2. 조준 시스템 (우클릭)

### 2.1 입력

- 신규 제안 `IA_Aim` (우클릭, `ETriggerEvent::Started`로 조준 시작, `ETriggerEvent::Completed`로 조준 해제 — 홀드 방식).

### 2.2 타겟 탐색 로직: `FindNearestTarget()`

오빠 기획서 2.3이 정한 사거리(3000cm)를 그대로 재사용해 탐색 반경으로 삼는다(사거리 밖의 적을 조준해봐야 발사해도 안 맞으므로 일관성 유지).

1. `UGameplayStatics::GetAllActorsWithInterface(this, UCombatDamageable::StaticClass(), ...)` 로 `ICombatDamageable`을 구현한 액터(적) 전체를 수집한다 — 오빠 기획서 0장에서 확인했듯 `ACombatEnemy`가 이 인터페이스를 구현하므로 신규 인터페이스 없이 재사용 가능하다.
2. 사거리(3000cm) 밖의 적은 제외.
3. **설계 결정(기본값)**: 캐릭터 정면 기준 전방 120° 원뿔 밖의 적은 제외한다(원 요구사항에 없는 추가 조건이나, 등 뒤의 적까지 조준되면 캐릭터가 부자연스럽게 홱 돌아버려 사이드뷰 카메라에서 어색하다 — 과설계라기보다 조작감 방어용 최소 조건).
4. **설계 결정(기본값)**: 벽 뒤에 가려진 적은 라인 트레이스(LOS 체크)로 제외한다(레벨 기획서 3.6의 "플레이어가 인지할 수 있어야 한다"는 원칙과 동일 취지 — 안 보이는 적이 갑자기 맞으면 억울함을 유발).
5. 남은 후보 중 **직선 거리 최소값**을 최종 타겟으로 선정.
6. 후보가 없으면 `nullptr` 반환(3.2의 폴백 로직으로 이어짐).

### 2.3 조준 상태

- `bIsAiming`(bool), `CurrentTarget`(`AActor*`, `ICombatDamageable` 구현 액터) 두 필드로 관리한다.
- 우클릭 Hold 시작 → `FindNearestTarget()` 호출 → 성공 시 `bIsAiming = true`, `CurrentTarget` 세팅. 실패 시(주변에 적 없음) `bIsAiming`은 false로 유지(허공 조준 없음).
- 조준 중에는 매 틱(`Tick` 또는 `Blueprint Update Animation`과 별개로 캐릭터 이동 로직 쪽에서) 캐릭터의 Yaw 회전을 `CurrentTarget` 방향으로 `RInterpTo`로 보간한다 — 순간 스냅이 아니라 자연스럽게 돌아가는 편이 사이드뷰 캐릭터 연출과 어울린다.
- 우클릭을 떼면 `bIsAiming = false`, `CurrentTarget = nullptr`.
- **엣지 케이스**: 조준 중 `CurrentTarget`이 사망하거나 사거리를 벗어나면, 매 틱 유효성 검사 후 즉시 `FindNearestTarget()`을 재호출해 다음으로 가까운 적으로 자동 전환한다(타겟 없으면 `bIsAiming = false`로 해제).

## 3. 발사 시스템 (좌클릭)

### 3.1 입력

- 신규 제안 `IA_Fire` (좌클릭). 오빠 기획서 2.1의 관습(`ETriggerEvent::Started`, 1클릭 = 1발, 홀드 연사 없음)을 그대로 채택한다.

### 3.2 발사 시 조준 로직

```
좌클릭(Started)
  ├─ 탄약/장전 가드: bIsReloading == true 이면 무시 (오빠 기획서 2.5 그대로)
  ├─ bIsAiming == true 이면
  │     └─ CurrentTarget 방향으로 발사
  └─ bIsAiming == false 이면
        ├─ FindNearestTarget() 즉시 실행 (2.2와 동일 로직, 조준 상태로 전환하지는 않음 — 이번 한 발만 그 방향으로 나감)
        ├─ 타겟 발견 시 → 그 방향으로 발사
        └─ 타겟 없음 시 → 캐릭터 정면 방향(GetActorForwardVector())으로 발사 (폴백)
```

이 구조가 "조준 상태가 아니어도 좌클릭 시 자동으로 조준 상태가 되면서 총알을 발사"라는 요구사항을 충족한다 — 다만 **좌클릭만으로 조준 상태(`bIsAiming`)에 진입시키지는 않는다**(설계 결정: 그 한 발만 자동 조준 방향으로 나가고, 캐릭터가 계속 그 타겟을 보고 서 있게 만들지는 않음 — 우클릭 없이 좌클릭만 연타할 때 캐릭터가 계속 홱홱 돌아가는 부자연스러움 방지). 조준 상태를 유지하고 싶다면 우클릭을 누른 채로 좌클릭을 눌러야 한다.

### 3.3 탄약/장전

오빠 기획서 2.2, 2.5의 탄창(30발)/자동 장전(2초)/장전 중 발사 무시 로직은 **변경 없이 그대로 유지**한다.

## 4. 총알(투사체) 설계

### 4.1 신규 액터: `ABrotherBullet`

- `AActor` 상속(무기 메시가 아직 없으므로 `ACharacter`나 무기 클래스에 종속시키지 않고 독립 액터로 설계).
- 구성: 충돌용 `USphereComponent`(작은 반경, 예 5cm) + `UProjectileMovementComponent`(직선 이동) + 비주얼(스태틱 메시 또는 나이아가라 이펙트 — 아트 리소스 확정 전이므로 우선 간단한 구체 메시나 트레일 이펙트로 대체 가능).
- `Source/Project_CX/Variant_BrotherCombat/Gameplay/BrotherBullet.h/.cpp`에 배치(오빠 기획서 5장 폴더 구조의 `Gameplay/` 서브폴더를 실제로 채우는 첫 클래스가 된다).

### 4.2 스폰 위치 ("캐릭터 앞")

무기 메시/소켓이 없으므로 총구 소켓 기준 스폰이 불가능하다. 대신 **캐릭터 기준 상대 오프셋**으로 스폰 지점을 계산한다.

- **설계 결정(기본값, 추후 조정)**: `GetActorLocation() + GetActorForwardVector() * 60.0f + FVector(0, 0, 60.0f)` 정도(캐릭터 정면 60cm, 캡슐 중심보다 살짝 위 — 가슴 높이 근사). 정확한 Z 오프셋은 `Brother_SK`의 실제 캡슐 하프하이트 확인 후 미세 조정 필요.
- 발사 방향은 3.2에서 결정된 방향(타겟 방향 또는 정면 폴백)이며, 스폰 시점의 `Rotator`를 이 방향으로 맞춰 `UProjectileMovementComponent::Velocity`에 반영한다.

### 4.3 이동/사거리/소멸

- 속도: **설계 결정(기본값)** 3000 cm/s. 오빠 기획서 2.3의 사거리 3000cm를 그대로 가져와, 수명(`InitialLifeSpan`) 1초로 설정하면 사거리 3000cm에서 자동 소멸하는 셈이라 별도의 거리 체크 로직이 필요 없다(과설계 방지).
- 관통 없음(1히트 후 즉시 파괴)을 기본값으로 한다 — 원 요구사항에 관통 언급이 없으므로 가장 단순한 형태를 채택.

### 4.4 충돌 및 데미지 적용

- `OnComponentHit` 또는 `OnComponentBeginOverlap`에서 `Cast<ICombatDamageable>(OtherActor)` → 성공 시 `ApplyDamage(5.0f, ...)` 호출(오빠 기획서 0장에서 확인한 `ICombatDamageable`을 그대로 재사용, 신규 인터페이스 불필요).
- 데미지 적용 후 총알은 즉시 `Destroy()`.
- 지형(월드 스태틱 메시 등 `ICombatDamageable` 미구현 액터)에 맞아도 즉시 소멸시켜, 총알이 무한히 날아다니지 않게 한다.

## 5. 데미지

- 총알 1발 데미지: **5.0 (고정값, 요구사항 지정)**.
- 0.4에서 짚었듯 오빠 기획서 2.3의 데미지 스케일 가정(1.0, MaxHP 5.0 기준)과 5배 차이가 나므로, **적 HP 수치를 이 값에 맞춰 재검토**해야 한다(예: 적 HP가 5~10 수준이면 1~2발에 즉사하는 셈 — 밸런스 의도라면 무방하나 확인 필요, 10장 체크리스트에도 재기재).

## 7. 네트워킹 고려사항 (리슨 서버 기준)

오빠 기획서 6장과 동일한 권위 분리 원칙(입력 반응성은 로컬, 데미지 확정은 서버)을 따른다.

- **조준(`bIsAiming`, `CurrentTarget`)**: 시각적 회전일 뿐 데미지에 직접 관여하지 않으므로, 로컬에서 즉시 처리하고 `Replicated`로 다른 클라이언트에게도 회전이 보이게만 동기화한다(서버 재검증 불필요 — 오빠 기획서 6장의 "조작감 우선" 기조와 동일).
- **발사/총알 스폰**: 서버(호스트)가 권위를 가진다. 클라이언트 `Server_RequestFire()` RPC → 서버가 `CurrentAmmo > 0 && !bIsReloading` 재검증 후 `ABrotherBullet`을 서버에서 스폰(`Replicated` 액터, `bReplicates = true`) → 엔진이 자동으로 모든 클라이언트에 복제. 데미지 적용(`ApplyDamage`)은 서버의 충돌 판정에서만 발생시킨다.
- **호스트 자신이 오빠를 조작하는 경우**엔 클라이언트=서버라 지연이 없다. 원격 클라이언트가 오빠를 조작할 때만 RTT만큼 발사 체감이 늦어질 수 있는데, 총알이 실제로 눈에 보이며 날아가는 연출이라 히트스캔보다는 지연이 덜 어색하게 느껴진다는 것도 이번 설계 변경(0.2)의 부수적 장점이다.

## 8. 향후 확장 여지

### 8.1 발사 모션 추가 시

발사 모션(몽타주)이 나중에 추가되면, 0.3에서 걷어냈던 `UAnimNotify_FireRailgun` 방식(오빠 기획서 2.3)으로 전환해 발사 타이밍을 모션 프레임에 동기화하는 것을 권장한다. 지금은 입력 즉시 발사로 충분하다.

### 8.2 조준 보조 강화

지금은 "가장 가까운 적"만 기준으로 삼는다. 추후 화면상 좌우 방향(진행 방향 우선) 가중치를 추가해 "가장 가까운"이 아니라 "가장 자연스러운" 타겟을 고르는 식으로 고도화할 수 있다(원 요구사항 범위 밖).

## 9. 구현 노트 (2026-09-14 실제 작업 내역)

문서 설계를 그대로 코드로 옮기면서 한 가지 중요한 이탈이 있었다 — 아래 기록한다.

### 9.1 `BrotherCharacter` 신규 클래스 대신 `UBrotherCombatComponent`(액터 컴포넌트) 채택

오빠 기획서 5장은 `ABrotherCharacter : ASideScrollingCharacter`로 재설계할 것을 제안했지만, **실제 `BP_Brother`는 현재 순정 `ACharacter`를 부모로 하는 블루프린트**이고(코드베이스 조사로 확인), 이번 세션에서 이미 Idle/Run/Jump 애니메이션 스테이트머신을 `BP_Brother`의 Event Graph 안에서 직접 손으로 연결해둔 상태다. 지금 시점에 부모 클래스를 통째로 갈아엎으면(Reparent) 방금 완성한 점프 로직이 깨질 위험이 크다.

**결정**: 새 캐릭터 클래스를 만들지 않고, **`UBrotherCombatComponent`(`UActorComponent`)를 `BP_Brother`에 컴포넌트로 추가**하는 방식으로 구현했다. 조준/발사/탄약/장전 로직 전부가 이 컴포넌트 안에 있다. 입력 바인딩도 C++에서 하지 않고, 기존 `IA_Jump`를 `BP_Brother` Event Graph에서 직접 연결한 것과 동일한 방식으로 `IA_Fire`/`IA_Aim` 이벤트 노드를 이 컴포넌트의 `Fire()`/`StartAim()`/`StopAim()`에 연결하는 구조다 — 안전성과 일관성을 위한 선택이며, 추후 `BrotherCharacter`로 정식 이관 시 이 컴포넌트를 그대로 멤버로 들고 있거나 로직을 흡수하면 된다.

### 9.2 작성된 파일

- `Source/Project_CX/Variant_BrotherCombat/BrotherCombatComponent.h/.cpp` — 조준/발사/탄약/장전, `FindNearestTarget()`(사거리 3000cm + 전방 120° + LOS), 서버 권위 발사(`Server_Fire` RPC).
- `Source/Project_CX/Variant_BrotherCombat/Gameplay/BrotherBullet.h/.cpp` — 총알 액터. `USphereComponent` + `UProjectileMovementComponent`, `ICombatDamageable` 대상에게만 서버에서 데미지 적용 후 소멸.
- `Project_CX.Build.cs`에 `Project_CX/Variant_BrotherCombat`, `Project_CX/Variant_BrotherCombat/Gameplay` 인클루드 경로 추가.

### 9.3 에디터에서 남은 작업 (코드만으로는 안 되는 부분)

1. **컴파일**: 에디터가 이미 켜져 있어(Live Coding 프로젝트) 외부 빌드가 락에 걸린다. 에디터 안에서 **Ctrl+Alt+F11**(Live Coding 컴파일)로 빌드해야 한다.
2. `BP_Brother`를 열고 **Add Component → Brother Combat**으로 컴포넌트 추가.
3. 추가한 컴포넌트의 Details 패널에서 `Bullet Class`에 `BP_BrotherBullet`(아래 4번에서 생성) 지정.
4. `ABrotherBullet`을 부모로 하는 블루프린트 `BP_BrotherBullet` 생성 후, `Mesh Comp`에 임시 비주얼(스태틱 메시 구체 등) 지정 — C++ 쪽은 메시를 비워둔 상태라 그대로면 안 보임.
5. `Content/Input/Actions/`에 `IA_Fire`, `IA_Aim` 입력 액션 신규 생성(Value Type: Digital(bool)) → 현재 `BP_Brother`가 쓰는 Input Mapping Context에 좌클릭/우클릭으로 매핑.
6. `BP_Brother` Event Graph에서 `IA_Jump`를 연결했던 것과 동일한 방식으로:
   - `IA_Fire`(Started) → `Fire`
   - `IA_Aim`(Started) → `Start Aim`
   - `IA_Aim`(Completed) → `Stop Aim`
7. 데미지 테스트용 타겟이 아직 없다 — 거미로봇(SpiderBot) 게임플레이 블루프린트가 미구현 상태다. 우선 `Variant_Combat/Gameplay/CombatDummy`(이미 `ICombatDamageable` 구현)를 레벨에 배치해 총알 명중/데미지를 테스트하는 것을 권장한다.

## 10. 완료 체크리스트

### 10.1 조준

- [ ] 우클릭을 누르고 있는 동안 가장 가까운 적이 자동으로 조준되고, 캐릭터가 그 방향으로 서서히 회전한다.
- [ ] 사거리(3000cm) 밖이나 전방 120° 밖의 적은 조준 대상에서 제외된다.
- [ ] 벽에 가려 안 보이는 적은 조준 대상에서 제외된다(LOS 체크).
- [ ] 조준 중 타겟이 죽거나 범위를 벗어나면 다음으로 가까운 적으로 자동 전환되거나, 없으면 조준이 해제된다.
- [ ] 우클릭을 떼면 조준이 해제된다.

### 10.2 발사

- [ ] 조준 중 좌클릭 시 현재 타겟 방향으로 총알이 발사된다.
- [x] 조준 중이 아닐 때 좌클릭 시, 그 순간 가장 가까운 적을 찾아 그 방향으로 발사된다. (2026-09-19 실기 확인)
- [x] 주변에 적이 전혀 없을 때 좌클릭하면 캐릭터 정면 방향으로 발사된다(폴백, 발사가 씹히지 않음). (2026-09-19 실기 확인)
- [ ] 좌클릭 1회당 총알 1발만 나가며(홀드 연사 없음), 탄약/장전 로직(30발, 2초 자동 장전)이 오빠 기획서 그대로 동작한다.

### 10.3 총알

- [x] 발사 모션/무기 메시 변경 없이, 캐릭터 앞 지점에서 총알 액터가 스폰되어 실제로 날아간다. (2026-09-19 실기 확인)
- [ ] 총알이 `ICombatDamageable` 구현 액터(적)에 맞으면 5의 데미지를 입히고 즉시 소멸한다.
- [ ] 총알이 사거리(3000cm 상당) 도달 또는 지형 충돌 시 자동으로 소멸한다(관통 없음).

### 10.4 입력 / 정합성

- [x] `IA_Fire`, `IA_Aim`이 입력 매핑에 연결되어 있다 — 구현 시 별도 `IMC_BrotherCombat` 대신 기존 `IMC_Default`에 좌클릭/우클릭으로 추가(9.3 참고).

- [ ] 총알 스폰이 서버 권위로 처리되고 클라이언트에 자동 복제된다.
