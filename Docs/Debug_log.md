## #16 WARDEN에게 보낸 채팅이 가끔 전달되지 않는 것처럼 보임 — 🔧 수정·빌드 완료(PIE 재확인 필요, 스페이스 씹힘은 원인 미확인)
- **수정 날짜**: 2026-11-13 (이슈 #25)
- **문제**: WARDEN에게 보낸 말이 가끔 전달되지 않는 것 같음. 서버 로그에는 받은 요청이 모두 정상이라 게임 쪽에서 조용히 버려지는 것으로 보임.
- **디버깅**:
  - `ACXWardenTerminal::BeginAttempt`가 요청 중(`bRequestPending`, 구글 응답이 10초 넘게 걸릴 때)이면 아무 표시 없이 `false`를 돌려줌. `UCXJeminiInputComponent::CanTalkNow`도 같은 이유로 채팅창을 아예 열지 않아 "Enter가 안 먹는" 것처럼 보임(HUD는 1.5초 `WARDEN BUSY`만).
  - 3초 간격에 걸리면 대사만 나오고 입력한 문장은 사라짐.
  - 대화창 인용은 46자에서 `…`로 잘리는데 전송은 200자까지라 "일부만 전달된 것"처럼 보임.
  - 스페이스 뒤 글자 씹힘(한글 입력기 추정)은 재현하지 못했고 코드만으로 원인을 특정할 수 없었다. 채팅창은 `ClearKeyboardFocusOnCommit(false)` + 수동 키보드 포커스(GameOnly)이고, 처리 안 된 키는 `OnKeyDown`이 삼킨다. 포커스를 훔치는 경로는 코드에서 찾지 못함.
- **수정**:
  - 분석 중에도 채팅창이 열린다. 분석 중·3초 간격 안에 제출한 텍스트는 서버(단말기)가 마지막 한 개를 보관하고(대화창에 "분석 중… 접수했습니다" / 간격 초 표시) 응답 1.5초 뒤 또는 간격이 풀리면 자동 전송. 해결되면 폐기. 음성은 보관하지 않고 안내(`WARDEN ANALYZING - WAIT`, 대화창 안내)만. 거절 사유(분석 중/간격/이미 해결)와 글자 수를 `LogCXWardenTerminal`에 남김.
  - 대화창 인용 2줄·약 90자, 채팅창 `n/200`(넘으면 주황색), WARDEN용 라벨/힌트.
  - 진단 로그(`LogCXJeminiInput`): `ChatBox text changed`(길이·끝 3글자 코드·키보드 포커스 위젯), `ChatBox key down`(키 이름·문자코드), `ChatBox focus`(포커스 이동 전→후·원인), `ChatBox commit/cancel`, `Chat submit`. 동작은 그대로.
- **확인**: 에디터 빌드 성공. `-game -nullrhi` + `CXWardenSay` 2개를 같은 틱에 연속 보냄 → 두 번째가 `input queued (analyzing)` + 대화창 상태 `busy`, 첫 응답 후 `queued text sent`로 이어서 전송됨(서버 실제 응답 2건).
- **다음 재현 시**: 로그에서 `ChatBox text changed` 줄이 스페이스(0020) 뒤로 이어지는지, `ChatBox focus`가 입력창 밖으로 옮겨 갔는지, `key down`이 `ProcessKey` 등으로 오는지(IME 조합) 확인.

## #12 마이크를 쓴 뒤 PIE를 끄면 에디터 전체가 크래시 — 🔧 수정·빌드 완료(실제 마이크 재확인 필요)
- **수정 날짜**: 2026-11-07
- **문제**: PIE에서 Y로 녹음(헤드셋 WASAPI)한 뒤 PIE를 끄면 `EXCEPTION_ACCESS_VIOLATION reading 0xffffffffffffffff`. 콜스택: Core ← AudioCaptureWasapi ← AudioCaptureCore ← `FCXJeminiVoiceRecorder::~FCXJeminiVoiceRecorder` ← `UCXJeminiInputComponent` 소멸(GC). 직전 로그: `too short (0.00s), discarded`(`Saved/Crashes/UECC-...45EBE9C9..._0000`).
- **디버깅**: 엔진 `FAudioCaptureSynth` 멤버 순서가 `AudioCapture` → `CaptureCriticalSection` → `AudioCaptureData`라 소멸 때 버퍼·락이 캡처 객체보다 먼저 파괴됨. 우리 `Stop()`은 `StopCapturing()`(플래그만)만 해서 **WASAPI 스트림·캡처 스레드가 계속 돌았고**, `Cancel()`은 녹음 중일 때만 닫음 → 짧은 녹음 뒤에도 스트림이 열린 채 GC 소멸자까지 감 → 파괴 중 캡처 콜백/스레드 종료가 해제된 락·버퍼를 만짐.
- **수정**: `CXJeminiVoice` — `Stop()`/`Cancel()`/`Start()` 실패 시 항상 `AbortCapturing()`(AbortStream+CloseStream, 캡처 스레드 join)으로 스트림을 닫고(이중 닫기 안전: `IsStreamOpen` 확인), 새 `Shutdown()`이 스트림을 닫은 뒤 캡처 객체를 파괴. `UCXJeminiInputComponent::EndPlay`/`OnUnregister`가 `ShutdownVoice()`(녹음기 Shutdown + 테스트 피드·실시간 자막 정리 + 진행 중 `/stt/partial` HTTP 취소·콜백 해제). 소멸자는 안전망(남아 있으면 경고 후 닫기)만. 덤: 녹음이 끝나면 마이크가 바로 해제된다.
- **확인**: 빌드 성공. PIE 시작→녹음 시작→PIE 종료, 짧은 녹음→PIE 종료, 녹음→전송 직후 PIE 종료 각 2회 + 실시간 자막 요청 진행 중 PIE 종료 2회 → 크래시 없음. 단, 확인 시점에 헤드셋(siindoo-H1)이 끊겨 캡처 장치가 없었다(`no default capture device`) → **실제 마이크로 PIE 종료 재확인 필요**.
- **교훈**: 엔진 오디오 캡처 객체는 스트림을 명시적으로 닫은 뒤 파괴한다. UObject 소멸자(GC)에 네이티브 스레드 정리를 맡기지 않는다.

## #10 게임이 띄운 jemini-server.exe가 살아 있는데 응답이 없음 — ✅ 완료
- **수정 날짜**: 2026-11-06
- **문제**: 서버 자동 실행(`UCXJeminiServerSubsystem`)을 넣은 뒤 독립 실행(-game)에서 exe 프로세스는 떠 있는데 `/health`가 끝까지 타임아웃.
- **디버깅**: 셸에서 띄우면 정상, `Start-Process -WindowStyle Hidden`으로 띄우면 같은 증상 재현 → 창 없는 PyInstaller exe(`--noconsole`)는 `sys.stdout`/`stderr`가 `None`이라 uvicorn 로깅에서 예외 → PyInstaller의 오류 대화상자가 숨은 채 떠서 프로세스가 멈춤. 부수: exe 옆에 `.env`가 없으면 시스템 환경변수의 예전 키를 씀.
- **수정**: `Jemini/run_server.py`가 stdout/stderr가 없으면 exe 옆 `logs/server.log`로 돌림. `app/config.py`는 exe 옆 `.env`가 없으면 `Jemini/.env`(저장소에서 만든 exe)도 찾음.
- **확인**: 숨김 실행 즉시 `/health` 응답. 독립 실행 게임 → exe 자동 실행 → 실제 Gemini 재장전 응답 → 게임 정상 종료 시 서버도 종료. PIE도 시작 시 파이썬 서버 실행·종료 시 정리 확인.

## #9 새 Gemini 키를 넣어도 401(ACCESS_TOKEN_TYPE_UNSUPPORTED) — ✅ 완료
- **수정 날짜**: 2026-11-06
- **문제**: `Jemini/.env`에 키를 새로 발급해 넣어도 `401 API key not valid`가 그대로 남.
- **디버깅**: 키 값을 출력하지 않고 비교만 함 → Windows 시스템 환경변수에 예전 `GEMINI_API_KEY`가 있었고 `.env`와 값이 다름. `python-dotenv`의 `load_dotenv`는 기본적으로 이미 있는 환경변수를 덮어쓰지 않아 예전 키가 계속 쓰였음. (부수: `tools/list_models.py`가 임시 클라이언트로 목록을 넘기다 "client has been closed" 오류.)
- **수정**: `app/config.py`, `tools/list_models.py`에서 `load_dotenv(..., override=True)` — 프로젝트 `.env`가 우선. `list_models.py`는 클라이언트를 변수에 잡아 둠.
- **확인**: 모델 목록 조회 성공(`gemini-3.5-flash-lite`, `gemini-3.1-flash-lite` 사용 가능). 실제 Gemini로 텍스트 5종 + 음성 2종(Windows 한국어 TTS로 만든 WAV) 의도대로 동작, 텍스트 약 0.8~1.2초, 음성 약 1.6초.
- 같이 고친 것: 텍스트 입력에 `heard`가 채워짐 → 서버가 텍스트 요청이면 비움. 반말 섞임·Chat에서 재장전 약속 → 시스템 지시문에 "해요체 고정", "Chat에서 행동 약속 금지" 추가.

## #7 제미니 요청이 전부 연결 실패(NO_CONNECTION) — ✅ 완료
