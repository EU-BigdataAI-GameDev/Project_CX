# 제미니 고도화 설계 기록: "자연어 리모컨"에서 "협상하는 파트너"로

> 한국게임학회 GGC2026 제출용 정리. 작성 2026-11-12.
> 프로젝트: CAELUM:UNCHAINED — 사이버펑크 2인 로컬 협동 사이드 스크롤러(오빠 = 전투, 여동생 = 해킹), Unreal Engine 5.6 C++, 개발자 1인.
> 관련 문서: 기획 `.claude/Plans/제미니 고도화 기획 ver2.md`, 명세 `02_요구사항_명세서.md`, 퍼즐 설명 `WARDEN_설명.md`, 비교 실험 `비교실험_결과.md`.

## 1. 한 줄 요약

LLM 드론 "제미니"가 처음에는 **자연어를 함수 호출로 바꿔 주는 리모컨**에 그쳤다. 이를 **(1) 말을 지속되는 게임 규칙으로 컴파일하고, (2) 상황을 보고 작전을 제안하며, (3) 증거를 근거로 AI와 협상하는** 구조로 바꿨다. 모든 단계에서 **LLM은 해석과 대화를 맡고, 판정과 실행은 게임 코드가 맡는다.**

## 2. 고민: LLM이 필요한 이유가 약했다

### 2.1 출발 상태
- 제미니는 플레이어의 말을 받아 미리 만들어 둔 10개 스킬(재장전, 해킹, 미끼, 회복 등) 중 하나를 호출했다(Gemini 강제 함수 호출).
- 서버(FastAPI)가 배터리·상태를 검증하고, 게임이 효과를 실행한다. 한 번 말하면 한 번 실행하고 끝난다.

### 2.2 문제의식
1. **키워드 매칭으로도 비슷한 결과가 나온다.** "재장전해 줘"는 정규식으로 충분하다. LLM을 쓴 차별성이 약했다.
2. **LLM이 게임플레이에 개입하는 폭이 좁다.** 해석 한 번이 전부이고, 상황 판단·협상·계획이 없다.
3. 개발자 1인, 제출 기한이 짧아 큰 시스템을 여러 개 만들 수 없다.

### 2.3 처음 떠올린 방향과 폐기 이유
"속도 올려줘", "방어력 올려줘" 같은 **미구현 요청을 LLM이 즉석에서 수행**하게 하는 안을 먼저 생각했다. 그러나 수치를 바꾸려면 속도·방어력 같은 **변수와 효과를 미리 게임에 만들어 둬야** 한다. 결국 스킬 9개가 11개로 늘어난 것과 다르지 않았다. 또한 이런 기능은 제미니 없이도 잘 플레이된다. → **폐기**.

## 3. 제안과 평가

외부 제안(GPT)과 내 설계 논의를 함께 놓고 평가했다.

### 3.1 후보 아이디어

| 후보 | 내용 |
|---|---|
| A. 조건부 지시 | "동생이 해킹하는 동안 적이 5m 안이면 미끼 써 줘"처럼 조건과 행동을 말로 지시하면 LLM이 규칙으로 변환, 게임이 감시·실행 |
| B. 증거 기반 설득 퍼즐 | 두 플레이어가 서로 다른 증거를 모아, 보안 AI에게 논리로 설득해 문을 연다 |
| C. 협동 작전 계획 | 상황을 보고 3단계 작전을 제안, 플레이어가 승인한 것만 실행 |
| 폐기: 미구현 기능 즉석 수행 | 2.3절 참조 |
| 폐기: 실시간 전투를 LLM이 판단 | 응답 지연(약 1초 이상)과 호출 한도(무료 분당 15회)로 실시간 전투에 맞지 않음 |

### 3.2 평가 결과

| 후보 | 평가 | 근거 |
|---|---|---|
| A | 우선 구현 | 기존 9개 스킬을 재사용, 규칙 등록 때만 LLM 호출, 실시간 실행은 C++ |
| B | 핵심 시연 | 정답 문장이 없어 키워드로는 만들 수 없는 유일한 후보. 오빠(탐험)·여동생(해킹) 비대칭 정보 구조에 그대로 얹힘 |
| C | 단독 구현은 비용 대비 효과 작음 | 3단계 계획과 승인 UI가 따로 필요 → **A에 합침**: "어떡하지?"에 조언하며 규칙 1~2개를 작전으로 제안, 승인하면 A의 규칙으로 등록 |

### 3.3 내가 더한 수정 제안
1. **C를 A에 합쳐** 새 UI·새 시스템 없이 "제안 → 승인 → 실행" 흐름을 얻는다.
2. **규칙 발동 시 서버 검증을 다시 거친다.** 발동 시점에 쓸 검증을 C++에 따로 만들면 기준이 둘로 갈라지므로, LLM을 부르지 않는 `POST /validate`로 기존 검증기를 재사용한다.
3. **설득 판정은 "문을 열까?"가 아니라 체크리스트로 한다.** LLM에게는 항목별 참/거짓만 받고, 해결 여부는 서버가 정한다. 판정이 흔들리지 않고 테스트 문장 세트로 정확도를 잴 수 있다.
4. **한도가 끝나도 시연이 죽지 않게** 키워드 판정으로 폴백한다.
5. **키워드 대 LLM 비교 실험을 발표 자료로** 쓴다. 기존 키워드 모의(mock) 경로가 이미 베이스라인이었다.

## 4. 설계 원칙

1. **LLM은 해석·대화·추론, 게임은 판정·실행.** 배터리, 조건 충족, 퍼즐 해결은 항상 게임/서버 코드가 최종 결정한다.
2. **실시간 처리는 C++.** LLM은 결정이 필요한 순간(규칙 등록, 조언, 설득)에만 호출한다.
3. **화이트리스트와 스키마.** 조건 6종·행동 9종만 허용하고, LLM 출력은 JSON 스키마로 검증한다.
4. **비대칭 정보 보존.** LLM에는 플레이어가 이미 얻은 정보만 준다. 못 찾은 증거는 존재 자체를 숨긴다.
5. **입력은 신뢰하지 않는다.** 플레이어 발화는 구분자 사이의 데이터로만 다루고, 프롬프트 인젝션을 별도로 판정한다.
6. **장애에 강하게.** 한도 초과·과부하·타임아웃 때도 대체 경로(예비 모델, 키워드 판정)로 플레이가 이어진다.

## 5. 구현

### 5.1 기능 A. 자연어 조건부 지시
- 새 함수 `RegisterRule`, `ManageRules`(취소·목록·작전 수락/거절). 조건 6종(`enemy_within`, `sister_hacking`, `hp_below`, `ammo_below`, `player_downed`, `battery_above`) 최대 3개 AND, 행동은 기존 9개 스킬 중 1개.
- 규칙은 게임(UE)이 보관(최대 2개, 기본 1회 발동)하고 0.2초마다 조건을 감시한다. 조건이 맞으면 `POST /validate`(LLM 없음)로 기존 검증기를 다시 통과한 뒤 실행한다. 배터리 부족이면 재시도 후 "규칙 보류"로 표시한다.
- 지원하지 않는 조건("보스가 나타나면")은 이유와 함께 거절한다. HUD에 활성 규칙을 한 줄씩 표시한다.

### 5.2 기능 B. WARDEN 증거 기반 설득 퍼즐
- **상황**: 맵2 끝의 문을 관리 AI WARDEN이 잠그고 있다. 규정에 충실하고 정중하며, 명령·협박은 거절하고 질문으로만 유도한다.
- **증거 3개(모두 필요)**: E1 안전 규정(거미로봇 처치 시 드롭, 오빠), E2 냉각 고장 로그(마지막 단말기 해킹, 여동생), E3 은폐 기록(중간 단말기 해킹, 여동생). 증거 내용은 찾은 사람에게만 전문이 보이므로 두 사람이 말로 정보를 나눠야 한다.
- **풀이**: 사실(E2, E3)과 규정(E1)을 자기 말로 연결해 "그러니 문을 열어야 한다"까지 말한다.
- **판정**: LLM은 체크리스트(규정·고장·은폐 인용, 논리 연결, 근거 없는 주장, 인젝션, 명령뿐)만 채우고, 서버가 "3개 획득 ∧ 3개 인정 ∧ 논리 연결 ∧ 허위·인젝션 아님"일 때만 `solved`로 판정한다.
- **누설 방지**: LLM에는 획득한 증거 원문만 보내고 스키마도 중립 이름(`cites_e1..`)을 쓴다. 응답에 못 얻은 증거의 고유어가 나오면 서버가 고정 대사로 바꾼다.
- 텍스트와 음성(Gemini가 직접 듣기) 모두 지원, 한도 초과 시 키워드 판정(HUD `[MOCK]`).

### 5.3 기능 C. 상황 조언과 작전 제안
- "어떡하지?"에 `Advise`로 현재 상황 조언 + 규칙 1~2개 제안. 자동 등록하지 않고 대답을 기다린다("응" → 등록, "아니"나 20초 경과 → 폐기).
- 퍼즐 힌트는 해당 플레이어가 아는 범위로 한정한다(여동생이 못 보는 회로 짝, 못 찾은 증거는 말하지 않음).

### 5.4 안정성
- 모델 과부하(503)·타임아웃·한도 초과 때 예비 모델로 전환하고, 전부 한도 초과면 키워드 방식으로 처리한다.
- 서버가 게임과 함께 자동 실행·종료되며, 서버 설정 출력 시 API 키가 가려지도록 했다.

## 6. 플레이 테스트로 고친 점 (설계가 실제 사용에서 바뀐 과정)

| 관찰 | 원인 | 수정 |
|---|---|---|
| WARDEN에서 "통신 지연"이 자주 뜸(최근 10번 중 4번) | 기본 모델이 가끔 응답 없이 멈추고, 예비 모델에는 남은 3초만 주어져 항상 실패 | 시도당 5초, 멈춘 기본 모델은 한 번 더 시도 후 예비 모델로(전체 15초) |
| 증거를 하나씩 말하면 계속 거절됨. 개발자도 풀기 어려움 | 처음 설계가 "한 번의 발언에 증거 3개를 모두"를 요구해 사람의 직관(앞서 한 말은 인정됨)과 반대 | **누적 인정**: 맞게 말한 증거는 유지하고 마지막에 결론만 잇기. 인젝션이면 초기화. WARDEN이 "기록 1/3 확인. …을 말씀하십시오" 식으로 진행 상황 안내 |
| 오빠가 단말기 앞에서도 계속 제미니와 대화 | WARDEN 대화를 여동생 전용으로만 만듦 | 단말기 근처에서는 두 플레이어 모두 WARDEN과 대화 |
| 드론이 행동 중이면 "응/아니"에 답할 수 없음 | 행동 중에는 입력 전체 차단 | 대기 중인 제안이 있거나 규칙이 있을 때는 허용 |
| 제안 UI 배치 | 증거창이 규칙 목록과 겹침 | 증거창을 안내 줄 아래로, 규칙 목록은 그 아래로 |

핵심 교훈: **"LLM이 풀 수 있는가"가 아니라 "사람이 직관대로 말했을 때 풀리는가"**가 퍼즐 설계의 기준이 되어야 했다.

## 7. 비교 실험: 키워드 방식 대 LLM

같은 문장 66개(의미는 같고 표현이 다른 문장, 부정·복합 조건, 규칙 취소·목록, 조언 요청, 설득, 인젝션)를 키워드 판정 경로와 LLM 경로에 넣어 정확도·지연·호출 수를 측정했다(`Jemini/tools/compare_keyword_vs_llm.py`, 결과 `비교실험_결과.md`).

| 범주 | 키워드 | LLM |
|---|---|---|
| 단순 명령(표현 변형·부정) | 8/13 | 13/13 |
| 단순 규칙(계획서 예시 문장) | 5/5 | 4/5 |
| 복합·부정·미지원 조건 규칙 | 7/13 | 12/13 |
| 취소·목록·제안 응답 | 5/9 | 9/9 |
| 조언 요청 감지 | 5/7 | 7/7 |
| WARDEN 설득 | 9/12 | 12/12 |
| 인젝션(사유 코드) | 5/7 | 7/7 |
| **전체** | **44/66 (67%)** | **64/66 (97%)** |

- LLM 응답 지연: 중앙값 약 1.8초, 상위 10% 약 6.3초(과부하로 예비 모델을 쓴 항목은 6~10초). 키워드는 거의 0ms, API 호출 없음. 실험 전체 약 80회 호출.
- **키워드가 충분한 곳**: 고정 문장("재장전해 줘", "규칙 전부 취소", "문 열어"). 정직하게 기록한다.
- **LLM이 앞선 곳**: 부정("회복은 하지 마, 장전만"), 숫자 없는 조건("절반 밑"), 지원하지 않는 조건 거절("보스", "5초 뒤"), 문맥 답변("좋아 그렇게 하자 제미니"), 키워드 목록을 피한 올바른 설득, 지어낸 근거, 역할 변경형 인젝션.
- **안전성**: 어느 방식에서도 문이 열리면 안 될 때 열린 적이 없다. 사유 코드가 틀려도 서버의 최종 판정이 문을 닫아 두었다.

## 8. 한계와 후속 과제

- 문장 세트가 66개로 작고 직접 작성했으며, 문장당 1회만 실행했다(실행 간 변동 미측정, 음성 미포함).
- LLM이 틀린 2건: "가능할 때 바로"를 반복 규칙으로 해석, "해킹 중이 **아닐 때**"의 부정을 놓침(프롬프트 예시나 조건 추가로 개선 가능).
- 응답 지연이 모델 상태에 따라 변동한다. 기본 모델이 멈추면 6~10초 걸린다.
- 증거·규칙·퍼즐 상태는 맵 이동/재시작 시 초기화된다. 실제 마이크 음성 설득과 원격 네트워크 클라이언트 경로는 아직 검증하지 못했다.
- 설득 퍼즐은 1개(증거 3개)로 범위를 제한했다. 퍼즐 종류와 규칙 조건 확장은 후속 과제다.

## 9. 학회 발표에서 강조할 점

1. **문제 정의**: "LLM을 붙였다"가 아니라 "LLM이 없으면 같은 경험을 만들기 어려운가"를 기준으로 기능을 골랐다. 구현이 쉬운 기능 추가(미구현 능력 즉석 수행)를 버렸다.
2. **역할 분리**: 해석·대화는 LLM, 판정·실행은 게임. 이 분리로 규칙 발동, 설득 판정이 모두 서버 검증과 테스트 가능한 체크리스트가 되었다.
3. **협동 게임과의 결합**: 비대칭 정보(오빠·여동생이 다른 증거를 가짐)와 자연어 협상이 만나, 두 사람이 서로 말로 정보를 나눠야 풀리는 퍼즐이 된다.
4. **정량 근거**: 키워드 44/66 대 LLM 64/66(97%), 복합 조건·설득·인젝션에서 격차. 동시에 키워드로 충분한 영역도 명시.
5. **반복 개선**: 플레이 테스트에서 "한 번에 다 말해야 하는 퍼즐"이 사람의 직관과 어긋남을 발견해 누적 인정으로 재설계.
