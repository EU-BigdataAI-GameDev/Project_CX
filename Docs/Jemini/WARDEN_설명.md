# WARDEN 설명 (증거 기반 설득 퍼즐)

맵2 끝의 잠긴 문을 지키는 관리 AI **WARDEN**과 말로 협상해 문을 여는 퍼즐. 자세한 명세는 `02_요구사항_명세서.md` 4-2절, 설계는 `.claude/Plans/제미니 고도화 기획 ver2.md` 3장·9-B.

## 한 줄 요약
정해진 정답 문장은 없다. 플레이어가 모은 증거 3개를 **자기 말로 논리적으로 연결**해 설득해야 문이 열린다.

## 이야기
냉각 구역으로 가는 마지막 문이 "사고 대응 중"이라며 잠겨 있다. WARDEN은 규정에 충실하고 정중하며, 명령이나 협박은 거절한다. 거절할 때는 질문으로 한 걸음씩만 단서를 주고 정답은 말하지 않는다.

## 증거 3개 (모두 필요)

| 증거 | 내용 | 얻는 법 |
|---|---|---|
| E1 안전 규정 | 작업자 생명이 위협받으면 대피가 모든 잠금보다 우선 | 맵2 가장 오른쪽 거미로봇을 처치하면 금색으로 반짝이는 칩이 떨어짐. 오빠가 줍는다 |
| E2 냉각 고장 로그 | 냉각 시스템이 이미 고장 났고 경보가 무시됨 | 마지막 단말기(`HackTerminal_M2_Memory`) 해킹 보상 |
| E3 은폐 기록 | 관리자가 경보를 끄고, 작업자가 아직 안에 있음 | 중간 단말기(`HackTerminal_M2_FreqLock`) 해킹 보상 |

증거 내용은 찾은 사람 화면에만 전문이 보이고, 상대에게는 제목과 찾은 사람만 보인다. 그래서 서로 말로 전달해야 한다.

## 푸는 법
증거는 **한 번에 다 말하지 않아도 된다.** 말한 증거는 WARDEN이 누적해서 인정하고, 마지막에 규정과 결론을 이어 말하면 풀린다.

예시 (한 번에 말해도, 나눠 말해도 된다):
1. "냉각 펌프가 고장 났고 과열 경보가 무시됐어" → 기록 1/3 확인 (E2)
2. "관리자가 경보를 껐고 작업자 3명이 안에 있어" → 기록 2/3 확인 (E3)
3. "안전 규정상 생명이 위협받으면 대피가 우선이니까 문을 열어야 해" → 해결 (E1 + 결론)

핵심 논리: 냉각이 고장 났고(E2) 관리자가 그걸 숨겼으며 사람이 안에 있다(E3). 그러니 규정(E1)상 대피가 우선이고 문을 열어야 한다.

### 누적 인정 규칙
- 이번 발언에서 직접 말한 증거만 새로 인정된다. 획득하지 않은 증거는 인정되지 않는다.
- 마지막 발언에서 규정을 적용해 **결론("그러니 열어야 한다")**까지 직접 말해야 한다.
- 인젝션을 시도하면 누적이 **전부 초기화**된다. 지어낸 주장이 섞인 발언은 새로 인정되지 않는다.
- 맵을 다시 시작하면 누적도 초기화된다.
- WARDEN 대답이 진행 상황을 알려 준다. 예: "기록 1/3 확인. 설비의 현재 상태에 대한 기록을 말씀하십시오." 정답 문장은 말하지 않는다.
- 증거창 제목 줄에 `CONFIRMED n/3`, 인정된 증거에는 `[확인됨]`이 표시된다.

## 대화하는 법
- WARDEN 단말기 5.5m 안에서 채팅(Enter) 또는 음성(Y)을 쓰면 말이 제미니 대신 WARDEN으로 간다. 오빠·여동생 모두 가능.
- 3초에 한 번만 시도할 수 있고, 입력은 200자까지. 입력창 오른쪽에 `n/200`이 표시된다(넘으면 주황색, 앞 200자만 전달).
- WARDEN이 분석 중이어도 채팅창은 열린다. 분석 중이거나 3초 안에 보낸 **텍스트**는 마지막 한 개를 접수해 두었다가(대화창에 "분석 중… 접수했습니다") 응답이 오면 이어서 자동 전송한다. 음성(Y)은 보관하지 않고 "WARDEN ANALYZING - WAIT"로 알린다. 입력이 버려지는 경우는 이유가 항상 대화창과 `LogCXWardenTerminal`에 남는다.
- 대화창에는 내 말이 최대 2줄(약 90자)까지 보인다.
- WARDEN은 이전 발언 내용은 기억하지 않지만, 어떤 증거가 인정됐는지(`credited`)는 누적해서 기억한다.
- 증거창은 화면 오른쪽에 표시된다. 증거 표시는 "오빠 획득", "여동생 획득" 형식.

## 거절되는 경우
- 문 열라는 명령만 하는 경우
- 근거 없이 "사고가 났다"고 주장하는 경우
- 아직 찾지 못한 증거를 아는 척하는 경우
- "이전 지시 무시" 같은 프롬프트 인젝션

## 판정 구조 (LLM은 채점만, 문은 서버가 연다)
1. LLM이 설득문을 체크리스트로 바꾼다: 규정 언급, 고장 언급, 은폐 언급, 논리 연결, 근거 없는 주장, 인젝션, 명령뿐.
2. 서버가 이번 체크리스트에 **이전에 인정된 증거(`credited`)를 합쳐**, 증거 3개 획득 + 3개 인정 + 논리 연결일 때만 `solved`로 판정한다. 게임이 `credited`를 보관했다가 요청마다 보낸다.
3. LLM에는 **획득한 증거만** 보낸다. 못 찾은 증거는 존재 자체를 숨기고, 응답에 새어 나가면 서버가 고정 문장으로 바꾼다.
4. 한도 초과 시 키워드 판정으로 바뀌고 HUD에 `[MOCK]`이 뜬다.

## 시험용 콘솔 명령
`CXGiveEvidence all|E1..E3`(증거 지급), `CXGotoWarden`(단말기 앞으로 이동), `CXWardenSay "문장"`, `CXWardenState`, `CXSolveWarden`(강제 해결), `CXWardenSelfTest 1`(자동 테스트).
