# 제미니 서버 배포 가이드

제미니(LLM 드론)와 WARDEN이 쓰는 서버(`Jemini/`)를 외부에 올려, 키 없는 게임 배포판도 제미니를 쓰게 만드는 과정을 기록한다. **진행하면서 계속 고치는 문서다.** 마지막 갱신: 2026-11-20(Render 배포 완료, 서버 동작 확인).

## 1. 개요

- 제미니 서버는 FastAPI 앱이다. 게임이 보낸 말(채팅·음성)을 Gemini API로 해석해 행동 JSON으로 돌려주고, WARDEN 설득 판정도 한다. 설계는 `Docs/Jemini/제미니_고도화_설계기록.md`.
- 지금까지는 게임을 켜면 같은 PC에서 서버가 같이 켜졌다(`127.0.0.1:8000`, 키는 `Jemini/.env`).
- **목표:** 서버를 인터넷에 올려 두고, 게임이 그 주소로 요청하게 한다. 배포판에는 서버 주소와 토큰만 넣고 **Gemini API 키는 넣지 않는다.**

## 2. 왜 배포하는가

| 이유 | 설명 |
|---|---|
| 키 보호 | 키를 넣은 배포판(`copy_jemini_to_package.bat --with-key`)을 zip으로 나누면 키가 퍼진다. 서버에만 키를 두면 배포판은 안전하다 |
| 팀원·시연 | 팀원이 서버·파이썬 설정 없이 exe만 받아 제미니를 쓴다. 학술제·GGC 시연 PC도 마찬가지다 |
| 과제 요구 | 학교 과제("Jemini" LLM 드론, 제출 2026-12-02, 발표 2026-12-09)에서 서버를 외부에 올려 두는 구성이 필요하다 |
| 용량 | 서버 폴더(음성 모델 포함 약 680MB)를 배포판마다 넣지 않아도 된다 |

## 3. 어디에 올리나 (결정 기록)

1. **처음 계획: 허깅페이스 Docker Space.** 서버가 이미 Docker 구조라 그대로 올릴 수 있다고 봤다.
2. **막힘(2026-11-20):** 2026년 7월부터 허깅페이스 무료 계정은 Docker Space를 만들 수 없다(SDK 선택 화면에 Paid 표시). Gradio SDK로 우회하는 방법은 ZeroGPU 하드웨어 문제로 확실하지 않아 보류.
3. **결정: Render 무료 웹 서비스.** GitHub 저장소를 연결해 Dockerfile로 빌드한다. 카드 없이 시작할 수 있고 서버 코드는 거의 그대로다.
   - 단점: 15분 안 쓰면 잠들고 깨어나는 데 30~60초가 걸린다 → 게임이 켜질 때 `/health`를 미리 보내 깨운다(아래 6절).
   - 대안(보류): Google Cloud Run(결제 수단 필요), 허깅페이스 유료.

## 4. 구조

### 4-1. 전체 흐름

```
게임(UE, 플레이어 PC)
   │  HTTPS  +  헤더 X-API-Key: <API_TOKEN>
   ▼
Render 웹 서비스  ← Docker 이미지(jemini-server 저장소의 Dockerfile)
   │  FastAPI (uvicorn, 포트는 Render가 PORT로 지정)
   │  환경변수: GEMINI_API_KEY, API_TOKEN, (STT_ENABLED=false)
   ▼
Gemini API (gemini-3.1-flash-lite, 실패 시 3.5-flash-lite로 대체)
```

- 서버는 상태를 갖지 않는다(증거·규칙 상태는 게임이 요청마다 보낸다). 그래서 재시작·잠들었다 깨어나도 게임이 이어진다.
- 로컬 실행도 그대로 가능하다. `ServerUrl`이 `127.0.0.1`이면 게임이 서버를 직접 띄운다.

### 4-2. 폴더 구조 (이 PC 기준)

```
source\repos\
├─ Project_CX\                     ← 게임 저장소 (조직 저장소, 팀 작업)
│  ├─ Jemini\                      ← 서버 원본 소스(여기서 고친다)
│  │  ├─ app\                      서버 코드(main, llm, persuasion, rules, validator ...)
│  │  ├─ prompts\                  시스템 지시문, WARDEN 지시문
│  │  ├─ Dockerfile                배포용 이미지 정의
│  │  ├─ requirements.txt          로컬용(음성 자막 faster-whisper, 테스트 포함)
│  │  ├─ requirements-space.txt    배포용(가벼운 의존성, 음성 자막 없음)
│  │  ├─ tools\deploy_to_repo.ps1  배포용 저장소로 복사·커밋하는 스크립트
│  │  ├─ tests\                    서버 테스트(pytest)
│  │  └─ .env                      로컬 키(저장소에 올리지 않음)
│  ├─ Project_CX\Config\DefaultGame.ini   ServerUrl, ApiToken
│  └─ Docs\Jemini\서버_배포_가이드.md      이 문서
│
└─ jemini-server\                  ← 배포용 저장소 (개인 GitHub, Private)
   ├─ app\  prompts\  Dockerfile  requirements-space.txt  README.md  .dockerignore
   └─ (.env, .venv, models, logs, tests는 넣지 않는다)
```

- **왜 저장소를 둘로 나누나:** `Project_CX`는 조직 저장소라 Render가 접근하려면 조직 설정이 필요하고, 게임 에셋(수 GB)이 함께 들어 있다. 서버 파일만 올릴 가벼운 개인 저장소(`jemini-server`)를 따로 두었다. Private이어야 한다(`prompts/warden_instruction.txt`에 WARDEN 판정 지시문이 있어 공개하면 정답이 드러난다).
- 서버 코드는 항상 `Project_CX/Jemini`에서 고치고, 배포할 때 스크립트로 `jemini-server`에 복사한다(반대 방향으로 고치지 않는다).

### 4-3. 환경변수

| 이름 | 어디에 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | Render 환경변수 | Gemini 키. 저장소·문서·채팅에 쓰지 않는다 |
| `API_TOKEN` | Render 환경변수 + 게임 `ApiToken` | 게임이 `X-API-Key` 헤더로 보내는 문자열. 없으면 누구나 서버를 쓸 수 있다 |
| `STT_ENABLED` | Dockerfile(`false`) | 무료 CPU에서 실시간 자막(faster-whisper)을 끈다 |
| `PORT` | Render가 주입 | Dockerfile의 기본값(7860)을 덮어쓴다 |
| `GEMINI_MODEL` | (선택) | 기본 모델을 바꿀 때 |

## 5. 배포 절차 (Render)

### 5-1. 배포용 저장소 만들기
1. GitHub에서 새 저장소 `jemini-server`를 **Private**으로 만든다(README 추가 안 함).
2. `source\repos`에서 받는다: `git clone https://github.com/<계정>/jemini-server`
3. 서버 파일을 복사·커밋한다(`.env`·`.venv`·`models`는 복사하지 않는 스크립트):
   ```powershell
   cd <repos>\Project_CX
   .\Jemini\tools\deploy_to_repo.ps1 -TargetDir <repos>\jemini-server
   ```
4. `jemini-server`에서 `git push`(또는 GitHub Desktop의 Push origin).
5. GitHub에서 올라간 파일을 확인한다. `.env`·`.venv`가 있으면 안 된다.

### 5-2. Render 서비스 만들기
1. render.com에 GitHub 계정으로 가입한다.
2. **New → Web Service** → `jemini-server` 저장소 연결(목록에 없으면 Render의 GitHub 앱 권한에서 그 저장소를 허용).
3. 설정: Language **Docker**, Region **Singapore**, Instance Type **Free**, Health Check Path **`/health`**.
4. 환경변수: `GEMINI_API_KEY`, `API_TOKEN`(긴 임의 문자열. 예: PowerShell `[guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")`).
5. **Create Web Service** → 첫 빌드는 몇 분.

### 5-3. 확인
- `https://<서비스>.onrender.com/health` → `{"status":"ok", ...}`. `"mock": true`면 `GEMINI_API_KEY`가 안 들어간 것이다.

### 5-4. 게임에 연결
`Project_CX/Config/DefaultGame.ini`의 `[/Script/Project_CX.CXJeminiDrone]`:
```
ServerUrl="https://<서비스>.onrender.com"
ApiToken="<API_TOKEN과 같은 값>"
```
- `ServerUrl`은 **따옴표 필수**(없으면 `//` 뒤가 잘린다).
- 주소가 로컬이 아니면 게임이 서버를 따로 띄우지 않는다(`UCXJeminiServerSubsystem`의 원격 모드).

## 6. 게임 쪽 처리

- **워밍업:** 원격 서버일 때 게임이 켜지는 순간 `/health`를 한 번 보낸다(최대 90초 대기, 응답은 쓰지 않는다). 잠든 서버를 깨워 첫 제미니·WARDEN 요청이 "통신 지연"으로 끝나지 않게 한다(`CXJeminiServerSubsystem.cpp`).
- **인증:** 모든 요청에 `X-API-Key`가 붙는다(`CXJeminiClient.cpp`). 서버가 `API_TOKEN`과 다르면 401을 돌려준다.
- **서버가 없을 때:** 게임은 그대로 돌고, 제미니만 "신호가 끊겼어요" 대사를 한다.
- **한계:** 실시간 자막(패드 Y로 말할 때 머리 위에 뜨는 글자)은 배포 서버에서는 나오지 않는다(`STT_ENABLED=false`). 음성 명령 자체는 동작한다.

## 7. 운영 메모

- 시연·발표 직전에 `/health`를 브라우저로 한 번 열어 깨워 둔다.
- 무료 인스턴스는 월 사용 시간 한도가 있다. 시연 날 전에 한도를 확인한다.
- 무료 Gemini 키의 호출 한도를 여러 명이 함께 쓰면 응답이 느려지거나 모의(`[MOCK]`) 모드로 떨어진다.
- 서버 코드를 고치면: `Project_CX/Jemini`에서 수정 → pytest(`--tb=line`) → 스크립트로 복사·커밋 → `jemini-server`에서 push → Render가 자동으로 다시 빌드한다.
- 키를 바꿀 때는 Render 환경변수만 고치고 재배포한다. 키가 새면 Gemini 키부터 재발급한다.
- `API_TOKEN`은 게임 ini에 들어가므로 비밀이 아니다. 남용이 보이면 Render 환경변수와 ini를 함께 바꾼다.

## 9. 문제 해결

| 증상 | 확인 |
|---|---|
| `/health`가 `"mock": true` | `GEMINI_API_KEY` 환경변수 누락 또는 오타 |
| 게임에서 제미니가 "신호가 끊겼어요" | 서버가 잠든 중(1분 기다림), `ServerUrl` 따옴표·주소, 인터넷 연결 |
| 게임에서 401 | 게임 `ApiToken`과 Render `API_TOKEN`이 다름 |
| 응답이 매번 느림 | Gemini 한도 초과로 모델 대체 중(3.1 → 3.5), 서버 지역(Singapore) 확인 |
| Render 빌드 실패 | Render 로그에서 pip 설치 오류 확인(`requirements-space.txt`), Dockerfile 경로 |
| 빌드 로그에 `mkdir: cannot create directory 'logs': Permission denied` | Dockerfile에서 `USER user` 전에 `mkdir -p logs && chown -R user:user /home/user/app`를 실행해야 한다(고침) |
| `/command`가 `status: fallback`, `reason: LLM_ERROR` | `GEMINI_API_KEY` 환경변수 값이 잘못됨(일부 누락, 공백·따옴표). Render Logs의 `LLM_ERROR (text): ...` 줄로 이유를 본다. 값을 고치고 재배포 |
| 허깅페이스에 올리고 싶다 | Docker Space는 유료 계정 필요. 같은 `Dockerfile`·스크립트로 올릴 수 있다 |

## 10. 변경 기록

- 2026-11-20: 허깅페이스 Docker Space가 무료 계정에서 막혀 Render로 결정. 경량 requirements·Dockerfile(STT 끔)·배포 스크립트·원격 워밍업 추가. 배포용 저장소 `jemini-server` 준비.
- 2026-11-20: Render 첫 배포가 Dockerfile 권한 오류(logs 폴더)로 실패 → 수정. 이어서 `GEMINI_API_KEY` 일부 누락으로 `LLM_ERROR`가 나서 값을 다시 넣고 해결. LLM 호출 실패 이유를 Render Logs에 남기도록 서버에 진단 로그(`log_llm_error`, 키처럼 보이는 문자열은 가림) 추가.
- 2026-11-20: 배포 서버 확인 완료(`/health` ok, 인증 401, "재장전 해줘" → `ReloadSupport`, WARDEN `/persuade` 정상 거절·판정, 응답 1.6~2.7초). `DefaultGame.ini`를 배포 서버 주소로 교체.
