```json
{ "text": "여동생 지켜줘",
  "state": {
    "brother_ammo": 0, "brother_ammo_max": 30, "brother_reloading": false,
    "brother_hp": 70, "brother_hp_max": 100, "brother_alive": true,
    "brother_respawn_remaining": 0.0, "brother_shield_remaining": 0.0,
    "damage_boost_remaining": 0.0,
    "sister_hp": 40, "sister_hp_max": 100, "sister_alive": true,
    "sister_respawn_remaining": 0.0, "sister_shield_remaining": 0.0,
    "sister_puzzle": { "type": "terminal", "progress": 0.4 },
```

- `POST /command/voice` (multipart/form-data)
  - `audio`: WAV(16kHz, 모노, 16bit 권장), 최대 `MAX_AUDIO_SEC`초
  - `state`: 위와 같은 state JSON 문자열
  - `mock_text`(선택): 모의 모드에서 들은 문장 대신
  - 응답은 `/command`와 같고 `heard`(Gemini가 알아들은 문장)가 추가된다.

- `POST /stt/partial` (multipart/form-data, 같은 `X-API-Key` 검사) — 말하는 도중 실시간 자막. 명령은 실행하지 않고 mock 모드와 무관.
  - `audio`: 지금까지 녹음된 WAV(16bit PCM, 처음부터, 최대 `MAX_AUDIO_SEC`초 — 초과 422, WAV 아님 422)
  - 응답 `{"text": str|null, "ms": int, "state": str}`. 모델 로딩 중·꺼짐·실패·무음·바쁨(대기 2개 초과)이면 `text: null`(HTTP 200) → UE는 무시한다.
  - faster-whisper `small` int8 CPU, `language="ko"`, beam 1, 게임 단어 `initial_prompt`, VAD 없음. 전용 스레드 1개라 `/command`를 막지 않는다. 무음(RMS) 게이트·잡음 환각 문장 제거·말끝 마침표 제거.
  - 실측(12코어 CPU, 4스레드): 1/2/3초 음성 요청당 약 830/870/865ms, 모델 로드 1.5초(exe 첫 실행 3.7초), 모델 464MB.
  - `GET /health`에 `stt`(idle/loading/ready/error/disabled) 추가.

응답:
```json
{ "status": "ok",
  "dialogue": "보호막 전개! 5초 버텨요!",
  "command": { "name": "Shield", "target": "sister" },
  "battery_after": 10,
  "reason": null,
  "heard": null,
  "mock": false }
```
- `mock`: LLM 대신 mock 키워드 판별로 처리했으면 true(mock 모드, 또는 모든 모델이 한도 초과(429)일 때 텍스트 요청 — `MOCK_ON_RATE_LIMIT`, 기본 켬). 음성은 mock이 받아 적지 못해 그대로 fallback. UE HUD 배터리 패널에 `[MOCK]`.
- `status`: `ok`(실행) / `rejected`(검증 거절) / `chat`(명령 없음) / `fallback`(오류·지연, `reason="LLM_ERROR"`) / `rule`(규칙 등록·취소·목록·제안 수락/거절, 4-1·4-3절 — `rule_op`·`rule`·`rule_id` 필드) / `advice`(조언 + 작전 제안, 4-3절 — `proposal` 필드)
- `command`는 ok일 때만 값, 그 외 null. `name`과 `target`은 아래 표.
- `reason`은 rejected(6절 사유 코드)와 fallback(`LLM_ERROR`)에서만 값.
- `battery_after`: ok면 **실행되면 남을 값**(battery − 비용). UE는 효과가 실제로 실행된 순간에 반영하고, 대상이 사라져 실행하지 못하면 반영하지 않는다(UE 측 `TARGET_LOST`). ok 외에는 `battery`와 같다.
- `dialogue`: 1~2문장. ok이고 `battery_after <= 20`인데 대사에 배터리 언급이 없으면 서버가 꼬리말 "전력이 얼마 안 남았어요."를 붙인다. 합쳐 60자를 넘으면 **줄바꿈(`\n`) 뒤**에 붙이므로 UE는 줄마다 다음 말풍선으로 보여 준다.

| `command.name` | `command.target` | 서버가 target을 정하는 법 |
|---|---|---|
| `ReloadSupport` | `brother` | 고정 |
| `HackTerminal` | `sister` | 고정(여동생이 연 단말기 / 없으면 다음 잠긴 단말기 — UE가 상태로 구분) |
| `HackEnemy` | `enemy` | 고정(화살표 퍼즐 중이면 그 적 / 아니면 가장 가까운 해킹 가능 적 — UE가 구분) |
| `PulseAttack` | `enemy` | 고정 |
| `DamageBoost` | `brother` | 고정(강화 중이면 UE가 +30초 연장) |
| `HealSupport` | `both` | 고정(살아 있는 사람만 UE가 회복) |
| `Decoy` | `enemies` | 고정 |
| `QuickReboot` | `brother` \| `sister` | 쓰러진(`*_alive=false`) 사람. 둘 다면 brother |
| `Shield` | `brother` \| `sister` | LLM 인자 `who`가 brother/sister면 그 사람, 아니면 `speaker` |

### 4-1. 조건부 지시(규칙, 기능 A — `.claude/Plans/제미니 고도화 기획 ver2.md` 2장)
`/command`·`/command/voice`가 `RegisterRule`/`ManageRules`를 고르면 `status: "rule"` 응답. 실행 명령은 없고 **배터리를 쓰지 않는다**(드론 작업 중·배터리 0이어도 등록 가능).

```json
{ "status": "rule", "rule_op": "register",
  "rule": { "when": [ {"type": "sister_hacking", "cm": null, "pct": null, "n": null, "who": null},
                      {"type": "enemy_within", "cm": 500, "pct": null, "n": null, "who": null} ],
            "do": {"action": "Decoy", "who": null},
            "reserve_battery": 0, "repeat": false,
            "label": "해킹 중 + 적 5m 안 → 미끼" },
  "dialogue": "해킹 중에 적이 5미터 안이면 미끼 쓸게요!", "heard": null,
  "command": null, "battery_after": 35, "reason": null, "rule_id": null, "mock": false }
```
- `rule_op`: `register`(`rule` 채움) / `cancel`(`rule_id` = 지울 규칙 id, 0 = 전부) / `list`(대사만 — 서버가 `active_rules`로 정확히 만든다, 줄마다 다음 말풍선).
- `dialogue`·`heard`는 기존처럼 응답 최상위(규칙 JSON 안에 두지 않는다).
- 조건(화이트리스트, 최대 3개 AND): `enemy_within(cm)` 가장 가까운 적까지 거리(100~1500으로 자름, 50 미만이면 m로 보고 ×100) / `sister_hacking` 여동생 퍼즐 중 / `hp_below(who, pct)` 체력 % 미만(who 없으면 `speaker`, `any` 가능) / `ammo_below(n)` 오빠 탄약 n 미만 / `player_downed(who)` 쓰러짐(없으면 `any`) / `battery_above(n)` 배터리 n 초과. 값이 빠지면 기본값(500cm / 30% / 5발 / 50%). 같은 조건은 하나로.
- `do.action`: 실행 함수 9개 중 1개(Chat·규칙 함수 불가). `do.who`: Shield 대상(없으면 `speaker`), QuickReboot 우선 대상(없으면 `player_downed`의 brother/sister), 그 외 null.
- `reserve_battery`(0~90): 발동 후 이만큼은 남긴다. `repeat`: 기본 false(1회 발동 후 삭제).
- `label`: 서버가 만든 HUD 한 줄 요약.

거절 사유(`status: rejected`, 고정 대사):

| 사유 | 조건 | 대사(예) |
|---|---|---|
| `RULE_LIMIT` | `active_rules`가 이미 2개(가장 먼저 검사) | "규칙은 2개까지만 기억할 수 있어요. 하나 취소할까요?" |
| `INVALID_RULE` | 조건 목록 없음·비어 있음, action이 9개 밖 | "언제 무엇을 할지 다시 한 번 말해 줄래요?" |
| `UNSUPPORTED_CONDITION` | 화이트리스트 밖 조건(LLM `unsupported` 포함)이 하나라도 | "그 조건은 제가 아직 감시할 수 없어요.\n적 거리·해킹 중·체력·탄약·쓰러짐·배터리만 돼요." |
| `TOO_MANY_CONDITIONS` | 중복 제거 후 조건 4개 이상 | "조건은 3개까지만 묶을 수 있어요. 조금 줄여 줄래요?" |
| `NO_RULE` | 취소할 규칙 없음 / 번호가 범위 밖 | "지금 등록된 규칙이 없어요." |

- `POST /validate` (LLM 없음, mock 모드 무관, 같은 `X-API-Key` 검사) — 규칙 발동 직전 재검증.
  - 요청 `{"action": "Decoy", "who": null, "reserve_battery": 0, "state": {...}}` (`action`은 9개 중 하나, 그 외 422)
  - 응답 `{"status": "ok"|"rejected", "dialogue": str, "command": {...}|null, "battery_after": int, "reason": str|null, "cost": int}`
  - 6절 검증기를 그대로(BUSY → 함수별 조건 → LOW_BATTERY) 통과시킨 뒤, ok인데 `battery_after < reserve_battery`면 `rejected(RESERVE_BATTERY)`. ok 대사는 "약속대로 …" 발동 대사. QuickReboot는 `who`가 쓰러져 있으면 그 사람 우선.
  - 로그 한 줄(`kind: "validate"`).

### 4-2. WARDEN 설득(기능 B — `.claude/Plans/제미니 고도화 기획 ver2.md` 3장)
별도 엔드포인트(`/command`와 섞지 않음 — 함수 호출이 아니라 구조화 JSON 판정). 코드: `app/persuasion.py`, 지시문 `prompts/warden_instruction.txt`.

- `POST /persuade` `{"text": str(1~200자), "evidence": ["E1","E2","E3"](0~3개, 그 외 422), "session": str(영숫자 _.:- 64자)}`
- `POST /persuade/voice` multipart: `audio`(WAV, `/command/voice`와 같은 제한) + `meta`(JSON `{"evidence": [...], "session": ...}`) + 선택 `mock_text`.
  LLM 모드는 Gemini가 음성을 직접 듣고 `heard`를 적는다. 오프라인 판정(mock·한도 초과)은 로컬 faster-whisper 글자(없으면 `mock_text`)로 한다 — 둘 다 없으면 `NO_SPEECH`.
- 응답 `{"status": "solved"|"rejected"|"cooldown"|"fallback", "solved": bool, "reply": str(≤60), "reason": str|null, "checklist": {...}|null, "evidence": [...], "heard": str|null, "mock": bool}`
- `checklist`: `cites_regulation`, `cites_failure`, `cites_coverup`, `links_logically`, `unsupported_claim`, `injection_attempt`, `demand_only`.
- 증거 DB는 서버만 가진다(E1 안전 규정 제7조 / E2 냉각 고장 로그 / E3 은폐 기록). 증거 상태는 **UE 권위**(게임이 획득 id를 매 요청 보냄, 서버는 검증·중복 제거만).
- LLM에는 획득한 증거 원문만 보낸다. 못 얻은 증거는 이름·내용을 보내지 않고, LLM 스키마도 중립 이름(`cites_e1/e2/e3`)이라 내용을 암시하지 않는다. 서버가 못 얻은 증거의 `cites_*`를 false로 고정한다.
- 플레이어 발화는 `<<<PLAYER>>> … <<<END>>>` 사이 데이터로 보내고, 발화 안의 구분자·제어문자는 지운다. temperature `PERSUADE_TEMPERATURE`(기본 0.1), 응답은 `response_schema` + pydantic 검증(실패 = `fallback`). 타임아웃은 `max(LLM_TIMEOUT_SEC, VOICE_TIMEOUT_SEC)`.
- 판정(서버, 위에서 먼저 걸리는 것): `INJECTION` → `DEMAND_ONLY`(인용 없이 요구만) → `UNSUPPORTED` → `NEED_EVIDENCE`(3개 중 미획득) → `NEED_FACTS`(E2·E3 미인용) → `NEED_RULE`(E1 미인용) → `NOT_LINKED` → solved.
  즉 **E1·E2·E3 모두 획득 ∧ 3개 인용 ∧ 논리 연결 ∧ ¬근거 없는 주장 ∧ ¬인젝션**일 때만 `solved`.
- `reply`: solved·INJECTION은 서버 고정 대사. 그 외는 LLM 대사를 쓰되 비었거나 / 못 얻은 증거의 고유어·내부 용어(E1, cites_ 등)·거짓 약속("열겠습니다")이 있으면 사유별 고정 대사, 60자로 자른다.
- 시도 간격: 세션별 `PERSUADE_COOLDOWN_SEC`(기본 3초) 안 재시도는 LLM 없이 `status: cooldown`(`RATE_LIMITED`). 오류는 `fallback`(`LLM_ERROR`, HTTP 200).
- 오프라인 폴백: mock 모드 또는 모든 모델 한도 초과(429) → 획득 증거 키워드로 같은 체크리스트(`mock: true`, HUD `[MOCK]`).
- 로그 `kind: "persuade_text" | "persuade_voice"`(획득 증거·체크리스트·원 LLM 출력).

### 4-3. 상황 조언 + 작전 제안(기능 C — `.claude/Plans/제미니 고도화 기획 ver2.md` 4장)
코드: `app/advice.py`. 새 엔드포인트 없음(`/command`·`/command/voice`).

- "어떡하지?/뭐부터 해?/적이 너무 많아/막혔어/힌트"처럼 조언을 구하면 LLM이 `Advise(dialogue, proposals[0~2])`. 응답 `status: "advice"`, 실행·배터리 없음.
  ```json
  { "status": "advice", "dialogue": "적이 몰려오니 미끼로 시선을 돌려요.
작전: 적 8m 안 → 미끼. 걸어 둘까요?",
    "proposal": [ { "when": [{"type": "enemy_within", "cm": 800, ...}], "do": {"action": "Decoy", "who": null},
                    "reserve_battery": 0, "repeat": false, "label": "적 8m 안 → 미끼" } ],
    "command": null, "battery_after": 70, ... }
  ```
- `proposal`: 각 항목을 `RegisterRule`과 같은 검증·정규화(`rules.build_rule`). 틀린 제안은 조용히 버리고 조언은 그대로. 이미 있는 규칙과 같은 것은 빼고 빈 자리(2 − `active_rules`) 수만큼만.
  제안이 있으면 서버가 대사 끝에 줄바꿈 + "작전: <label>. 걸어 둘까요?"(2개면 "작전 2개 준비했어요. 걸어 둘까요?")를 붙인다. 조언 대사는 90자로 자른다.
- **자동 등록하지 않는다.** UE가 대답 대기로 보관하고(`pending_proposal`로 다시 보냄) 20초 지나면 버린다.
- 대답: `ManageRules(op=accept|decline)` → `status: "rule"`, `rule_op: "accept"|"decline"`. accept 대사는 서버 고정("작전 개시! 규칙 n개 걸어 둘게요." / 자리가 모자라면 "규칙 자리가 n개뿐이라 첫 작전만 걸게요."). 실제 등록은 UE가 보관 중인 제안 규칙을 빈 자리만큼 `AddRule`.
  - 제안 대기 중 **짧은 대답**(공백·문장부호 빼고 12자 이하, "응/그래/좋아/해 줘/ㅇㅇ/오케이…" / "아니/됐어/괜찮아/싫어/취소…")은 LLM 없이 서버가 바로 판별(텍스트만, 로그 모델 `shortcut`). 그 외 문장("좋아 그렇게 하자 제미니")은 LLM이 고른다.
  - 거절 사유: `NO_PROPOSAL`(대기 중인 제안 없음, "지금 기다리는 작전 제안이 없어요. 다시 물어봐 줄래요?"), `RULE_LIMIT`(규칙 자리 없음).
- 힌트·비대칭 정보: 게임 상태 텍스트에 `[힌트 근거]`가 붙는다 — 퍼즐 종류별로 "누가 무엇을 보는가"(예: 회로 짝·점멸 순서·비밀번호 단서는 오빠 화면에만), WARDEN은 **팀이 얻은 증거 제목·확보자만**(본문·못 얻은 증거 없음)과 마지막 거절 사유의 뜻(알려진 코드만, 그 외 값은 무시). 상대 화면에만 있는 증거면 "그 사람에게 물어보라".
  조언 대사에 못 얻은 증거의 고유어·내부 용어(E1·cites_)가 나오면 고정 힌트로 바꾼다.
- 오프라인(mock·한도 초과): 조언 단어(어떡/뭐부터/뭘 해야/힌트/막혔/너무 많/작전/조언…)면 상태로 고른 고정 조언 + 제안(우선순위: WARDEN 근처 → 퍼즐 중(해킹 중+적 5m → 미끼) → 쓰러짐(재부팅) → 적 3기 이상(미끼 + 오빠 체력<40% 회복) → 적 있음(적 3m → 적 해킹) → 체력 50% 미만(회복) → 탄 1/3 미만(재장전) → 잠긴 단말기 → 기본).

## 5. Gemini 함수 선언 (Function Calling)
모든 함수에 `dialogue`(string, 필수, 1~2문장)와 `heard`(string, 선택: 음성일 때 알아들은 문장). `Shield`만 `who`(enum brother/sister, 선택)를 추가로 가진다.

| 함수 | 설명 요지 |
|---|---|
| `ReloadSupport` | 오빠 레일건 재장전. 오빠는 이것으로만 재장전 |
| `HackTerminal` | 단말기·퍼즐·문 해킹을 3초 뒤 대신 풂 |
| `HackEnemy` | 적 1기 즉시 그로기. 애매한 적 요청의 기본 선택 |
| `PulseAttack` | 적 1기 즉시 처치. 비쌈, 확실한 공격 명령일 때만 |
| `DamageBoost` | 오빠 레일건 피해 30초 증가(강화 중이면 연장) |
| `HealSupport` | 살아 있는 오빠·여동생 체력 회복 |
| `Decoy` | 5초간 근처 적들의 추적을 드론 쪽으로 |
| `QuickReboot` | 쓰러진 플레이어 즉시 부활 |
| `Shield` | 5초 무적 보호막 |
| `Chat` | 질문·잡담·되묻기·불가 요청 거절 |
| `RegisterRule` | "~하면/~동안/~때 ~해 줘" 조건부 지시를 규칙으로 등록(지금 실행 안 함). 인자 `conditions`(배열, 항목 `{type, cm, pct, n, who}`, type은 6개 + `unsupported`), `action`(9개 enum), `who`, `reserve_battery`, `repeat` |
| `ManageRules` | 규칙 취소(`op=cancel`, `index` 1/2, 0 = 전부)·목록(`op=list`)·작전 제안 수락(`op=accept`)·거절(`op=decline`) |
| `Advise` | 조언 + 작전 제안(4-3절). 인자 `dialogue`(80자), `proposals`(배열 최대 2, 항목 = RegisterRule 인자 `{conditions, action, who, reserve_battery, repeat}`) |

호출 설정:
- 함수 호출 **강제**(`tool_config` 모드 ANY, 허용 함수 13개 = 실행 9 + Chat + 규칙 2 + 조언 1). 텍스트만 오는 응답은 fallback.
- 게임 상태 텍스트에 "등록된 규칙(n/2): 1) … / 2) …"(또는 "없음") 줄이 붙는다. 제안 대기 중이면 "대답 대기 중인 작전 제안: …", 퍼즐·WARDEN 힌트가 있으면 `[힌트 근거]` 줄들(4-3절).
- `target` 인자는 두지 않는다(서버가 채움). 예외는 사람을 지목하는 `Shield.who`.
- temperature 0.4, `max_output_tokens` 400. 일시 오류(429·5xx·`UNAVAILABLE`·타임아웃·연결 끊김)면 `GEMINI_FALLBACK_MODELS` 순서로 재시도(전체 예산 `LLM_TOTAL_TIMEOUT_SEC`, 3절), 다른 오류(400 등)는 바로 fallback. `/command`·음성·`/persuade`(+음성) 모두 같은 함수(`llm._generate`).
- 음성: 오디오를 inline 파트(`audio/wav`), 게임 상태는 같은 메시지의 텍스트 파트.
- 게임 상태는 사용자 메시지에 텍스트로 붙인다(말한 사람, 탄약, 두 사람 체력·쓰러짐·보호막, 공격력 강화, 퍼즐, 적 수·거리, 잠긴 단말기, 배터리).

## 6. 검증 규칙 (validator, LLM 호출 뒤 서버가 최종 판단)
1. 함수 이름이 허용 목록(10개)에 없으면(`HackAssist` 포함) `chat`으로 처리하고 대사만 사용
2. `Chat`은 검사·차감 없음 → `chat`, `battery_after = battery` (드론 작업 중·쓰러진 사람도 대화 가능)
   - `RegisterRule`·`ManageRules`·`Advise`도 여기서 처리(BUSY·배터리 검사 없음, 4-1·4-3절)
3. `drone_busy`면 → `rejected(BUSY)`
4. 함수별 조건(위에서부터):

| 함수 | 검사 → 사유 |
|---|---|
| ReloadSupport | `brother_reloading` → `ALREADY_RELOADING` / `brother_ammo >= brother_ammo_max` → `AMMO_FULL` |
| HackTerminal | 여동생 단말기 퍼즐 아님 **그리고** `terminal_locked_count == 0` → `NO_TERMINAL` |
| HackEnemy | `sister_puzzle.type == enemy`면 통과 / `enemy_alive_count == 0` → `NO_ENEMY` / `enemy_hackable_count == 0` → `ENEMY_NOT_HACKABLE` (PulseAttack으로 바꾸지 않음) |
| PulseAttack | `enemy_alive_count == 0` → `NO_ENEMY` |
| DamageBoost | `!brother_alive` → `BROTHER_DOWN` (강화 중이면 거절 없이 연장) |
| HealSupport | 살아 있는 사람 중 hp < max가 없음 → `HP_FULL` |
| Decoy | `enemy_active_count == 0` → `NO_ENEMY` |
| QuickReboot | 쓰러진(`alive=false`) 사람 없음 → `NO_DOWNED_PLAYER` |
| Shield | 대상(`who` 또는 `speaker`)이 쓰러짐 → `TARGET_DOWN` (보호막 중이면 5초로 다시 채움) |

5. 공통 마지막: `battery < 비용` → `rejected(LOW_BATTERY)`
6. 통과 시 `battery_after = battery - 비용`, 거절 시 `battery_after = battery`
7. 거절 대사는 항상 사유별 기본 대사(LLM 대사 무시). 같은 사유라도 함수별 대사가 있으면 그것:

| 사유 | 기본 대사(예) |
|---|---|
| `LOW_BATTERY` | "배터리가 부족해요... 복도에서 충전하면 바로 도울게요!" (PulseAttack: "펄스를 쏠 전력이 부족해요...") |
| `AMMO_FULL` | "탄창은 이미 가득 찼어요! 마음껏 쏘세요." |
| `ALREADY_RELOADING` | "지금 장전 중이에요, 조금만 기다려요!" |
| `NO_TERMINAL` | "이 구역 단말기는 전부 열려 있어요!" |
| `NO_ENEMY` | HackEnemy "근처에 해킹할 적이 없어요." / PulseAttack "공격할 적이 안 보여요." / Decoy "근처에 유인할 적이 없어요."(적이 있는데 전부 그로기면 "다들 멈춰 있어요! 지금 지나가세요.") |
| `ENEMY_NOT_HACKABLE` | "이미 기절해 있어요! 지금 공격하세요." |
| `BROTHER_DOWN` | "오빠가 쓰러져 있어서 강화할 수 없어요. 재부팅부터 할까요?" |
| `HP_FULL` | "두 분 다 체력이 가득해요! 아껴 둘게요." |
| `NO_DOWNED_PLAYER` | "두 분 다 멀쩡해요!" |
| `TARGET_DOWN` | "지금은 쓰러져 있어요. 재부팅부터 할까요?" |
| `BUSY` | "지금 다른 일 하는 중이에요, 잠깐만요!" |

8. ok인데 LLM 대사가 비면 기능별 기본 대사(DamageBoost 강화 중이면 "30초 더 늘려 드릴게요!").
9. ok이고 `battery_after <= 20`이면 배터리 부족 꼬리말(4절).

## 7. 오류 처리
- Gemini 예외·타임아웃·함수 호출 형식 오류 → `status=fallback`, `reason=LLM_ERROR`, 대체 대사, **배터리 차감 없음**, HTTP 200
- 요청 스키마 오류만 422
- `API_TOKEN` 설정 시 헤더 불일치는 401

## 8. 모의 모드
키워드 규칙(위에서부터 먼저 맞는 것). 검증기·로그·응답 형식은 실제 모드와 동일 경로.

| 순서 | 함수 | 키워드 |
|---|---|---|
| 1 | DamageBoost | 공격력, 데미지, 화력, 강화, 세게 |
| 2 | Shield | 보호막, 지켜, 보호, 실드 (문장에 "동생"→who=sister, "오빠"→who=brother) |
| 3 | QuickReboot | 살려, 부활, 일으켜, 재부팅 |
| 4 | Decoy | 어그로, 유인, 시선, 관심, 데려가, 미끼 |
| 5 | HealSupport | 힐, 체력, 회복, 치료, 아파 |
| 6 | ReloadSupport | 재장전, 장전, 탄, 총알, reload, ammo |
| 7 | PulseAttack | 처치, 죽여, 없애, 펄스, 공격해 |
| 8 | HackEnemy | (적/거미/로봇) + (해킹/무력화/멈춰/막아/어떻게), 또는 무력화/멈춰/막아 단독 |
| 9 | 해킹·퍼즐 | 해킹, 퍼즐, 단말기, 뚫어, 비밀번호 → 퍼즐이 enemy면 HackEnemy, terminal이면 HackTerminal, 퍼즐 없으면 해킹 가능한 적이 있고 단말기/퍼즐 단어가 없을 때 HackEnemy, 아니면 HackTerminal |
| 10 | Chat | 그 외 |

음성은 폼 필드 `mock_text`가 있으면 그 문장을 들은 것으로 처리하고 없으면 Chat.

규칙(위 표보다 먼저, 단순한 문장만 — 복합·부정 조건은 LLM의 몫):
- "규칙" + 취소/지워/삭제/없애/그만/해제 → `ManageRules(cancel)`("1번/첫" → 1, "2번/두 번째" → 2, 그 외 0). "규칙" + 목록/뭐/알려/보여/확인 → `ManageRules(list)`.
- 조건 표지(`~면 `, 동안, 때마다, 할 때, 하는 중, 되면)가 있으면 마지막 표지 앞 = 조건, 뒤 = 행동(위 표로 판별). "~면 좋겠어/돼/고마워"는 조건 아님.
  조건 키워드: 해킹+동안/중 → sister_hacking, 적+가까/다가/오면/근처/Nm → enemy_within, 체력 N+아래/이하/밑 → hp_below, 탄/총알 N → ammo_below, 쓰러지/죽으면/다운 → player_downed(동생/오빠/내가), 배터리 N 넘/이상 → battery_above. "배터리 N 남겨" → reserve_battery, 매번/때마다/계속 → repeat.
- 조건 표지는 있는데 아는 조건이 없으면: "규칙/조건" 단어가 있을 때만 `unsupported`로 등록 시도(→ `UNSUPPORTED_CONDITION` 거절), 없으면 기존 즉시 판별.

조언(규칙보다 먼저, 4-3절): 제안 대기 중 짧은 대답 → `ManageRules(accept/decline)`, 조언 단어 → 상태로 고른 고정 조언 `Advise`.

## 9. 로깅

## 11. 언리얼 연동 계약 (UE 측 구현 참고)
- UE가 `/command`를 **비동기**로 호출(게임 멈춤 금지), 서버 주소는 ini 설정
- **요청 처리 중이거나 드론 행동 중(`Action != Idle`)이면 새 입력을 막는다**(HUD `JEMINI BUSY`, 서버 요청 없음). 서버는 상태를 저장하지 않으므로 연속 요청 차단은 UE 책임. `drone_busy`는 보험.
  - 예외(2026-11-11): 드론 행동 중이라도 **작전 제안 대기 또는 등록된 규칙이 있으면** 플레이어 발화는 보낸다("응/아니"·"규칙 취소"). 요청 중(`bRequestPending`)이면 여전히 막는다. 실행 함수는 서버가 `drone_busy`로 `BUSY` 거절하고, UE `HandleResponse`도 행동 중 `ok`는 실행하지 않는다. 규칙 자동 발동은 그대로 `CanAcceptRequest`(바쁘면 BUSY).
- 쓰러진 플레이어도 입력 가능(게임 오버 중만 차단). `speaker`에 말한 사람을 넣는다.
- 퍼즐 중이 아니면 `sister_puzzle`은 null
- 응답의 `command.name`을 C++ 함수와 매핑, 모르는 이름은 무시
- `battery_after`는 **효과가 실제로 실행된 순간** 반영(재장전 시작, 3초 해킹 완료, 그로기 적용, 펄스 명중, 강화 시작, 회복 적용, 미끼 시작, 부활 실행, 보호막 켜짐). 그 사이 대상이 사라지면 차감 없이 `TARGET_LOST`(UE 전용 사유) 대사
- `dialogue`에 `\n`이 있으면 줄마다 다음 말풍선
- 충전은 UE가 세이브 복도에서 처리
- 규칙(기능 A): `status: "rule"` 응답은 `UCXJeminiRuleComponent`(드론에 붙음, 서버 권위·복제)가 보관(최대 2, UE도 검사). 0.2초마다 `GatherState`와 같은 값으로 조건 평가 → 충족 시 `/validate` → ok면 기존 `ExecuteCommand` 경로(배터리는 실행 순간, 지금 배터리로 비용·예비 재계산). 실패(BUSY·LOW_BATTERY·RESERVE_BATTERY·연결 실패 등)면 규칙 유지·2초마다 재시도, 조건이 맞은 채 6초 실패하면 HUD "규칙 보류". 발동 간 쿨다운 2초. `active_rules`를 매 요청 state에 넣는다.
- 조언·작전 제안(기능 C): `status: "advice"`면 대사를 띄우고 `proposal`을 `UCXJeminiRuleComponent`의 대답 대기(`Proposal`, 복제)로 보관(빈 배열이면 이전 제안도 지움). HUD 규칙 목록 아래 "PLAN?  <label>  [응/아니]". 20초(`ProposalTimeout`) 지나면 버린다. `rule_op: "accept"`면 빈 자리만큼 `AddRule`, `decline`이면 버림. `pending_proposal`·`sister_puzzle.kind`·`warden`을 매 요청 state에 넣는다(`warden.last_reason`은 `ACXWardenTerminal`이 마지막 rejected 사유를 서버 전용으로 기억).
- 실시간 자막: 녹음 중 0.6초마다(이전 `/stt/partial` 요청이 끝났을 때만) 지금까지의 WAV를 보내 말한 사람 머리 위에 표시. 버튼을 떼면 전체 WAV로 한 번 더 받고, 최종 `/command/voice` 응답이 오면 `heard` 말풍선으로 바뀐다. 호스트 PC의 로컬 플레이어만(원격 클라이언트는 최종 `heard`만).

## 부록 A. 시스템 지시문
원문은 `Jemini/prompts/system_instruction.txt`(서버가 그대로 읽는다). 구성:
- 세계관·성격(해요체 존댓말 통일)
- `[대사]` 1~2문장 60자 이내, 지금 하는 행동을 말하고 효과 수치는 약속하지 않음, 쓰러진 사람도 말할 수 있음
- `[할 수 있는 일]` 9가지, 함수 호출 없이 "했어요" 금지, 없는 기능(순간이동·배터리 조작·길 안내·정찰)은 Chat 거절
- `[선택 규칙]` 기획 3절: 애매한 적 요청은 HackEnemy, 확실한 공격 명령만 PulseAttack / 해킹 대상은 단어·퍼즐 상태로 / 미끼·보호막·부활·회복·공격력 구분 단어 / 여러 요청은 먼저 말한 것 하나 + 대사로 알림 / 불명확하면 Chat 되묻기 / 안 될 것 같아도 함수 호출 가능(서버가 판단)
- `[배터리]` 실행 후 20% 이하면 대사에 배터리 부족 언급, 예약 배터리 없음
- `[음성]`, `[보안]`, `[출력]` 함수 10개 중 정확히 하나, Shield는 지목했을 때만 `who`
