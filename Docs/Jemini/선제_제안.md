# 제미니 선제 제안 · 한 단어 명령

싸우는 중에는 글을 칠 수 없으니, 제미니가 **먼저 묻고**(고정 대사, LLM 호출 없음) 플레이어는 **한 버튼**으로 답한다. 채팅 한 단어 명령도 서버 왕복 없이 바로 실행한다.
구현: `Source/Project_CX/Jemini/CXJeminiProactiveComponent.*` (드론에 붙는 서버 권위 컴포넌트). Jemini 서버(FastAPI)는 바뀌지 않았다 — Render 재배포 불필요.

## 1. 선제 제안 4종

| 종류 | 조건 | 대사(말풍선, 상태 `coach`) | 수락 시 실행 | 비용 |
|---|---|---|---|---|
| `ammo` Reload | 오빠 탄 <= 탄창의 1/3 **그리고** 오빠 주변 15m 안에 살아 있는 적 | 탄이 얼마 안 남았어요. 장전해 드릴까요? [응/아니] | `ReloadSupport`(오빠) | 5 |
| `hp` Heal | 오빠 체력 < 최대의 40% | 체력이 많이 닳았어요. 회복해 드릴까요? [응/아니] | `HealSupport` | 30 |
| `stuck` HackAssist | 여동생이 같은 단말기를 20초 넘게 해킹 중 | 퍼즐이 오래 걸리네요. 제가 도와드릴까요? [응/아니] | `HackTerminal`(대행) | 20 |
| `decoy` Decoy | 해킹 중인 여동생 5m 안에 움직이는(그로기 아닌) 적 | 여동생이 해킹 중인데 적이 다가와요. 미끼 던질까요? [응/아니] | `Decoy` | 15 |

- 우선순위(동시에 맞을 때): 미끼 > 회복 > 장전 > 퍼즐 도움.
- 수락 = 기존 실행 경로(`ExecuteLocalCommand` → `HandleResponse` → `ExecuteCommand`): 배터리는 효과가 실제로 실행된 순간 차감, 대상이 사라지면 차감 없이 TARGET_LOST, 대상 없음·배터리 부족이면 거절 대사. 드론이 바쁘면 제안이 사라진다.
- 거절·시간 초과(15초) = 조용히 버림. 거절하면 "알겠어요. 필요하면 말해 줘요!".

### 말하지 않는 때 (`CXJeminiOfferState`의 `blocked`)
이미 제안이 대기 중, LLM 작전 제안(`PLAN?`) 대기 중, 드론이 바쁨/요청 중/게임 오버·이동 중, 제미니가 6.5초 안에 다른 대사를 함, 전체 쿨다운 8초, 일시정지, 튜토리얼 카드, 채팅·녹음 중, WARDEN 단말기 근처(코치 담당), 배터리가 그 기능 비용 미만, 종류별 쿨다운 30초(보여 준 시각 기준).

### 튜닝(`DefaultGame.ini [/Script/Project_CX.CXJeminiProactiveComponent]`)
`OfferTimeout=15` `TypeCooldown=30` `GlobalCooldown=8` `DroneSpeechHold=6.5` `AmmoFraction=0.3334` `AmmoEnemyRange=1500` `HealHpFraction=0.4` `StuckSeconds=20` `DecoyEnemyRange=500` `CheckInterval=0.25`.

## 2. 응/아니 입력

| 방법 | 응 | 아니 |
|---|---|---|
| 키보드 | `R` | `T` |
| 게임패드 | `LB` | `RB` |
| 채팅(Enter) | 응, 네, 예, 좋아(요), 그래(요), 해줘(요), 부탁해, 콜, ㅇㅇ, ok, yes … | 아니(요), 아뇨, 싫어, 괜찮아(요), 됐어(요), 노, no, ㄴㄴ … |
| 음성(패드 Y / 솔로 V) | 받아 적은 글(Heard)이 위 짧은 대답이면 서버 응답 대신 로컬 처리 | 〃 |

- 키·패드 버튼은 `UCXJeminiInputComponent`의 `IMC_Jemini`에 있다(R/T, 패드 LB/RB). 제안이 없을 때는 아무 일도 없다. 채팅창이 열려 있거나 녹음 중이면 무시. 게임 안에서 LB/RB·G/H를 쓰는 곳은 없다(메뉴 입력 처리기의 Q/E·LB/RB는 메뉴가 열렸을 때만).
- 어느 쪽 플레이어가 눌러도 된다(수락한 사람이 말한 사람 = 제미니가 그쪽으로 이동).
- HUD: 채팅창 바로 아래 가운데에 큰 박스(질문 한 줄 + `[R] YES  [T] NO  14s`, 패드는 `[LB]`/`[RB]`). 솔로 모드의 AI 슬롯 칸에는 안 그린다.
- LLM 작전 제안(`UCXJeminiRuleComponent.Proposal`, `pending_proposal`로 서버에 보냄)과는 별개다. 선제 제안은 서버에 알리지 않으므로 LLM이 "응"을 다른 뜻으로 해석할 일이 없다(채팅은 서버로 가기 전에 여기서 가로챈다).

## 3. 한 단어 명령 (채팅만, LLM·서버 없음)

공백·문장부호를 걷어낸 전체 문장이 **8글자 이하**이고 아래 단어(+ 끝말 `해/해줘/해줘요/해요/해주세요/좀/요`)와 같을 때만. 그 밖의 말은 기존대로 서버로 간다.

| 단어 | 실행 | 비고 |
|---|---|---|
| 엄호, 미끼 | `Decoy` | |
| 힐, 회복, 치료 | `HealSupport` | 살아 있는 사람 모두 회복(체력이 닳은 사람이 없으면 거절 대사) |
| 장전 | `ReloadSupport` | 탄이 가득/이미 장전 중이면 거절 대사 |
| 보호막, 방어, 실드 | `Shield` | 말한 사람에게 |
| 해킹 | `HackTerminal` / `HackEnemy` | 여동생 퍼즐 종류 -> 다음 잠긴 단말기 -> 해킹 가능한 적 순 |
| 펄스, 전기 | `PulseAttack` | |
| 재부팅 | `QuickReboot` | 쓰러진 사람이 있을 때 |
| 강화, 공격력 | `DamageBoost` | 오빠 |

- 배터리·대상 검증·BUSY 규칙은 제안 수락과 같다. 실패하면 이유를 말풍선으로(예: "탄이 이미 가득해요!").
- WARDEN 단말기 근처의 여동생 채팅은 WARDEN으로 가므로 해당 없음. 음성은 받아 적는 곳이 서버라 한 단어 명령은 채팅만(음성의 짧은 응/아니 대답만 로컬 처리).

## 4. 테스트

- `CXJeminiOfferState`: 지금 입력(탄약·체력·퍼즐 시간·적 거리·배터리), 종류별 조건 충족(`meets`)·쿨다운, 막힌 이유(`blocked`)를 출력.
- `CXJeminiOffer ammo|hp|stuck|decoy`: 조건·쿨다운 무시하고 즉시 제안(이미 대기 중이면 거절). 수락하면 실제 조건 검증은 실행 때 한다(예: 탄이 가득하면 "탄이 이미 가득해요!").
- 채팅 확인: `CXJemini 응` / `CXJemini 장전` 도 같은 경로.
