# 웹 게임 버전 계획서 (학교 제출용)

과제 "AI 시스템 활용" 제출·발표용으로, 학교 PC 브라우저에서 **HTML 파일을 열기만 하면 돌아가는 가벼운 웹 게임**을 만든다. 웹에 공개하지 않고, 제출물(폴더)로 전달한다. 목적은 그래픽이 아니라 **제미니·WARDEN과 대화하는 기능 전부가 실제로 동작하는 것**이다. 언리얼 본편(CAELUM:UNCHAINED)과는 별개의 데모이며, 본편 코드는 건드리지 않는다.

일정: 제출 12/2(수), 발표 12/8(화). 결정 사항은 9절에 있다.

## 1. 결론: 스택과 구조

| 항목 | 선택 | 이유 |
|---|---|---|
| 게임 | **바닐라 JavaScript + HTML5 Canvas 2D** | 설치·빌드 없음. 실시간 액션 루프가 필요해서 |
| 실행 | **`index.html`을 로컬에서 더블클릭**(웹 공개 없음) | 폴더째 제출하고 학교 PC 브라우저로 연다 |
| AI 서버 | **이미 배포된 Render 서버**(기존 FastAPI 그대로) | Gemini 키는 서버에만 있다. 학교 PC에 Python·키를 설치할 필요가 없다 |
| 오프라인 대비 | 로컬 서버 `python run_server.py`(모의 모드) | 인터넷이 막혀도 키워드 방식으로 동작 |
| 그래픽 | 사각형·원·글자만. 이미지·사운드 없음 | 공들이지 않는다 |

- **HTML을 로컬로 여는 것과 AI는 별개다.** 게임 화면·전투·해킹은 브라우저 안에서만 돈다. 제미니·WARDEN의 말뜻 해석과 판정만 서버에 요청한다. 서버가 필요한 이유는 Gemini 키를 JS에 넣을 수 없기 때문이다.
- **`<script type="module">`을 쓰지 않는다.** 브라우저가 `file://`로 연 페이지에서는 모듈 불러오기를 막는다. 일반 `<script src>` 여러 개(순서대로)로 불러온다.
- **Streamlit을 쓰지 않는 이유:** 입력할 때마다 스크립트를 처음부터 다시 실행하는 구조라, 이동·사격·적 AI가 매 프레임 도는 액션 게임을 만들 수 없다. 기존 `demo/streamlit_app.py`는 개발용으로만 남긴다.
- **Phaser 등 엔진·CDN을 쓰지 않는 이유:** 이 규모에는 과하고, 학교망에서 외부 주소가 막히면 안 열릴 수 있다. 모든 코드를 폴더 안에 둔다.

```
[학교 PC 브라우저: index.html + js/*.js] ──POST /command, /persuade, /validate──▶ [Render: FastAPI] ──▶ Gemini
                                                                                  └ 한도 초과·키 없음: 키워드 모의 모드
```

## 2. 서버 변경(최소)

서버 판정 로직(`persuasion.decide`, `validator`, `rules`, `advice`)은 **수정하지 않는다.**

1. **CORS 허용 추가**(`app/main.py` 몇 줄). `file://`로 연 페이지는 출처가 `null`이라 서버가 허용해 주지 않으면 요청이 브라우저에서 막힌다. 이것 때문에 **서버를 한 번 다시 배포**해야 한다.
2. **웹 전용 토큰**: 본편 `API_TOKEN`과 별개로 `WEB_TOKEN`을 추가로 허용한다(9절 ② 설명). 토큰은 제출 폴더의 `config.js`에 둔다.
3. (선택) 서버 하루 총량 상한: 한도를 넘으면 오류 대신 키워드 모의 모드로 답한다.

## 3. 게임 범위

| 항목 | 내용 |
|---|---|
| 맵 | **단일 맵**, 가로 스크롤(월드 약 4000px, 화면 1280×720). 시작 → 거미 구간 → 단말기 → 엘리트 거미 → 기록 칩 → **WARDEN 문(맵 끝)** |
| 전투 | 오빠: 이동·점프·자동 조준 사격(탄약 30). 적: 거미 로봇(걷다가 접근해 공격). 엘리트 1마리(증거 E1 드랍) |
| 해킹 | 여동생(AI): **화살표 맞추기만**. 단말기 1개(성공 시 문 개방 + 증거 E2·E3 두 개), 적 해킹(성공 시 3초 그로기). 해킹 중 퍼즐 진행도(0~1)를 서버 상태로 보낸다 |
| 증거 | E1 엘리트 거미 처치(오빠가 칩을 줍는다) / E2·E3 단말기 해킹 보상(한 번에 2개). 3개 모두 필요 |
| 충전 | 중간에 충전 패드 1개(E키, 쿨다운 30초). 본편의 "세이브 복도 충전"을 대신한다 |
| 승리/패배 | WARDEN 설득 성공 → 문 열림 → 클리어. 두 명 다 쓰러지면 게임 오버(재시작 버튼) |

**솔로 모드 방식(본편 `CXSolo`와 같음):** 플레이어는 **오빠만 조작**한다. 여동생은 AI로 뒤를 따라다니며 근처 단말기·적을 자동으로 해킹한다(본편 `UCXSoloFollowerComponent` 동작).

- 여동생이 해킹하는 동안 화면 한쪽에 **화살표 퍼즐이 자동으로 한 칸씩 채워지는** 모습을 보여 준다. 사람이 풀지는 않지만 "여동생 해킹 중 / 진행도" 상태는 실제로 생긴다.
- 단말기 해킹은 **느리게**(약 25초) 둔다. 이래야 "여동생이 해킹하는 동안 적이 오면 미끼" 규칙, "퍼즐 정체(20초)" 선제 제안, 제미니 `HackTerminal`(가속)이 모두 의미를 가진다. 적 해킹은 3초.
- 오빠는 조작 중 이동·점프·사격만 한다. 여동생이 쓰러지면 해킹이 멈춘다(`QuickReboot`로 부활).

| 키 | 동작 |
|---|---|
| A/D, W(또는 Space) | 이동, 점프 |
| J 또는 클릭 | 사격(자동 조준) / Q 수동 재장전 |
| E | 줍기·충전 패드·WARDEN 문 상호작용 |
| Enter | 채팅(제미니, WARDEN 근처면 WARDEN) |
| R / T | 제미니 제안 응 / 아니 |

## 4. 제미니 기능 전부 — 구현 체크리스트

서버가 하는 일은 그대로 호출하고, **본편 언리얼이 맡던 부분을 JS로 옮긴다.** 숫자(비용·지속시간)는 본편 값을 그대로 쓴다.

### 4-1. 명령 9종 (`POST /command` → 응답의 `command`를 JS가 실행)

| 명령 | 비용 | 웹 게임에서의 효과 |
|---|---|---|
| ReloadSupport | 5 | 오빠 탄약 가득 |
| HackTerminal | 20 | 가까운 단말기를 제미니가 대신 해킹(3초 후 개방) |
| HackEnemy | 20 | 해킹 가능한 적 3초 그로기 |
| PulseAttack | 50 | 가장 가까운 적 1기 처치(본편 원본과 동일) |
| DamageBoost | 10 | 오빠 공격력 ×2, 30초 |
| HealSupport | 30 | 살아 있는 두 캐릭터 체력 +50 |
| Decoy | 15 | 5초간 미끼 드론, 적이 미끼를 향함 |
| QuickReboot | 30 | 쓰러진 캐릭터 부활 |
| Shield | 25 | 대상 5초 무적 |

- 배터리는 효과가 **실제로 실행된 순간** 차감(본편과 같음). 대상이 사라지면 차감 없이 "대상을 놓쳤어요".
- 거절 사유 11종(`LOW_BATTERY`, `NO_TERMINAL`, `AMMO_FULL` 등)은 서버 응답의 대사를 그대로 말풍선으로 표시.
- 서버 오류·지연 → `fallback` 대사, 배터리 차감 없음. 한도 초과 → 서버가 모의 모드로 전환하고 HUD에 `[MOCK]` 표시.

### 4-2. 서버 기능을 JS가 이어받는 것

| 기능 | 본편 위치 | 웹 JS 모듈 | 내용 |
|---|---|---|---|
| 상태 수집(`GameState`) | `CXJeminiDrone` GatherState | `state.js` | 탄약·체력·쓰러짐·보호막·퍼즐 종류·진행도·적 수·최근접 거리·단말기 수·배터리·활성 규칙·제안 대기 |
| 조건부 규칙(기능 A) | `CXJeminiRuleComponent` | `rules.js` | 서버가 준 규칙 보관(최대 2). 0.2초마다 조건 6종(적 거리·여동생 해킹 중·체력·탄약·쓰러짐·배터리) 평가 → 충족 시 `POST /validate` → ok면 실행. 실패 시 2초 재시도, 6초 지속 시 "규칙 보류", 발동 간 쿨다운 2초, 1회성/반복 |
| 조언·작전 제안(기능 C) | `CXJeminiClient` | `drone.js` | `status: "advice"` 대사 + 제안 규칙 보관, "응/아니"로 등록/폐기 |
| 한 단어 명령 | `CXJeminiProactiveComponent` | `quickwords.js` | 엄호·미끼, 힐·회복, 장전, 보호막, 해킹, 펄스, 재부팅, 강화 등을 서버 없이 즉시 실행 |
| 선제 제안 4종 | `CXJeminiProactiveComponent` | `offers.js` | 탄약·체력·퍼즐 정체(20초)·적 접근(미끼). 박스 + R/T. 우선순위·쿨다운·"말하지 않는 때" 규칙 포함 |
| 평소 코멘트 | 〃 | `chatter.js` | 15초 간격 고정 문구 14개, 이벤트 문구(도착·증거·배터리 30% 이하) |
| WARDEN 설득 | `CXWardenClient` | `warden.js` | `/persuade` 호출, 응답의 `credited`를 보관했다가 다음 요청에 전송, 3초 쿨다운·200자 제한·접수 대기 |
| WARDEN 코치 | `CXWardenCoachComponent` | `coach.js` | 단말기 근처에서 막혔을 때 제미니가 단계별 힌트(예시·요구만·마지막 단계·도착·증거 없음) |

> 음성 입력은 이번 웹 버전에서 **제외**한다(채팅만). 서버의 음성 엔드포인트는 그대로 두지만 웹은 쓰지 않는다.

### 4-3. WARDEN

- 단말기(문) 앞 5.5m 안에서 Enter로 말하면 제미니 대신 WARDEN으로 간다.
- 증거 3개 획득 + 3개 인정 + 논리 연결일 때만 서버가 `solved`를 준다(기존 규칙 그대로, 인젝션·명령만·지어낸 말은 거절).
- 증거 E2·E3는 단말기 해킹 완료 때 함께 지급된다.
- 증거창에 `CONFIRMED n/3`, 증거 목록, "다음 ▶" 한 줄을 표시. 증거 내용은 전문 표시(한 화면이라 "찾은 사람만 보임" 규칙은 뺀다).

## 5. 파일 구조

```
Jemini/web/
  index.html              캔버스 + 채팅창·HUD용 최소 DOM(여기를 더블클릭)
  style.css
  config.js               서버 주소(Render), WEB_TOKEN
  js/
    main.js               루프, 입력, 화면 전환
    world.js              맵, 적, 총알, 충돌(사각형만)
    hack.js               화살표 퍼즐
    api.js                fetch 래퍼(/command, /persuade, /validate), 토큰·타임아웃
    state.js  drone.js  rules.js  quickwords.js  offers.js  chatter.js
    warden.js  coach.js  follower.js(여동생 AI)
    ui.js                 HUD, 말풍선, 증거창, 제안 박스, 채팅창
  tests/                  순수 로직 단위 시험(규칙 조건 평가, 한 단어 명령, 제안 우선순위) — node --test, 개발용
```

## 6. 진행 순서

| 순서 | 내용 | 완료 기준 |
|---|---|---|
| 1 | `index.html` + 맵·이동·사격·적·체력 | 파일을 열면 걷고 쏘고 맞는다 |
| 2 | 여동생 AI(따라다니기·자동 해킹, 화살표 표시), 단말기·증거·충전 패드, 적 그로기 | 단말기 해킹 완료 시 문 개방·E2·E3 획득 |
| 3 | 채팅창 + 제미니 명령 9종 + 배터리 + 거절 사유 + 폴백 | 9종 각각 효과·차감이 맞다 |
| 4 | 한 단어 명령, 규칙(`/validate`), 조언·제안 | "해킹하는 동안 적 5m 안이면 미끼" 자동 발동 |
| 5 | 선제 제안 4종·평소 코멘트·이벤트 문구 | R/T로 응답, 간격 규칙 동작 |
| 6 | WARDEN 설득 + 코치 + 증거창 + 클리어 화면 | 증거 3개로 설득하면 문이 열린다 |
| 7 | 서버 재배포(CORS·웹 토큰), 학교 PC 시험, 제출 문서 | 폴더를 다른 PC에서 열어 처음부터 끝까지 클리어 |

제출이 12/2이므로 **1~6을 11/30까지, 7을 12/1까지**를 목표로 한다. 12/5 전시 준비와 겹치는 점에 유의한다.

## 7. 확인·시험

- **서버:** 기존 `pytest -q` 260여 개가 그대로 통과해야 한다(서버 로직 무변경).
- **JS 순수 로직:** 규칙 조건 평가, 한 단어 명령 분류, 제안 우선순위·쿨다운은 `node --test`로 시험(개발용, 제출물엔 불필요).
- **수동 체크리스트(제출 문서에 첨부):** 기능 항목마다 입력 예 → 기대 결과 표. 제미니 9종 + 거절 사유, 규칙 등록·발동·취소, 제안 응/아니, WARDEN 성공/실패/인젝션, 서버 오프라인 시 모의 모드.
- API 키는 서버(Render)에만 있다. 브라우저·정적 파일·저장소에는 넣지 않는다.

## 9. 결정 사항

| 항목 | 결정 |
|---|---|
| ① 조작 | **솔로 모드**: 오빠만 조작, 여동생은 AI가 따라다니며 자동 해킹 (확정) |

### ② 인증을 쉽게 설명하면

- **지금 방식(언리얼):** 서버에 `API_TOKEN`이라는 비밀번호가 있고, 게임이 요청할 때마다 이 값을 같이 보낸다. 게임 파일 안에 있어 일반 사용자는 볼 일이 없다.
- **웹/HTML은 다르다:** HTML·JS는 파일을 받은 사람이 메모장으로 열어 읽을 수 있다. 그래서 JS에 넣은 비밀번호는 사실상 공개된 값이다.
- **왜 신경 쓰나:** 서버 뒤에 Gemini 무료 키가 있고 하루 호출 한도가 있다. 값이 퍼지면 한도가 바닥나서 시연 때 제미니가 키워드 모의 모드로 떨어질 수 있다.
- **그래서:** 본편용 `API_TOKEN`은 파일에 넣지 않고 **웹 전용 `WEB_TOKEN`**을 새로 만들어 넣는다. 파일이 샌 경우에도 서버에서 웹 토큰만 폐기하면 본편은 안전하다. 이번에는 공개 사이트가 아니라 **제출 폴더를 교수님께 전달**하는 것이라 이 정도로 충분하다고 본다.
- **한계:** 파일에 들어가는 값은 비밀이 될 수 없다. 목표는 본편 보호와 남용 시 대응이다.
