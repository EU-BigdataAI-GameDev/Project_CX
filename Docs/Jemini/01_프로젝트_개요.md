# 프로젝트 개요: 제미니(Jemini) LLM 서버

> 2026-11-28 현재 상태로 갱신. 초기 계획(허깅페이스 Space, 기능 2~3개)에서 크게 늘어난 부분을 반영했다. 세부 명세는 `02_요구사항_명세서.md`.

## 1. 목적

Project_CX(CAELUM:UNCHAINED, UE 5.6 C++, 2인 로컬 협동 사이드 스크롤러)의 드론형 AI 동료 **'제미니'의 두뇌**를 **Python FastAPI 서버**로 구현한다.
플레이어의 자연어(채팅·음성)를 Gemini API로 해석해 **게임이 실행할 명령·규칙·대사(JSON)** 로 돌려주고, 게임이 그것을 실행한다. LLM은 해석·대화·추론, **판정과 실행은 서버·게임 규칙**이 맡는다.

## 2. 제출·일정 (학교 과제)

- 제출: 2026-12-02(수) LMS. PPT(10장 이내, **본문에 이름·학번 금지**) + **Python 소스코드(정상 실행 가능)**
- 발표: 2026-12-08(화), 1인 5분, 기능·구현 설명과 실행 시연 위주
- 서버는 **언리얼 없이 단독 실행·시연**할 수 있어야 한다 → 웹 데모 게임(`Jemini/web/`)과 제출용 묶음(서버 exe + 웹 게임)을 만들었다.

## 3. 구성 요소

| 구성 | 위치 | 역할 |
|---|---|---|
| **제미니 서버(Python)** | `Jemini/app/` | Gemini 호출, 함수 호출 검증, 배터리, 조건부 규칙 정규화, WARDEN 판정, 모의 모드, 로그. **제출 핵심** |
| 본편 게임(Unreal C++) | `Project_CX/Source/Project_CX/Jemini/` | 서버 응답 실행, 규칙 감시, 선제 제안, 평소 코멘트, WARDEN 코치 |
| **웹 데모 게임(JS)** | `Jemini/web/` | 언리얼 없이 제미니·WARDEN을 보여 주는 시연용 게임. 본편의 클라이언트 로직을 JS로 이식 |
| 제출용 묶음 | `Jemini/dist/` (git 제외) | `jemini-server.exe`(파이썬 불필요) + 웹 게임 + 실행 스크립트 |
| 배포 | Render(Docker, 무료) | 본편이 쓰는 외부 서버. 키는 서버 환경변수에만 있다 |

```
[Unreal C++ 또는 웹 데모(JS)]
   채팅/음성 + 게임 상태(JSON)
        │ POST /command, /command/voice, /validate, /persuade(/voice), /stt/partial
        ▼
[FastAPI] ──▶ Gemini (기본 모델 → 예비 모델 → 키워드 모의 모드)
   스키마 검증 · 배터리 차감 · 규칙 정규화 · WARDEN 체크리스트 판정 · 로그(JSONL)
        │ 응답: status / dialogue / command / battery_after / rule / proposal …
        ▼
[게임] 대사 표시, 명령 실행, 규칙 감시·발동, 제안 UI
```

## 4. 제미니가 하는 일 (현재 구현)

| 기능 | 내용 | 처리 위치 |
|---|---|---|
| **명령 9종** | 재장전, 단말기 해킹 대행, 적 해킹, 펄스, 공격력 강화, 회복, 미끼, 재부팅(부활), 보호막. 기능마다 배터리 비용(5·20·20·50·10·30·15·30·25) | 서버가 해석·검증, 게임이 실행 |
| **조건부 규칙(기능 A)** | "여동생이 해킹하는 동안 적이 5m 안에 오면 미끼 써 줘"처럼 말을 **지속되는 규칙**으로 컴파일. 조건 6종·행동 9종 화이트리스트, 최대 2개, 발동 직전 재검증(`/validate`) | 서버가 등록·정규화, 게임이 감시·발동 |
| **WARDEN 설득(기능 B)** | 맵 끝 문을 지키는 관리 AI. 두 사람이 나눠 모은 **증거 3개**를 근거로 말로 설득해야 열림. LLM은 체크리스트만 채우고 **문은 서버 규칙이 연다**(인젝션·명령만·지어낸 근거는 거절, 증거 누적 인정) | 서버 |
| **상황 조언·작전 제안(기능 C)** | "어떡하지?"에 상황별 조언 + 규칙 제안, "응/아니"로 수락·거절 | 서버 + 게임 |
| **선제 제안** | 탄약 부족·체력 저하·퍼즐 정체(20초)·해킹 중 적 접근 때 제미니가 먼저 묻고 **R/T 한 키**로 응답 | 게임(고정 대사, LLM 없음) |
| **평소 코멘트·이벤트 대사** | 조용할 때 15초 간격 고정 문구(상황 5 + 기능 안내 9), 구역 도착·증거 획득·배터리 부족 이벤트 | 게임 |
| **한 단어 명령** | "미끼", "힐", "장전" 등은 서버 왕복 없이 즉시 실행 | 게임 |
| **WARDEN 코치** | 막힌 플레이어에게 제미니가 추측하는 말투로 단계별 힌트(WARDEN 본인은 힌트를 주지 않음) | 게임 |
| **음성** | 패드 푸시투토크 → WAV → Gemini가 직접 듣고 해석. 말하는 도중 실시간 자막은 로컬 faster-whisper | 서버(웹 데모는 제외) |

## 5. 핵심 설계 결정

1. **LLM은 '선택'만 한다.** 함수 호출 결과만 받고, 실행은 게임이 한다. LLM 출력은 신뢰하지 않고 서버가 최종 검증한다(허용 명령·대상·배터리·화이트리스트).
2. **배터리 제한**으로 남용을 막는다(쿨다운 없음). 효과가 **실제로 실행된 순간** 차감한다.
3. **서버는 상태를 저장하지 않는다(stateless).** 게임이 매 요청에 상태를 보내고, 서버는 `battery_after` 등을 돌려준다. 단, WARDEN의 누적 인정(`credited`)은 게임이 보관했다가 다시 보낸다.
4. **LLM이 필요한 곳에만 쓴다.** 고정 명령·평소 코멘트·선제 제안은 LLM 없이 처리한다. 부정·복합 조건, 조건부 규칙, 설득 논리 판정, 인젝션 거절처럼 결정이 필요한 곳에만 호출한다. 근거: 같은 문장 66개 비교에서 키워드 44개(67%) 대 LLM 64개(97%)(`비교실험_결과.md`).
5. **비대칭 정보 보존.** LLM에는 플레이어가 이미 얻은 증거만 준다. 못 찾은 증거는 존재 자체를 숨기고, 응답에 새면 서버가 고정 문장으로 바꾼다.
6. **장애에 강하게.** 기본 모델 → 예비 모델 → 키워드 모의 모드 순으로 내려가고, 오류 시 대체 대사(배터리 차감 없음, HTTP 200)로 게임이 끊기지 않는다.
7. **비밀 관리.** API 키는 서버 `.env`/환경변수에만 있고, 설정 출력 시 가려진다. 테스트는 가짜 키만 쓴다.

## 6. 기술 스택

- Python 3.10+, FastAPI, Uvicorn, Pydantic, `google-genai`(Function Calling·구조화 JSON), python-dotenv
- 실시간 자막: faster-whisper(로컬 CPU, 선택). 테스트: pytest(모의 모드, 네트워크 불필요) **265개**
- 클라이언트: Unreal Engine 5.6(C++), 웹 데모(바닐라 JS + Canvas, 빌드 없음, `file://` 실행)
- 배포: Render(Docker), 제출용은 PyInstaller `jemini-server.exe`

## 8. 범위 제외·한계

- 범위 제외: RAG/벡터 DB, 로컬 LLM, 서비스화. DB는 쓰지 않고 로그는 JSON Lines 파일.
- 웹 데모는 단일 맵·솔로(오빠만 조작)·화살표 해킹만 있고, 음성은 제외했다.
- 비교 실험은 문장 66개·1회 실행으로 작고, 음성·실행 간 변동은 측정하지 않았다. LLM 응답 지연은 중앙값 약 1.8초, 모델 과부하 시 6~10초.
- 무료 Gemini 키는 하루 호출 한도가 있어 초과하면 키워드 모의 모드로 떨어진다.
