# 패키징·배포 체크리스트

게임을 exe로 빌드(패키징)해서 팀원·시연 PC에 나눠 줄 때 따르는 체크리스트다. 빌드 방법의 기본은 `Docs/Guide/빌드_실행.md`의 "패키징" 절, 제미니 서버는 `Docs/Jemini/서버_배포_가이드.md`. **패키징은 에디터에서 잘 돌던 게 exe에서 빠지는 일이 잦으니 7번 "패키징본 실행 확인"을 꼭 한다.**

## 0. 한눈에 보기

| 항목 | 결정 |
|---|---|
| 빌드 종류 | Development(팀 시연용). 마지막 공개 배포판만 Shipping 검토 |
| 빌드 위치 | 저장소 밖: `D:\Builds\CAELUM_UNCHAINED\<버전>\` (예: `v0.1-beta`) |
| 제미니 서버 | 배포 서버(Render) 사용. **배포판에 키·서버 exe를 넣지 않는다** |
| 전달 | zip 압축 → Google Drive/OneDrive 링크(현장은 USB) |
| 필요 장비 | Windows 10/11 64bit, 여동생(2P)용 게임패드, 마이크(음성 명령), 인터넷 |

## 1. 빌드 전 점검

- [ ] `develop`이 최신이고 배포할 PR이 모두 머지되었다(`git pull`, 로컬 변경 없음)
- [ ] 에디터에서 `Map_Title` → 새 게임 흐름이 한 번 끝까지 돈다(컷신 → Map1 → Map2 → 복도 → 베타 종료 안내)
- [ ] `Project_CX/Config/DefaultGame.ini` `[/Script/Project_CX.CXJeminiDrone]`
  - [ ] `ServerUrl="https://jemini-server.onrender.com"` (**로컬 주소 `127.0.0.1`이 아님**, 따옴표 있음)
  - [ ] `ApiToken`이 Render의 `API_TOKEN`과 같다
- [ ] Render 서버가 살아 있다: `https://jemini-server.onrender.com/health` → `{"status":"ok","mock":false,...}`
- [ ] 코드·문서·ini 어디에도 `GEMINI_API_KEY` 값이 없다(`Jemini/.env`는 저장소에 올라가지 않는다)
- [ ] 버전 표기를 올렸다(타이틀 화면 우하단 `v0.1`, 코드의 버전 문자열)

## 2. 쿠킹 설정 확인 (`DefaultGame.ini` `[/Script/UnrealEd.ProjectPackagingSettings]`)

패키징 때는 맵과 거기서 참조하는 에셋만 포함된다. **코드가 경로 문자열로 불러오는 에셋은 따로 지정하지 않으면 exe에서 빠질 수 있다.**

- [ ] `MapsToCook`: `Map_Title`, `Map1_SoulCity1`, `Map2_SoulCity2`, `Map_SaveCorridor` (맵을 추가하면 여기도 추가. 보스맵 `Map3_Final`은 아직 없음)
- [ ] `GameDefaultMap`(`DefaultEngine.ini`)이 `Map_Title`이다
- [ ] `DirectoriesToAlwaysCook`에 경로로 불러오는 폴더가 모두 있다
  - 기존: `Audio`, `SoulCity/Sound`, `Characters/Enemy/SpiderBot`, `UI/Fonts`, `NNEDenoiser`
  - **추가(2026-11-20): `Title`(키아트·로고), `Cutscene`(컷 이미지 5장), `Characters/Brother`(애니메이션·총), `Characters/Drone`(드론 메시·머티리얼), `Environment/Materials`(네온 머티리얼)**
  - 새로 `LoadObject`·경로 문자열로 불러오는 에셋 폴더를 만들면 여기에 넣는다(안 넣으면 exe에서만 안 보이는 문제가 생긴다)
- [ ] `bCookAll=False`, 쿠킹 대상은 Development 빌드

## 3. 빌드 (패키징)

에디터에서(가장 쉬움):
1. 에디터를 연 상태에서 **Platforms → Windows → Package Project**(플랫폼 → Windows → 프로젝트 패키징)
2. 저장 위치를 `D:\Builds\CAELUM_UNCHAINED\v0.1-beta`로 지정
3. 끝날 때까지 기다린다(오래 걸린다. 오른쪽 아래 출력 로그 확인)

명령줄(자동화, 에디터 불필요, 아직 이 프로젝트에서 직접 돌려 보지는 않았다):
```powershell
& "D:\games\Epic Games\UE_5.6\Engine\Build\BatchFiles\RunUAT.bat" BuildCookRun `
  -project="C:\Users\KyungJun\source\repos\Project_CX\Project_CX\Project_CX.uproject" `
  -platform=Win64 -clientconfig=Development -build -cook -stage -pak -archive `
  -archivedirectory="D:\Builds\CAELUM_UNCHAINED\v0.1-beta"
```
- [ ] 로그 끝에 `BUILD SUCCESSFUL`(또는 패키징 완료 알림)이 나왔다
- [ ] 실패하면 로그에서 `Error`를 찾는다. 에디터 출력 로그 끝의 `PackagingResults: Error: Unknown Error`는 이유를 말해 주지 않는다. **진짜 오류는 그 위의 `UATHelper:` 줄이나 `%APPDATA%\Unreal Engine\AutomationTool\Logs\<엔진>\Log.txt`에서 `error`로 검색**한다
- [ ] 패키징은 **게임 타깃**을 컴파일한다(에디터 빌드와 다름). 에디터 전용 코드(`PostEditChange`, `GEditor` 등)는 `#if WITH_EDITOR`로 감싸야 한다. 미리 확인: `Build.bat Project_CX Win64 Development -Project=...`

## 4. 빌드 폴더 점검 (배포 전에 꼭)

- [ ] `D:\Builds\CAELUM_UNCHAINED\v0.1-beta\Windows\` 안에 `Project_CX.exe`와 `Project_CX\` 폴더가 있다
- [ ] **비밀·불필요 파일이 없다**
  - [ ] `.env` 파일이 없다(폴더 전체 검색)
  - [ ] `jemini-server` 폴더·`jemini-server.exe`가 없다(`copy_jemini_to_package.bat`는 쓰지 않는다)
  - [ ] `Saved\Logs`, `Saved\SaveGames`에 내 세이브·로그가 없다(처음부터 깨끗한 폴더)
- [ ] 폴더 크기를 본다(너무 크면 zip이 어려우니 불필요한 에셋이 들어갔는지 확인)
- [ ] 패키징된 `Config`의 `DefaultGame.ini`(또는 쿠킹된 설정)에 `ServerUrl`이 원격 주소다

## 5. 압축과 전달

- [ ] 폴더를 zip으로 압축: `CAELUM_UNCHAINED_v0.1-beta.zip`
- [ ] zip에 `README_실행방법.txt`를 넣는다(아래 7번 템플릿)
- [ ] 클라우드(Google Drive/OneDrive) 링크로 공유. **링크 공개 범위는 팀원만**
- [ ] 다른 PC에서 받은 zip을 풀어 실행해 본다(내 PC에서만 되는 의존성이 없는지)

## 6. 팀원 PC 요구사항과 주의

- Windows 10/11 64bit. 첫 실행 때 셰이더를 컴파일해 잠깐 "응답 없음"이 뜰 수 있다(버그 아님)
- 여동생(2P)은 게임패드. 오빠가 패드를 쓰는 구성으로 바꾸면 여동생을 키보드로 쓸 수 있다(ESC 메뉴 → 입력 장치)
- 마이크: 패드 Y 또는 키보드로 음성 명령. 마이크 권한을 허용해야 한다
- 인터넷 필수: 제미니·WARDEN은 배포 서버(`jemini-server.onrender.com`)를 쓴다. 오프라인이면 제미니는 "신호가 끊겼어요"라고만 말한다
- 서버가 잠들어 있으면 첫 응답이 30~60초 걸린다(게임이 켜질 때 서버를 깨운다). 시연 전에 `/health`를 한 번 열어 둔다

## 7. 패키징본 실행 확인 (내 PC, 에디터를 닫고)

빌드 폴더의 `Project_CX.exe`를 직접 실행해서 확인한다(에디터 PIE와 다르다).

- [ ] 타이틀 화면에 **키아트 배경과 로고 이미지**가 보인다(안 보이고 옛 글자 화면이면 2번의 `Title` 쿠킹 누락)
- [ ] NEW GAME → **오프닝 컷신 5컷과 자막**이 나온다(컷신 없이 바로 시작하면 `Cutscene` 쿠킹 누락. **새 게임은 패키징본의 세이브만 지운다**)
- [ ] 이동·점프·사격, 오빠 총이 손에 있고 팔이 올라간다, 연속 점프 정상
- [ ] 첫 거미·해킹 단말기·제미니·WARDEN 튜토리얼이 뜬다
- [ ] 제미니: Enter로 말 걸기에 응답이 온다(서버 연결), 음성(Y)도 동작
- [ ] 맵2 끝 WARDEN 설득이 동작한다
- [ ] 맵 이동(Map1 → Map2 → 복도 → 출구), 출구에서 "BETA TEST // END OF BUILD" 안내
- [ ] 소리(배경음·효과음·발소리), 한글 글자, ESC 메뉴·설정·조작법
- [ ] 로그 확인: `Project_CX\Saved\Logs`에서 `Error`, `LogCXJeminiServer`(워밍업 `ok`), `LogCXCutscene`(`skipped` 경고 없음)
- [ ] 시연용 콘솔 명령이 먹는다(`~` 키로 `CXGotoNextMap`, `CXGiveEvidence all` 등). 목록: `Docs/Guide/콘솔_명령_목록.md`

## 8. README_실행방법.txt 템플릿(zip에 같이 넣기)

```
CAELUM:UNCHAINED  v0.1-beta (플레이 테스트)

1. 압축을 풀고 Project_CX.exe를 실행합니다. (첫 실행은 셰이더 컴파일로 몇 초 멈출 수 있습니다)
2. 인터넷이 필요합니다. 제미니(AI 드론)가 온라인 서버를 사용합니다.
   서버가 잠들어 있으면 첫 응답이 30~60초 걸립니다.
3. 2인 협동: 1P 오빠 = 키보드·마우스, 2P 여동생 = 게임패드.
4. 제미니에게 말하기: Enter(채팅) / 게임패드 Y(음성). 마이크 사용을 허용해 주세요.
5. 건너뛰기: Esc / Space / 패드 A (컷신).
6. 문제가 있으면 Project_CX\Saved\Logs 폴더의 로그와 함께 알려 주세요.
```

## 9. 알려진 한계 (배포판 안내에 적을 것)

- 마지막은 보스맵이 아니라 "베타 테스트 종료 안내"다(보스맵은 후속)
- 실시간 자막(패드 Y로 말할 때 머리 위에 뜨는 글자)은 배포 서버에서 나오지 않는다. 음성 명령은 동작
- 무료 Gemini 키의 호출 한도를 여러 명이 함께 쓰면 응답이 느려지거나 `[MOCK]`(키워드 판정)으로 떨어질 수 있다
- 서버가 15분 이상 쓰이지 않으면 잠든다
